# Qwen3.5 分词器告警与验证范围

Qwen3.5 的实验日志出现了“分词正则不正确，建议设置 `fix_mistral_regex=True`”的 Transformers 告警。固定版本源码表明，这是对模型类型的误判；**发出告警的分支没有修改正则，告警本身不能证明 Qwen token ID 有误。** 历史基线已出现同一告警，本轮没有修改分词器。

## 为什么 Qwen 会进入 Mistral 检查

当前 Transformers 4.57.6 会对词表超过 100,000 的快速分词器执行这项检查。本地配置排除非 Mistral 模型的条件依赖 `transformers_version` 字段；缺少字段时，即使 `model_type` 不是 Mistral，也会继续发出告警。

Qwen 官方配置带有 `transformers_version=4.57.0.dev0`。实验文本视图从官方配置提取 `text_config`，因此没有带入外层版本字段，触发了这个条件。分词器配置仍声明 `Qwen2Tokenizer`，视图中的词表、merges、分词器 JSON 和模板仍链接到官方文件。

本地 Transformers 5.23.0.dev0 参考源码也有依赖版本字段的检测分支，但具体版本阈值与 4.57.6 不同。结论仅针对这两份固定源码。此前 [Dory 的分词验证](dory-tokenizer-template-20261108.md)记录过类似告警；Dory 的正则和编码结果不能直接用于证明 Qwen 正确。

## 已有什么证据，还缺什么

现有真实注册检查已把文本视图的六条序列与原始 HF 保存的完整 token ID 逐项比较，全部相同；长度分别为 23、30、28、26、28、1,614。长解码检查使用保存的原始输入 ID，本身不构成新的分词器比较。

quality96 的两侧配对检查使用相同输入，但当前质量工具没有为 Qwen 单独执行全部 96 条输入的官方分词器对照。已有上下文预检核对了长度，不能替代完整 ID 比较。后续原生预检已补充这项检查的源码：比较全部 96 条质量输入、HTTP 输入、六条 HF 序列和两条长序列的完整 ID；真实原生执行仍待串行安排。

预检 v3 的 31 项源码／模拟检查通过。独立复核还发现并修复了本项目预检工具的临时符号链接写入检查缺口；实际 Python 检查钩子对临时合成文件拒绝了 241 次写入，正常读取和新配置创建通过。测试未运行原分词器或写入官方文件，不构成真实分词一致性证明。[新增预检源码及复核证据](evidence/qwen35-tokenizer-preflight-v3-20261112/manifest.json)保留了发现、修复和执行范围。

此次复核没有启用 Mistral 修复开关，没有改写当前实验或官方文件，也没有重新运行分词器。它澄清了告警来源和现有证据的范围，没有新增性能结论。
