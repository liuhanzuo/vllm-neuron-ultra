# MiniCPM5：第 0 层完整 BF16 投影的整模型候选被拒绝

2026-11-08，两个完整 BF16 输出投影候选均完成原 14 次调用、32 帧对照。**两个候选均从严格 CPU 基线的 29/32 通过降到 28/32，首选 token 一致数从 32/32 降到 31/32，因此拒绝采用。** 没有新增可发布的 Neuron 优化配置或提速倍数。

此前[固定输入投影](minicpm5-fixed-oproj-20261108.md)和[真实双 rank 收集](minicpm5-full-bf16-gather-20261108.md)确实缩小了首层局部误差。本轮显示，该局部改善不能直接推出最终 logits 的改善。

## 改动及保留的控制

模型使用原权重和 BF16 精度。仅替换 `layers.0.self_attn.o_proj.o_proj`：在实际 NxD TP2 进程组中收集两个 rank 的 1,024 维 context，以原顺序组合完整 2,048 维输入，每个 rank 执行一次完整 BF16 线性投影。候选不转换 FP32、不对投影输出再求和。

完整 `[2048,2048]` 矩阵由实际原列分片收集重建，并核对原官方 8 MiB 矩阵哈希。所有 42 层的参数对象、权重字节及原方法均检查和恢复；其余层保持原实现。按顺序运行严格基线、仅预填充替换、预填充和解码都替换。

每个方案完整运行 8 个固定输入、14 次调用、32 帧，使用自己的真实连续缓存状态。严格基线的输入、213 个观测点、全部缓存元数据和 logits 均准确复现。两个候选首组 4 次预填充准确相同，首次解码传入缓存准确相同；原槽位保留、填充区及阶段切换检查均保留。两个 rank 的重复输出只计一次。

## 完整结果

| 方案 | 全部通过 | 预填充通过 | 解码通过 | 首选 token 一致 | 未通过帧 |
|---|---:|---:|---:|---:|---|
| 严格 CPU 原基线 | 29/32 | 7/8 | 22/24 | 32/32 | 1、9、13 |
| 第 0 层完整 BF16，仅预填充 | 28/32 | 5/8 | 23/24 | 31/32 | 1、13、16、17 |
| 第 0 层完整 BF16，预填充及解码 | 28/32 | 5/8 | 23/24 | 31/32 | 1、13、16、17 |

两个候选都修复了原失败帧 9，但新增帧 16、17 失败。帧 1 的 KL 从 **0.101269543 → 0.329327852**，首选 token 从正确的 **1062** 变为 **15182**。原生参考的首选优势为 **1.125**，超过必须匹配的 0.5 门槛，因此这是明确的高置信度首选 token 回退。

两个候选的通过数相同，并不表示每一帧 logits 完全相同。首次预填充的回退已足够拒绝两者；解码阶段也替换没有挽救这项回退。此前设备的 30/32 不能替代 CPU 的 29/32 基线；此前 FP32 投影和全矩阵 down 候选也继续拒绝。

## 独立复核及新发现的指标布局差异

完整模型运行会话 `17987` 实际退出 0，两个 rank 均退出 0，服务组已清空。保存 84 份完整 logits 文件（两个 rank × 三个方案 × 14 次调用）及 84 份选定观测点文件；其中 logits 文件共 100,404,852 字节，选定观测点原始数据共 3,145,728 字节，整轮物理输出约 126.8 MB，位于 NVMe。

独立标准库分析读取受限的 ZIP/张量元数据和所有保存字节，没有导入 Torch/NumPy。它对 96 个计分帧重新计算双精度余弦、KL、最大/平均误差、首选 token 和优势。**96/96 的通过/失败判定、首选 token 索引都与原报告一致。** 原始数据哈希、跨 rank 输出和观测点核对通过。

但独立双精度与原 FP32 指标的严格数值一致性检查没有全部通过：75 个余弦值超出预先规定的 `3e-6` 绝对容差，最大差约 `9.4581e-5`。KL 最大差约 `9.4401e-6`，在原 `2e-5` 容差内。我们保留这项失败，没有扩大容差，也没有改模型验收阈值。独立分析的完整执行不等于这项标量一致性门槛通过。

随后使用同一份保存 logits，恢复完整生产张量的形状、步幅与字节，再执行固定原 SDK 中的原 FP32 指标函数。**全部 96 帧、所有原指标精确重现。** 其中 72 个解码帧的原行步幅是 4；仅将同一行改为连续布局，就会改变部分 FP32 指标，余弦最大变化约 `9.1076e-5`。改为连续布局后与双精度的最大余弦差仍约 `1.3142e-5`，所以不能把全部误差都归给布局。

这说明：读取保存后的连续张量再计算，不一定精确复现原非连续视图上的 FP32 归约。原报告本身可精确复现；独立双精度也支持候选回退的判定。指标重放会话 `71249` 退出 0，约 40.86 秒，包含依赖校验与读写，**不是模型推理性能**。该重放未重跑模型、投影或矩阵乘法。

## 保留的工具失败

计划构建曾因局部变量覆盖旧退出记录而失败；一次启动命令误带占位哈希，在进入实验前被拒绝。二者修正后才启动本轮模型运行。

复核准备阶段曾误用只接收元数据的哈希函数，以及把原 `[4,130560]` HF 张量当作四个 Python 列表项。实际复核又发现，大小为 1 的维度可以有非规范步幅而仍是连续张量；修正检查后，继续遇到上述真实 FP32/双精度余弦差异。失败源码、实际退出和修正后的分析均保留，没有覆盖失败记录。这些是工具适配或指标复现问题，不是芯片缺陷证据。

## 后续方向

两个完整 BF16 第 0 层候选不进入 Neuron 编译或性能测试。MiniCPM5 保留原基线和全部数值、84 项冷缓存、2,049 次长路径操作/93 个检查点、槽位复用与恢复、96 题质量及配对服务验收。后续先分析已有观测点和 logits 的误差传播；不重复已完成的局部收集或本轮被拒绝候选。
