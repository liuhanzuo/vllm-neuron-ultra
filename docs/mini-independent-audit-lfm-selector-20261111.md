## LFM3：精确写回推进到槽位选择，整套测试仍失败

命名空间修正后的 r4 已实际结束，外层工具和工作进程均退出 1，进程消失，服务及进程组已排空。三个对照组都实际执行，结果如下。

| 对照组 | 实际结果 | 可支持的结论 |
|---|---|---|
| 原实现 | 首例恒等操作返回 4,096 字节精确一致，但调用后输入的 27 个 BF16 字发生 NaN 位模式变化 | 返回值相等不能替代输入未改变检查；原失败继续保留 |
| 精确 BF16 写回候选 | 恒等、复制、置换三项通过，输入未改变；随后槽位选择出现 `AttributeError: 'bool' object has no attribute 'shape'` | 候选仅完成前三项，尚未完成全部 32 例及 65,536 种 BF16 编码 |
| 恢复原实现 | 再次出现与第一组相同的首例输入变化 | 移除写回修正后，原失败行为可复现 |

候选记录 12 次提取，其中 6 次对 BF16 输入写回使用精确提取；各组结束后原函数均恢复。此次不是完整诊断通过，也不是设备算子验证。报告外层的 `complete: true` 表示三组调用已经收集，不能替代候选套件的 `complete: false` 或运行器的失败退出。

固定源码检查表明，新诊断内核使用 `mapping == destination`，但新版 NKI 张量类没有 Python 相等运算重载；模拟器直接执行此 Python 函数，比较结果因而是普通真假值，随后 `nl.where` 读取 `condition.shape` 失败。`selected - 1` 同样依赖该张量类没有提供的减法重载。后继改用显式 `nl.equal`、`nl.subtract`，保持 payload 类型、槽位语义和全部测试范围。主任务独立复跑 12 项纯测试通过，包含 140 组槽位控制；原 567 项来源保留，增加三个后继源码，共 570 项。r5 已启动，实际结果仍待完成。该兼容错误属于本地诊断迁移代码；它不证明上游模型计算有缺陷。

## MiniCPM5：保存算子报告的独立全量复核

独立复核已实际通过：工具退出 0，原进程已消失。新进程重新读取全部 **1,284 份 capture、77,790,564 字节**，六份完整比较报告及汇总均精确重现，包含各字段的 JSON 类型。执行前，主任务在原 Python 3.12 环境独立复跑了 13 项针对性检查。此前原生 936 文件审计与此次比较报告审计是不同阶段。

本次审计保留完整 99 条先前串行记录与 47,839 项来源；真正退出后成为第 100 条记录。原 SDK 模型退出 1 的事实保持；已恢复的保存数据可以用于诊断，并不使原失败运行变成成功。

保存的 24 个检查点各对应两个 SDK rank，共 48 组比较。下表是已独立复核报告的汇总，没有重新执行算子或模型。

| 保存边界 | 逐字节相等的组数 | 含义 |
|---|---:|---|
| 历史 K、V | 各 48/48 | 本轮输入的有效历史内容一致 |
| BF16 注意力概率 | 48/48 | FP32 softmax 的微小位差在转成 BF16 后消失 |
| 更新后的有效 V | 47/48 | 一组有两个 BF16 元素不同，完整保留 |
| P×V 合并后的 context | 0/48 | 47 组概率与有效 V 都相同的输入，仍产生不同 context |

FP32 概率的最大绝对误差为 `1.1920928955078125e-7`，但 BF16 概率全部精确一致。context 的最大相对 L2 误差约为 `0.003224`。这些是局部张量比较，不能解释为模型质量变化或推理提速。

下一项实验将先在各自原环境复现保存的原输出，再固定完整 P/V 输入，比较历史与当前 token 分开计算、合并计算，以及中间舍入和累加精度。同时保留原 batch、head、有效长度、padding 与布局对照，避免把形状变化误判为公式效果。

首个出现位差的保存边界只能用于选择下一项实验，不能证明因果算子。局部数值诊断也不能替代完整模型的质量与性能门槛。
