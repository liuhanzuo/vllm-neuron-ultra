# MiniCPM5 审计环境修正与 LFM3 写回对照

MiniCPM5 原生 r3 的完整独立审计已经通过，审计进程实际退出 0。LFM3 的新对照复现了首例输入变化，并确认变化集中于 27 个 NaN 的位模式，但候选组启动检查失败，三组对照尚未完成。没有新增整模型合格结果或推理提速倍数，已有配对性能结果保持原口径。

## MiniCPM5：先修正审计环境，再核对数据

原生 r3 的 24 个检查点、72 次直接注意力调用已运行结束，外层与独立结束记录器均实际退出 0。它使用保存的官方输入及历史缓存进行第二层注意力的局部重放，没有重新执行完整模型或 prefill。

首次独立审计实际退出 1，错误位于 Python 跟踪记录的精确比较。模型运行使用 Python 3.12.16，而该审计从系统 Python 3.10.12 启动。同一份已固定摘要的源码，在两个解释器下编译得到不同的 `co_linetable` 和 `co_lnotab`；源码、函数名、起始行及观测位置均相同。

主任务随后只读取 48 份跟踪元数据并编译原源码进行定位：系统解释器下 0/48 份契约完全匹配，模型原解释器下 48/48 完全匹配。该定位没有导入 Torch、读取张量或执行模型，也不替代完整审计。首次失败及其实际退出码保留，审计源码与精确相等检查均未修改。

新的独立审计使用模型原来的解释器，重新核对完整来源、模型及记录器的真实退出和进程清理，并重新读取全部 **936 份原始文件／28,490,724 字节**，核验 **72 份结果、72 份日志中的 2,736 条记录**。24 个检查点的三组注意力输出及完整 K/V 缓存均与保存的官方参考逐字节一致。完整物理检查覆盖 1,323 个历史服务和 1,888 条进程身份；审计本身随后实际退出 0，原进程已消失。

这个问题属于本地审计启动环境配置，不能归因于 MiniCPM5、Transformers 或 vLLM-Neuron 的计算实现。SDK 与官方参考可能使用不同解释器，后续逐算子比较也必须分别认证两边的原始跟踪记录，不能用一个解释器生成的行号记录替代另一边。

逐算子比较入口已经通过主任务独立复跑的 **11 项测试**。官方参考一侧在原解释器下重建记录；SDK 一侧复用已完成独立审计所认证的原文件及完整跟踪合同，保留全部行号摘要。它要求两 rank 的 12 份合同完全一致，并拒绝缺失或伪造的证据；原审计失败记录继续保留。真实比较随后启动，范围为 1,284 份 capture／77,790,564 字节；结果尚待完成及独立核验，不能据此声称已经定位造成数值差异的算子。

## LFM3：三组对照的范围

此前 NKI 0.5 模拟器的首个恒等操作返回 4,096 字节完全一致，但调用结束后主机输入发生变化，因而失败。下一轮保留原 32 例、全部 65,536 种 BF16 编码以及算术、转换和负对照，顺序执行原实现、精确写回候选、恢复原实现。

候选只在已固定源码的模拟器输入写回位置使用精确 BF16 提取；显式指定精度的其他调用保持各自行为，已安装 SDK 文件不改动。每组都记录输入变化、写回位置和函数恢复情况。即使候选通过，原实现的失败仍保留，整个诊断不会被改写成原实现通过，更不代表设备算子或整模型已经合格。

本次实际运行在原实现组复现失败：返回的 4,096 字节仍全部一致；缓存中的 24 个 BF16 字和更新输入中的 3 个 BF16 字发生变化，共 81 位。全部变化都是 NaN 保持为 NaN、内部位模式被改变；其他字、符号位和有符号零没有变化，槽位索引也未改变。这是对该首例的范围说明，尚未完成全部 BF16 编码覆盖。

候选组在任何检查执行前遇到 `FileNotFoundError`，恢复原实现组未运行，实际工具及 worker 均退出 1，进程和服务已排空。因此当前不能判断精确写回候选是否通过，也没有完成写回原因的三组验证。

源码排查发现一条可触发相同异常的路径：NKI 首次调用延迟加载 PyTorch，后者注册 `torch.ops`、`torch.classes` 两个动态命名空间；旧检查器将其相对伪文件名 `_ops.py`、`_classes.py` 当成实验目录中的真实文件。主任务独立复跑的 **8 项纯测试**复现了旧检查器的错误，并验证后继只接受来源、类型、对象身份和构造代码全部核对的这两个命名空间，普通缺失文件仍会被拒绝。原 561 项来源全部保留，补齐后为 567 项；科学测试和写回探针未改动。

这属于本地检查器的兼容问题。原实际日志只保存了异常类型，没有缺失文件名或内部调用栈，因此上述路径是源码与隔离测试支持的解释；完整实机后继仍待运行，不能把纯测试计作三组对照通过。

完整模型结论仍须通过原权重和 BF16 条件下的数值、冷缓存 4096、长解码、请求槽位复用、质量 96 及相同设置的 HTTP 对照。已有提速倍数见[配对结果与适用范围](multi-model.md#existing-results-and-provenance)。
