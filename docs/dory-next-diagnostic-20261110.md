# Dory 下一步诊断：区分注意力输出差异与残差归一化放大

本材料只准备源码与元数据设计，尚未准备或运行原生实验。已完成的 Dory 残差重放及独立存档复核，仍保留 **87 个检查点中的 7 个 FP32 数值失败**。87 个检查点的 top-1 一致，不能替代 cosine ≥ 0.995、max_abs ≤ 2、KL ≤ 0.02 三项原有门槛。

这些结果来自 **官方 vLLM Dory 的 CPU oneDNN 实现与上游测试中的 ReferenceAttention**，不是 Neuron 执行结果。旧指标字段 `kl_reference_to_neuron` 在本组数据中沿用了历史名称，也不能因此将它解释为 Neuron 对比。

## 已确认的证据

原始执行和残差重放各覆盖 6,200 个事件、6,185 次成功调用、56 路独立缓存历史。模型有 72 个物理层、112 次实际层访问、224 个残差边界；已保存 2 次全因果参考与 87 次检查调用，共 153 个抽样行。

独立存档复核 r3 已实际退出，退出码为 0。最新结果中，7 个失败点的最大残差 RMS 增量有 5 个发生在物理层 56，另 2 个发生在物理层 32 的第二次循环。因此选择三个目标位置：

| 物理层 | 循环下标 | 独立缓存编号 | 注意力窗口 |
| --- | --- | --- | --- |
| 32 | 0 | 32 | 1024 |
| 32 | 1 | 104 | 1024 |
| 56 | 0 | 56 | 1024 |

例如，事件 6160 在层 56 的输入差异 RMS 为 0.00248058，输出为 0.02000048，放大约 8.06 倍。这是定位线索，尚不能证明层 56 是最终 logits 失败的根因。

| 事件 | fixture / slot / position | 首次数值差异 | 最大 RMS 增量所在位置 | 原始失败指标 |
| --- | --- | --- | --- | --- |
| 3607 | 1 / 1 / 1025 | 层 0 | 层 32，循环 1 | cosine |
| 4105 | 1 / 2 / 1023 | 层 0 | 层 56，循环 0 | cosine |
| 4113 | 1 / 2 / 1025 | 层 0 | 层 32，循环 1 | cosine、max_abs |
| 6160 | 0 / 0 / 2047 | 层 0 | 层 56，循环 0 | cosine、max_abs |
| 6164 | 0 / 0 / 2048 | 层 2 | 层 56，循环 0 | cosine、max_abs |
| 6176 | 0 / 0 / 2051 | 层 0 | 层 56，循环 0 | cosine、max_abs、KL |
| 6181 | 1 / 1 / 1668 | 层 0 | 层 56，循环 0 | max_abs |

事件 6181 是 **slot 3 复用后，slot 1 继续解码**；不能把它改写成 slot 1 自身被复用。

## 现有数据的真实缺口

残差存档只有抽样的输入与输出行，没有保存 mixer 输出，也没有保存宽调用的完整中间输入矩阵。83 次单行调用已经有完整的这一行输入，7 个失败点都在其中；但还必须补齐以下六次调用，才能保留完整的原始调用形状：

| 事件 | fixture / slot / epoch | 原始阶段 | 完整行数 | 已保存行数 | 缺少输入行数 |
| --- | --- | --- | ---: | ---: | ---: |
| 1 | 0 / 10 / 1 | full_causal | 2060 | 33 | 2027 |
| 4 | 1 / 11 / 1 | full_causal | 2060 | 33 | 2027 |
| 7 | 0 / 3 / 1 | prefill | 23 | 1 | 22 |
| 9 | 1 / 1 / 1 | prefill | 127 | 1 | 126 |
| 11 | 0 / 0 / 1 | prefill | 511 | 1 | 510 |
| 6179 | 1 / 3 / 2 | slot_reuse_prefill | 31 | 1 | 30 |

六次都从 position 0 开始，总计 4,812 行，其中 4,742 行没有被原残差观察器保存。因此可准备六次原始完整模型前向补采；没有必要再无变化地执行全部 6,185 次模型前向。新诊断仍要按顺序认证全部 6,200 个原始事件及完整缓存存档。

不能用零填充未保存行来称作“复现原始完整输入”，也不能把最终覆盖范围缩减成 83 次单行调用。

## 第一阶段：六次完整输入补采

使用原始权重、词元、位置、BF16 精度、oneDNN 投影和官方源代码，在三个目标位置复制完整的 input、mixer output、residual output。观察 hook 只复制，返回 `None`。保留原始 full-causal 输出头的 33 行和其他调用输出头的 1 行。

每次调用的全部 hidden、logits、56 路 K/V 历史必须与原存档一致；原来 224 个边界的抽样行也要逐项比对。保留 112 次物理层/循环访问及每次完整调用 281 次 oneDNN 投影的检查。新保存的六次完整输出和目标边界必须在实际退出后独立回读复核。

六次调用各自在空缓存上执行，携带原 slot、epoch、request 标签。它们是独立诊断调用，不以此重新认定生产环境的槽位复用或故障恢复已经合格。

## 第二阶段：输入与过去 K/V 的八组对照

对全部 87 个检查调用、每个目标位置，执行 input × past-K × past-V 的 2×2×2 组合。`I` 指原增量调用；`F` 指真正的全因果参考。每个组合保持该检查调用原来的完整行数：

- 输入使用原增量矩阵，或完整全因果矩阵的 `[start:end]`。
- 过去 K/V 各自使用该原请求的 `[:start]`，或相同 fixture 的全因果历史 `[:start]`。
- 当前调用新增的 K/V 始终由所选输入经过原始投影计算。输入因子同时影响 Q、gate、当前 K/V 和残差输入，不把它误称为仅替换 Q。

每个组合使用私有缓存，不能把干预后的结果写回顺序重建的历史或另一个组合。层 32 的两个循环必须分别使用缓存 32 和 104。

`III` 在组合开始前与结束后各做一次，必须恢复原残差输出及追加后的完整目标 K/V 哈希。另对两个真正的 2,060 行参考、三个目标位置执行完整形状对照。`FFF` 保持检查调用的行数和历史终点，与真正全参考行的差别要单独记为调用形状/范围差别。

四次 marked prefill 从 0 开始，过去 K/V 都为空；它们的 K/V 对照相同，不能据此声称发现历史影响。保存实际张量 stride；现有抽样行存档不能证明原张量布局。任何原样对照失败都阻止因果归因。

## 第三阶段：残差输入与 mixer 输出的四组对照

分别替换残差输入与 mixer 输出，做 `II / IF / FI / FF`。官方运算是：

```text
ya = justnorm(a).float()
yb = justnorm(b).float()
lr = abs(alpha.float() * alpha_scale)
z  = ya + lr.float() * (yb - ya)
y  = justnorm(z).to(a.dtype)
```

两个内层 `justnorm` 会先舍入回 BF16，再转回 FP32；不能省掉这一步。`z` 和外层归一化使用原有 FP32 运算，alpha 仍是原始 BF16 参数，scale 仍为 `0.05 / 0.0177`。有效 `lr` 是逐坐标参数，不能假设所有值都在 `[0,1]`。

记录内层归一化结果、归一化前的 `z`、最后输出，以及各行范数、抵消程度、归一化前后的误差变化。这可以区分“mixer 已产生较大差异”和“残差混合后的小范数进一步放大差异”。两者交互也必须报告。`II` 要与原样 layer 对照一致；`FF` 对全参考输出的比较保留形状效应标签。

这些是局部受控诊断。即使某一替换减少了局部误差，也不能直接宣布七个最终 logits 失败已经解释、修复或通过验收。

## 预计资源与执行边界

以下是设计计算，实际新增张量数据仍为 **0 字节**：

| 计划保存内容 | 字节数 |
| --- | ---: |
| 六次完整 hidden / logits / 全部 K/V 输出 | 1,165,094,912 |
| 六次调用、三个位置的完整 input / mixer / residual | 221,736,960 |
| 两个全参考、三个位置的原始形状 layer 对照 | 126,566,400 |
| 87 点、三个位置、八种输入/历史组合 | 190,464,000 |
| 每点每位置的恢复对照 | 23,808,000 |
| 四种残差/mixer 组合的归一化中间值与输出 | 238,080,000 |
| **合计** | **1,965,750,272，约 1.83 GiB** |

计划为原始输出、元数据和余量预留 3 GiB NVMe，且预留以外仍保留根盘 28 GiB、NVMe 30 GiB 的空闲下限。需要读取已有完整缓存存档 5,867,691,008 字节；不再复制一整轮旧存档。保存缓存重建的保守上限为六个槽位各 2,060 token、全部 56 路历史；它不是模型和原生库的总内存预算。

预计为六次完整模型调用加 2,355 次目标层调用，共 8,751 次 oneDNN 投影。**这不是耗时预测或提速倍数**。完整原模型初始化仍有约 39.75 亿参数，内存、CPU、墙钟时间与原生库开销须由新执行器单独约束，不能沿用旧准入。可以在一次新的原始模型初始化后串行执行三个阶段，但此实现尚未准备或获运行准入。

本准备步骤只读了 198 个源码/JSON/JSONL 文件，没有读取张量或权重载荷，没有导入 Torch/NumPy，没有编译、设备执行、删除、启动队列或修改主状态。下一步须由主任务审核本设计，补齐新的生产器、独立存档复核器及串行资源准入，再执行。

冷缓存、长解码、请求槽位复用、完整质量与 HTTP 服务门槛继续保留。Dory 尚无新增模型通过结论，也无新增提速倍数。
