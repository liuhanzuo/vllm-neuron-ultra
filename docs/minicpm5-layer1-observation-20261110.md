# MiniCPM5 第二层完整缓存观测准备与 Nemotron r11 进展

MiniCPM5 的第二层观测后继 worker、完整缓存差分记录和计划检查已完成源码准备，**30 项检查通过**。实际计划准备退出 0，核对了 109 份原始 JSON 元数据、42,345,927 字节。没有读取原始张量、执行新的 MiniCPM5 前向或获得运行准入。Nemotron r11 同期继续串行运行，前六项状态读写检查已成功退出并独立核对。

## 为什么需要这一步

此前完整轨迹核对发现：MiniCPM5 的六次 decode 调用中，原锚点与仅 prefill 使用完整 BF16 投影的候选具有相同的七个当前输入、全部位置／掩码路线，以及第二层归一化输入；第二层历史 K、V 的哈希已经不同，首个记录到的预测差异在第二层注意力。现有记录没有保存完整缓存数值，无法量化差异或证明历史缓存是原因。

原 CPU 锚点仍为 29／32 数值通过、top1 32／32；两个候选均为 28／32、top1 31／32，继续判为不合格。当前工作用于建立可检验的因果对照，原失败和性能表保留。

## 实现的观测方式

后继 worker 沿用原三个配置、两路进程、每配置 14 次调用／32 帧及全部缓存连续性。原投影实现、权重、BF16、输入准备和旧四个预测位置观测点保持一致。

每次原前向完成后，先比较已保存的原调用：完整 logits、213 个预测观测点、全部输入／输出缓存元数据、七个外部输入、42 层位置与掩码路线、物理行映射和原 HF 指标必须逐项一致。之后再导出已经存在的第二层归一化输入、注意力输出和层输出三个预测位置张量，以及完整第二层输入 K/V。没有新增前向 hook，也不在这一步交换缓存。

导出之后还要重新检查全部 84 个输入缓存、84 个返回缓存、七个输入、完整 logits 和 213 个观测点，防止保存过程改变后续轨迹。真实运行必须通过这些检查，源码检查本身不构成观测无干扰的实测证明。

## 完整缓存如何控制存储

每个 K 或 V 的实际形状为 `[4, 1, 4224, 128]`，每元素 2 字节。84 次调用若直接保存完整 K/V，需要 **726,663,168 字节（693 MiB）**，超过原实验 256 MiB 总输出上限。

新记录把完整字节串分成 64 KiB 页。每配置、每路进程的第一条记录保存全部页；后续保存相对上一条输入缓存发生变化的页，页内容作无损压缩。读取时从精确哈希绑定的前一条完整缓存还原，再核验整个缓存哈希。四个槽位、4224 个位置和物理填充全部包含，没有截掉未使用区域或仅保留活跃 token。

原 **每路 128 MiB、总计 256 MiB、单文件 16 MiB、最多 512 个文件**的限制继续保留。合成字节测试验证了还原和错误拒绝，尚未证明实际数据可以在容量上限内完成导出。真实运行仍须检查实际占用，超限即失败，不自动扩大配额或减少观测范围。

## 已验证的内容与待办

30 项检查覆盖完整首记录、空差分、四个槽位及填充区变化、不可压缩数据、错误基底、页重排／重复、损坏／截断／额外压缩数据、14 次调用的完整帧映射，以及禁止修改原调用、精度、质量要求、来源哈希和输出上限。测试使用合成字节和实际元数据，没有运行模型；最初的 25 项属于最终 30 项的子集，不能相加。

实际源码计划保留原冷缓存、长解码、槽位复用、96 项质量与真实 HTTP／配对性能要求。仍需接入完整运行器及当前队列历史，串行运行完整轨迹并核验观测不改变结果，然后独立读取和还原保存的数据。

下一次因果实验先使用相同的当前输入与自身历史重放第二层 decode，要求复现捕获的原注意力输出，再比较另一个配置的历史。prefill 保存的是原预测位置观测，不能据此声称拥有完整 prefill 中间输入或已经完成其因果重放。

六项状态读写检查已完成：卷积状态、SSM 状态，以及 KV 长度 256／4096 的单行和四行四组检查。各阶段保留的实际退出、进程身份和进程组清空情况已独立核对。观察时控制器持有串行锁，正在执行后续控制阶段；本轮 52 阶段任务继续。
