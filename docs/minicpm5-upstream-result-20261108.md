# MiniCPM5：长提示首层差异定位到注意力输出

本轮完成了官方原生路径与 SDK CPU 双分片路径的首层完整前缀采集、残差/归一化重放，以及实际进程退出后的独立保存字节复核。**注意力输入完全一致；注意力输出开始出现差异。在保持 SDK CPU 的完整布局与补齐行不变时，仅替换有效前缀的注意力输出，即可使后续残差和归一化恢复为原生结果。**

这定位了第 1 帧首层的局部差异传播，不证明注意力内部哪一个算子有错，也不证明最终 logits/KL 差异的唯一原因。没有修改模型算子，没有新的 Neuron 整模型合格候选或提速倍数。

## 完整前缀实测结果

使用原长提示 1,231 个 token，CPU 保留 2,048 行物理桶，隐藏维度 2,048，BF16。两条 CPU 分片的全部七处完整边界逐字节一致；下表比较原生与 CPU 的 1,231 行有效前缀，每处均为 **2,521,088 个元素**，没有只检查最后一个 token。

| 首层边界 | 不同元素 / 2,521,088 | 最大绝对差异 |
|---|---:|---:|
| 层输入 | 0 | 0 |
| 输入归一化输出 | 0 | 0 |
| 注意力输入 | 0 | 0 |
| 注意力输出 | 802,431 | 0.0078125 |
| 残差相加后 / 后归一化输入 | 423,479 | 0.0078125 |
| 后归一化输出 | 584,829 | 0.03125 |
| MLP 输入 | 584,829 | 0.03125 |

最后一行完整 MLP 输入与此前 r3 采集逐字节一致，重现原来 584,829 个不同元素。原生与 CPU 的物理布局仍各自保留，不能把两种布局的不同 stride 本身当作数值错误。

## 固定 CPU 布局的三组替换

先用各路径自身的保存输入重放输入归一化、残差相加和后归一化；三个角色各五处，共 15 处控制的数值与布局全部精确复现，才执行下表。每次只替换前 1,231 行，CPU 的原补齐行不变，输出仍完整保存 `[1,2048,2048]`。

| 替换内容 | 后归一化相对原 CPU | 有效前缀相对原生 |
|---|---|---|
| 只换层输入 | 全部 4,194,304 个元素逐字节不变 | 仍有 584,829 个不同元素 |
| 只换注意力输出 | 584,829 个元素变化 | 2,521,088 个元素逐字节一致 |
| 同时换层输入和注意力输出 | 与“只换注意力输出”完整输出逐字节一致 | 2,521,088 个元素逐字节一致 |

只换层输入没有效果，与实际层输入本来就一致相吻合。在本轮固定输入、权重、CPU 布局与补齐方式下，注意力输出差异足以解释观察到的残差/后归一化差异。注意力模块内部仍包含 QKV 投影、RoPE、attention 计算和输出投影，下一步应在这些位置继续做完整前缀对照。

这些替换输出是局部计算得到的反事实结果，不是新的整模型观测输出；没有重新执行 attention、Gloo 通信、后续模型层或最终 logits。

## 执行和独立复核

原生、CPU 双分片、保存数据重放按顺序执行，模型控制会话 10266 实际退出 0。保存 **21 个完整边界、6 份归一化权重和 3 个完整替换输出，共 177,926,144 字节**，整个输出目录 178,425,856 字节，低于原 192 MiB 限制。七个已有参考锚点、原权重/算子调度、全部六个预测位置锚点均保留。

独立复核会话 5597 实际退出 0：重新认证全部 21 个边界、6 份权重和 3 个替换输出，重算完整指标、核对两 CPU 分片和 r3 完整 MLP 输入、独立重放 BF16 残差加法、核对补齐行未变。耗时约 99.23 秒，峰值 RSS 30.92 MiB；这是诊断开销，不是模型性能数据。它没有独立重跑 RMSNorm 的 rsqrt 算术、attention 或最终 logits。

新串行执行器 37 项检查、独立复核运行器 12 项检查通过；保存数据复核算法此前已有 41 项检查。本轮准备期间发现我们的历史读取器把 13.3 MB 的 v14 配置交给只认识 v13 的大文件读取规则，导致准备失败、未启动模型；已对该固定路径和哈希使用原 v14 读取器，补充真实大文件和错误哈希检查。所有失败记录保留。

实际完成历史已归档，前序 978 条服务记录与 190 条已知进程记录全部保留，追加本轮后共 981 条服务、196 条进程。归档进程也已实际退出 0，完整历史和资源释放再次独立核验通过。归档工具 17 项源码/模拟记录检查通过；首轮因测试样例缺少历史字段失败的记录保留，没有更改真实模型结果。
