# MiniCPM5 收尾失败与 LFM3、DeepSeek 诊断接入

2026-11-11 本轮没有新增合格模型或推理提速。MiniCPM5 已写出全部 24 个检查点的 72 份对照结果，但在收尾源码校验时失败；LFM3 与 DeepSeek 的下一步诊断已补齐源码和针对性检查，实际模型验证仍待执行。

## MiniCPM5：数据写出后，源码清单校验失败

真实运行会话 `58352` 以退出码 **1** 结束，终止记录为 `48dff3`。原生运行器在 `driver.run(...)` 返回后检查已加载模块，报错 `Every actually loaded local source pinned`。随后协调与外层进程按失败结束；三个实际进程均已消失，服务已排空。失败和全部输出保留。独立失败记录程序随后实际退出 0，明确保留模型退出码 1 与缺失的成功凭据，没有将记录程序成功当作模型成功。

这不能记为采集成功：原结果汇总及最终权重、函数恢复凭据未写出，现有成功审核入口要求这些凭据。72 份局部结果的存在也不能代替逐字节完整数据审核。严格的原生/Neuron 保存数据比较尚未通过。

下一版将完整认证实际使用的原生 Transformers 源码包，并在模型加载和长时间采集前检查已加载依赖；同时保留最后的源码与科学结果校验。正在修正的是自有实验运行器的依赖清单，尚无依据将这次失败归因于模型计算、Trainium 硬件或正常 vLLM 服务。

## LFM3：为 BF16 数据搬运诊断补齐真实运行入口

旧 typed v5 在原 CPU 回归后，扩展测试首例仍复现 NaN 位模式变化；未改变的完整重跑不会提供新证据。新增诊断使用固定 NKI 0.5 环境，逐步观察输入、载入、暂存、条件复制、写回和返回值，保留原失败样本的准确摘要，并覆盖所有 65,536 种 BF16 编码。该诊断不修改已通过的 B4 模型包。

源码检查通过：13 项来源、768 组槽位映射、六项损坏/类型/形状负控。独立串行入口已接入原锁、完整历史排空、固定 CPU/内存/时限和非零失败处理。主任务独立检查 `30753 / f3d208 / 0` 确认合成失败会保留诊断结果并退出 1，不产生成功凭据；约 13.49 MB 的完整历史代表数据能无损分块到约 1.06 MB，满足原 256 KiB 单文件和 4 MiB 总量限制。

这些是源码和合成检查。实际 NKI 模拟器、原 CPU3716/291、设备与完整模型测试仍未通过此新入口执行。既有 LFM3 配对收益和 B4 资格范围不变。

## DeepSeek：保持 CPU 采样的独立中间值观测

原 DeepSeek-R1-0528-Qwen3-8B 冷缓存诊断保留 42 个原生帧、84 个设备帧、四个物理槽位、两条不同输入流及全部 14 个失败帧。新代码固定 BF16、TP2 和原模型，捕获 36 层各 13 个边界，共 468 个具名张量；Q/K/V 分别保存，两个 TP 分片都保留。

当前 SDK 的默认张量捕获要求设备端采样。直接绕过限制会导致 logits 解析错误；强行增加第二个 logits 头又可能错置 KV 输出。实际已安装源码的 AST 检查复现了这三种不受支持的诊断配置问题；不能据此声称普通服务路径存在同样故障。隔离适配器明确采用一份 logits、全部捕获值、72 个 KV 的输出顺序。

为控制输出量，图内先选择每个原预测位置，再汇集 TP 分片；完整特征和全部 KV 历史保留。其他 prefill token 的中间激活、注意力概率及 MLP 内部乘积未观测，因此该诊断只能定位所观察位置的分歧，不能证明首个全局因果故障。

三组源码检查分别通过 7、5、5 项，覆盖原测试循环不变、输出偏移、独立生命周期路径，以及原始 logits/KV 的完整一致性验证接口。根审查发现初版设备 logits 缺少预先固定的摘要核对，推荐 v2 已要求调用方绑定四份 logits 和所有外层报告、清单，再进行反序列化和比较。真实编译、运行及观测开关一致性仍未执行。

完整输出估计约 **12.24–22.22 GiB**，另计最多约 15.26 GiB 权重副本与尚未测定的编译空间。根盘仍需保留 28 GiB、NVMe 保留 30 GiB；实际运行前须核对可删除的已结束产物和权重共享，当前没有总空间准入结论。
