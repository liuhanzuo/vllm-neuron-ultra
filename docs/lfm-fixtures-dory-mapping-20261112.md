# LFM 完整测试数据、Mini 映射诊断与 Dory 接入进展

2026-11-12 本轮继续原 15 个模型家族的研究。LFM3 完整 CPU 对照仍在运行；MiniCPM5 和 Dory 完成了下一步诊断工具的源码验证。本轮没有新增整模型验收或推理提速倍数，既有结果见[全部模型提速表](model-speedups-20261112.md)。

## LFM3：原环境的完整测试数据已生成并复核

现有串行任务没有重启。原 Python 3.10 环境完成 3,716 个用例的输入与预期输出生成，包含 1,648 个回归用例／123 批次，以及 2,068 个扩展用例／168 批次。主任务独立重读 587 份 JSON，核对全部 291 个报告、输入和预期输出的类型／形状／字节数／哈希，以及父进程记录的退出码 0、子进程 PID、启动时间和启动确认，全部一致。

这一步完成的是原环境测试数据基准。新 Python 3.12 环境仍须逐字节复现同一批输入和预期输出，之后才能进入三组控制和候选模拟器执行。当前观察记录中，新环境已写出 13 个通过报告、覆盖 208 个用例；它是运行中的局部进度，不能称为完整 CPU 通过。

完整计划仍为三遍各 3,716 用例／291 批次，加一个独立控制子进程，共 874 个子进程。原始模拟器失败必须保留；候选使用的模拟器写回修正即使通过，也不能代替设备行为、缓存别名、整模型和 HTTP 性能验证。原权重、精度、冷缓存、长解码、请求槽位复用与质量门槛继续保持。

主任务再次确认原 outer／worker 的进程身份和实际 user service；原串行交接文件保持不变。完整运行结束后，还需核对实际工具退出、全部子进程报告和资源释放，才能安排下一项实机工作。

## MiniCPM5：将映射错误诊断推进到可审核的观察逻辑

此前实际失败仍是 `import torch` 加载 `libcusparseLt.so.0` 时的 `failed to map segment from shared object`。异常没有 errno，尚不能确定失败是否来自地址空间上限或其他原因。

源码复查发现，最初考虑的 `strace -D` 在固定上游版本中会调用 `PR_SET_PTRACER_ANY`，并使用两次 fork。该发现只说明上游实现，不能证明本机二进制与其完全相同；本轮没有运行 strace。新设计改为由原 outer 通过 `PTRACE_SEIZE` 观察自己的直接 SDK 子进程，保持 SDK 环境、父进程关系和原 2 GiB／900 秒限制。

已实现不含原生追踪接口的纯事件处理逻辑，主任务独立执行 47 项模拟检查通过。它同时推进非阻塞输入写入和进程事件，只等待已知任务；新增任务必须来自内核的 fork／clone 事件。普通 SIGTRAP 会继续传递，`PTRACE_EVENT_EXIT` 只算停止事件，只有真实退出状态才能更新子进程退出码。

审阅期间修正了两个自有工具问题：真实退出必须先保存，后续日志超限不能将其丢失；事件预算应在读取退出状态之前检查，预算耗尽后使用独立的清理流程继续收取真实退出。未知进程、缺失调用配对和无法排空均不能被标记成功。`brk` 返回旧地址不会被自行解释为 ENOMEM，系统调用重启码也不作为最终 errno。

这仍是源码与模拟结果。原生库来源认证、实际 ptrace 接口、原输入门控及输出存储接入尚未完成，没有新的真实映射 errno。最多 2 MiB 的追踪输出和原总预算保持；原导入前还有大量源码认证，追踪开销可能耗尽原 900 秒，因此实际可完成性仍待验证。本实现只记录数值文件描述符和偏移，尚不提供动态库路径归属证据。

## Dory：有限 glibc 元数据读取已接入原串行流程

新增四份源码，将已审核的 glibc 元数据 API 接入原 inventory 父子进程执行流程。保留七份固定历史输入、原租约与握手、2 GiB 地址空间、600 秒 CPU／900 秒总期限、128 MiB 输出，以及进程组排空后才释放串行锁的要求。

下载顺序固定为两个已认证历史 Release 对应的 by-hash Sources 索引。完整长度、压缩与解压哈希、精确源包记录通过后，最多再读取一个由索引导出的 DSC；不下载源代码归档。保存后通过固定 API 完整重放，检查全部结果和请求记录。HTTP 的 EOF 指完整消息体结束，不证明原始 socket 的 EOF；阻塞 DNS 由原父进程总期限兜底。

主任务读完四份源码和两份测试，分别独立执行 18 项传输／保存检查与 12 项接入／重放／清理检查，全部通过；最终 20 份本地源码依赖摘要也已核对。之前已通过的核心 API 25 项检查没有重复计算为本轮新增结果。

真实网络和新父子进程尚未运行，历史 by-hash 地址是否仍可访问也未验证。原 15 条动态库加载关系、原生 ABI 和整模型验收仍待解决。
