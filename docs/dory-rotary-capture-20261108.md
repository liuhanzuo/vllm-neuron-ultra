# Dory RoPE：修复结果记录错误并准备完整字节复核

Dory 的位置编码对照新增了完整输出采集和独立复核代码，**18 项标准库检查通过**。这轮没有执行 PyTorch 原生数值对照，没有加载模型权重，也没有新增提速结论；当前串行设备实验仍是 Nemotron r6。

## 发现并修复的自建测试问题

旧版 `dory_rotary_arithmetic_v1.py` 的结果组装显式传入 `dtype`，又展开了包含 `dtype` 的比较结果字典。这会在第一条比较结果组装时触发 Python `TypeError`。原有 24 项源码检查没有覆盖这条运行路径，不能据此认定旧程序已能完成数值执行。

新建的 v2 保留旧源码和固定科学计划，只移除冗余的字段参数，使用比较函数记录的实际 `torch.dtype` 字符串，并采用 v2 结果格式。新增检查直接复现原来的重复参数异常，并验证除记录逻辑外原计算语句不变。这是我们尚未执行的测试程序缺陷，不是 Dory、上游 vLLM、Neuron 或芯片的已证实问题。

## 未来实测会保留什么

原计划仍覆盖两种 theta、FP32/BF16、两组输入、Q/K 和六个位置，合计 96 个独立比较条件。完整 262,144 位置缓存继续按原函数生成，不缩短为采样缓存。

程序将先运行一次不采集的控制轮，再运行一次采集轮，共 192 次位置比较；这仍然只有 96 个独立条件，不能把重复执行算成扩大覆盖范围。两轮全部输出指标和输入、缓存指纹必须一致，才认为采集未改变结果。

采集轮保存 53 个完整张量：位置数组、四份选中位置的缓存系数，以及八组条件下的 Q/K 输入、本地候选输出和官方原生函数输出。总计 **2,230,320 字节**，每个文件记录完整形状、dtype 和 SHA256。每组 Q 为 `[6,16,256]`、K 为 `[6,4,256]`；不会只保存少量元素或最大误差。

## 独立复核的范围

标准库复核程序不导入 Torch。它重新读取全部保存字节、重建确定性输入、核对每一条比较记录，并用保存的缓存系数重新计算旋转的两半乘加，在每次运算处按 FP32 或 BF16 舍入后比较完整字节。正负零即使数值相等，字节不相等仍判为失败；非有限值、错误形状、缺失张量或被修改的文件会被拒绝。

本轮测试使用明确标注的合成系数和合成保存文件，验证的是采集/复核程序和反例处理。它没有证明真实 RoPE 的数值一致性。后续真实复核也不重新生成全缓存的三角函数，更不替代官方后端 dispatch、CPU 融合内核、线性投影、SDPA 或原权重整模型验证。
