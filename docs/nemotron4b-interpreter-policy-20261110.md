# Nano4B：两个 Python 环境的解释器来源检查

2026-11-10 UTC：已完成解释器检查模块的源码审查，并保存两套实际环境的候选清单。这一步补上了先前启动恢复中对内置模块、冻结字节码和模块别名的检查接口；完整 SDK 启动与模型计算仍未执行，没有新增提速结果。

## 为什么需要区别处理

原生参考使用 Python 3.12，Neuron 环境使用 Python 3.10。Python 3.12 的 `site` 等标准库模块由解释器内嵌的冻结代码提供，不能用磁盘 `site.py` 的哈希证明它们的来源。两个环境还保留 `importlib._bootstrap` 等合法别名，直接要求注册名、模块名与 spec 名全部相同会误拒绝正常启动。

| 实际观察 | 原生参考 Python 3.12 | Neuron Python 3.10 |
|---|---:|---:|
| 可导入内置模块 | 96 | 59 |
| 发现的冻结模块 | 29 | 6 |
| 冻结模块枚举方式 | 解释器提供完整枚举接口 | 标准库文件名、预加载名及明确的 CPython 名称扫描 |

Python 3.10 的扫描不代表穷尽所有可能名称。这些清单描述观察进程，未来 worker 仍须检查自己的解释器与实际加载依赖。

## 已实现和验证

检查模块将解释器实际进程映射与已经校验的原生文件清单关联，核对原始导入器、解释器内置调用、冻结模块代码和合法别名。冻结代码记录覆盖嵌套代码、常量和位置字段，并按固定顺序编码；两次不同随机哈希种子的独立进程观察得到相同清单。

真实 Python 3.10 与 3.12 各执行 23 项测试，共 44 次通过、两次因版本不适用而跳过。检查覆盖错误的解释器身份、缺失映射、未校验文件、被替换的导入器、装饰器闭包代码变化、错误冻结代码、未绑定模块和别名替换。测试使用了真实冻结代码与原始加载器，但解释器文件和映射证据使用合成数据，不能据此声称真实二进制已验证。

两套实际环境观察读取了文件属性并在内存中检查冻结代码，未读取原始解释器或 SDK 二进制内容，也未执行真实环境的 `site.main`、模型、Torch、Neuron SDK 或辅助程序。源码审查复核三份新源码与七份前序源码固定值，保留最初语法失败记录；本轮未因源码未变而重复已有测试。
