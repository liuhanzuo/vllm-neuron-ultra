# Dory 注意力对照：调用形状与完整历史 K/V 的影响

2026-11-09：已完成 CPU 注意力对照及独立保存数据复核。结果确认，在本实验的 BF16 计算中，查询行数、被遮蔽的未来 K/V 长度以及可见历史 K/V 的差异都会影响部分注意力输出。**这还没有证明原先 7 个完整模型数值失败的根因，也没有新增 Dory 提速倍数。**

## 做了什么

此前[前五层重放](dory-long-reference-status-20261109.md)保存了当前 token 的查询 Q，以及可重建的完整历史 K/V。本轮以这些已经核验的数据为输入，覆盖全部 87 个标记点的物理层 0、2、4，共 261 组对照。Q 用于提出当前 token 的查询，K/V 保存注意力可以读取的历史信息；只比较当前 token 的 K/V 行不足以比较整个注意力输入。

对照使用固定官方源码中未经修改的 `ReferenceAttention` 类，CPU PyTorch `2.14.0+cpu`、原 BF16 输入、16 个查询头、4 个 K/V 头、每头 256 维、缩放 0.0625、滑动窗口 1024。类通过 AST 提取执行。本轮没有加载权重、执行完整模型或使用 Neuron，也没有证明具体底层原生库/JIT 算法的身份。

每组都执行增量路径 I 与整段参考 F 的 Q/K/V 八种组合：III、IIF、IFI、IFF、FII、FIF、FFI、FFF。另有完整 K/V 长度、存储布局、原增量单行重放和整段查询形状对照，总计 **2,877 次注意力调用**。

两个重要限制：

- 87 个标记点中，83 个原本就是单行查询，其 249 个分层输出全部逐字节复现。另 4 个原调用是较宽的 prefill；本轮抽取其目标行计算，明确改变了查询形状，不能算作原调用形状复现。
- 整段查询对照保持 2,060 行查询和原完整 K/V，只把已保存的 33 行 Q 放回原位置，未保存的查询行显式填零。两条轨迹、三层合计 **198 个选定输出全部逐字节复现**；没有复现或验证整个原始 Q 矩阵及所有输出行。

## 哪些因素改变了输出

每层分母均为 87 个标记点；“不同”表示保存的输出存在字节差异，并不等同于超过完整模型验收门槛。

| 物理层 | 改变查询行数后输出不同 | 移除被遮蔽的未来 K/V 后输出不同 | 仅改变 K/V 存储布局后不同 | 可见 K 历史不同 | 可见 V 历史不同 |
|---|---:|---:|---:|---:|---:|
| 0 | 57 | 53 | 0 | 71 | 75 |
| 2 | 65 | 58 | 0 | 87 | 87 |
| 4 | 64 | 52 | 0 | 87 | 87 |

查询行数对照保持目标 Q、完整 2,060 行 K/V 的数值和步幅、以及目标查询的因果/窗口遮罩不变。261 组中 186 组输出不同，各层观察到的最大绝对差均为 **0.000244140625**。这个结论只适用于本次受控输入和计算环境。

未来 K/V 长度对照保持查询与可见 K/V 数值不变，只移除已被遮罩排除的未来位置，261 组中 163 组输出不同。这个操作同时改变键的总长度和必需的步幅几何，不能进一步断言某一种内核选择就是原因。独立的存储布局对照在本次 261 组中均无输出差异，不能外推为所有形状都不受布局影响。

此前第 0 层当前 K 行仅在 8/87 个点不同、当前 V 行在 18/87 个点不同；完整可见历史分别在 **71/87、75/87** 个点不同。因此当前 token 的 K/V 相同，不能用来排除注意力输入差异。

III 与独立增量单行重放在全部 261 组中一致；这个检查也包含明确改变形状的 4 个较宽 prefill 标记点，不能因此把它们算作原形状复现。

## 如何核验，以及我们自己的问题

原生对照和独立复核均观察到实际退出码 0。复核重新重建 6,185 次原始缓存追加和 6,200 个生命周期事件，核验 **135,794,688 字节缓存追加数据**，检查每个保存的 Q/K/V 来源哈希与布局、可见历史差异数量，并重新读取 **267 个输出文件、25,141,248 字节**，复算全部记录的输出比较。全部 249 个原单行输出及 198 个选定整段输出核验一致。

第一次复核在启动检查时失败：我们自己的 JSON 读取器默认最多接受 4 MiB，而结果文件实际为 8,474,267 字节。它尚未取得串行锁或创建输出，也没有运行模型。v2 仅将该有界读取上限改为 16 MiB，仍校验 SHA256；原脚本、失败规格和退出记录均保留。该失败未取得进程启动身份，证据中明确标为缺失，不补造 PID。这不是模型或上游仓库错误。

原生对照约 197.86 秒、独立复核约 203.30 秒；这些是诊断和核验耗时，不能作为推理速度。当前复核验证保存数据；原权重来源与前一轮执行证明继续由已发布的前五层复核承接，本轮没有重新读取全部权重。

## 结论和后续

原先 7 个整模型失败及原 FP32 验收门槛全部保留。现有证据不足以断言 PyTorch、oneDNN、vLLM 存在通用缺陷，也没有涉及 Trainium 执行，不能归因于芯片。后续仍需定位更后层的差异传播和因果关系，随后完成完整模型、冷缓存至 4096、长解码、请求槽位复用、生成/RNG/停止/文本、质量、真实 HTTP 四并发和配对性能验证。不能用失败参考作为提速分母。

已有其他模型的[提速倍数与适用范围](dory-long-reference-status-20261109.md#已有提速结果保持原范围)保持原记录；全部 15 个模型家族继续在长期任务范围内。
