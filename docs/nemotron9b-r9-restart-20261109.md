# Nemotron 9B：空间已恢复，r9 完整验证已提交启动

## 如何恢复空间

首先检查了约 4.9 GiB 的 uv 缓存，发现绝大多数文件与现有软件环境共享硬链接。删除缓存会影响固定的文件身份，而且几乎不释放实际数据块，因此这些缓存保持原状。

随后在独占串行锁内，对精确列出的 16 份已关闭日志进行无损压缩：12 份此前保存在 NVMe 的归档、4 份根盘旧日志。原始总计 **2,147,483,648 字节（2 GiB）**，gzip 总计 **251,842,473 字节（约 240 MiB）**。每份压缩文件均完整解压并核对原始字节哈希；此前 12 份归档也与既有独立记录的哈希一致。全部核验通过后才移除原文件，并保留逐文件恢复映射。日志正文留在本机私有归档，没有上传仓库或飞书。

维护任务实际退出码为 0，耗时约 94 秒。结束时根盘可用 **29.35 GiB**、NVMe 可用 **48.28 GiB**，已满足新实验原定 **29 GiB、48 GiB** 的预留要求。模型权重、未解决实验、运行库和冻结的进度文件核验不变，没有扩容，也没有停止用户服务。

准备中还纠正了一个自身校验问题：已复制日志的文件修改时间是复制时间，不能用来判断原日志何时结束。新规则分别绑定归档文件当前身份与此前保存的原日志关闭时间。正式维护前的 8 项归档检查覆盖完整解压、内容错误、源文件变化、已有归档、符号链接/硬链接和活动日志拒绝；均通过。
