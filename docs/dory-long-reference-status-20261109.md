# Dory 长解码参考：已记录的数值失败与后续诊断

这是一份 **2026-11-09 的复核完成记录**，已补入第一层投影、前五层传播及完整历史 K/V 注意力对照的独立复核。Dory 原权重长解码完成全部 **6,185 次调用、87 个标记检查点**。独立原始缓存重建、原 FP32 指标复算、全部 logits 与逐层缓存差异分析均已完成；**7 个检查点仍未通过原定数值门槛**。数据复核通过不能把数值失败改为合格。当前没有新增 Dory 整模型资格或提速倍数。

## 失败发生在哪条路径

当前运行的是官方 vLLM Dory 模型、原始 BF16 权重、官方线性层与上游 CPU ReferenceAttention 测试实现。它使用实际权重执行 CPU 前向，生产注意力后端、Neuron 编译和 HTTP 服务尚未进入本轮测试。

| 对比 | 当前证据 | 能说明什么 |
|---|---|---|
| 同一次调用：官方模型与共用官方投影的对照实现 | 6,185 次调用、6,200 个事件、11,735,382,016 字节归档已独立复核；完整状态哈希重建一致、缓存前缀保持不变 | 对照在当前输入及调用方式下复现官方路径；包括 2,052 项与独立新进程的状态比较 |
| 官方模型：整段 2,060-token 因果计算与增量计算 | 完整 87 个检查点中有 7 个未通过余弦、最大绝对差或 KL 门槛 | CPU 参考的不同调用方式出现数值差异，尚未定位原因 |
| Neuron 与官方参考、端到端服务 | 本轮尚未执行 | 不能把上述现象归因于 Trainium，也没有新的性能结论 |

共用官方投影是定位差异的因果对照，本身没有独立的优化收益。它不改变先前独立 F.linear 候选被拒绝的结论。

## 目前可以排查什么

上游 ReferenceAttention 的因果条件为 `key_pos <= query_pos`，窗口条件为 `key_pos > query_pos - window`；其后调用带 GQA 的原始 SDPA。位置接近 1024 本身不能证明窗口边界有错误。当前没有足够证据宣称上游 vLLM、PyTorch、oneDNN 或 Neuron 存在缺陷。

源码中整段参考的输出头输入有 33 行，增量路径有 1 行；更早的投影和注意力输入形状也不同。调用形状、BF16 舍入的传播以及窗口附近的状态差异都是待排查方向，不能仅凭相同首选 token 确定原因。

主任务实际退出码为 0，执行器耗时约 7 小时 2 分钟。独立状态复核耗时约 76 分钟，随后完成全部 87 个检查点的原 FP32 指标复算。两项均正常退出，全部指标与原记录完全相同，原有 7 个失败保持。进程退出码为 0、同次调用对照一致、或者复算出的指标与原记录完全相同，都不能把不合格的数值结果改为通过。

只读解释程序已分析全部 87 对原始 logits，核验 80,216,064 字节输出数据，并计算平均偏移、误差均方根、减去平均偏移后的残差，以及原始／中心化余弦。这些 Float64 统计只用于解释，验收继续使用原 FP32 公式；程序没有保存归一化后的替代结果。

7 个失败点中，平均偏移解释的平方误差比例仅为 **0.38%～44.32%**；每个点扣除这个常数后仍保留过半的平方误差。因此不能把这些失败简单解释为所有 token 分数一起平移。位置 2047 的中心化余弦约为 0.840，位置 2051 约为 0.918；这些统计不替代原验收结果。

逐层分析还核验了 89 个所选官方归档的全部字节，共 1,228,073,984 字节，并比较全部 87 个点的 **9,744 对 K/V 行与 87 对最终隐藏状态行**。每个检查点都保留全部 56 组循环历史，并按实际层执行顺序排列。

## 第一层投影诊断：相同输入的形状差异

## 保留的后续范围

原有 **13 次参考交叉检查已执行并完成两项独立复核**：两条原始 fixture 分别从 127-token 前缀继续解码至位置 127／128／129，6 个检查点均通过原数值门槛。最小余弦为 0.9999760389、最大绝对差为 0.2058212757、最大 KL 为 0.0009606301，首选 token 为 6/6 一致。请求 A 明确释放后，同槽位换入不同请求 B 的三次调用也与独立新进程状态一致；独立复核重建了 162,301,952 字节保存数据，核对 684 项跨进程状态比较，6 个 FP32 指标字典逐项完全复现。原生运行、状态复核和指标复核的实际退出码均为 0。

该交叉检查没有消除原长序列的 7 个失败，也不是生产调度器四并发或实际服务槽位复用验收。输出头单独诊断暂缓，先继续定位模型内部差异。冷缓存前缀仍保留 32、128、256、512、1024、2048、2052 和实际 4096。

真实采样、请求随机数生命周期、停止条件和文本解码仍待运行。模型默认思考／随机采样与固定质量／非思考贪心两组各保留 96 个用例、每组最多 35,840 个输出 token。生产调度器、实际四并发 HTTP、Neuron 编译与配对性能比较仍需分别验证。

文本验证准备还修正了我们此前文档的一个用词：分词器的 1,000 个附加 token 中，994 个是特殊 token，另 6 个是普通附加 token，即 `<think>`、`</think>` 和四个工具调用／响应标记。这 6 个在跳过特殊 token 时仍应保留。已增加相应合成用例；新的原生停止／解码测试尚未执行。这是我们测试覆盖和表述的修正，没有观察到上游分词器缺陷。

原任务及后续复核使用串行执行。失败或未解决问题的原始证据继续完整保留，不删除或去重这些归档，EBS 不扩容。
