# Qwen3.5 采样实测与 MiniCPM5 启动诊断

2026-11-12：Qwen3.5-2B 的两侧 HTTP 测试已经跑完，随机采样测得 1.23×／1.85×、混合长度 1.68×。但汇总存在两个本项目工具问题，整轮实际退出 1，因此这些是**已独立复核的实测吞吐量比，尚未完成整轮验收**。MiniCPM5 的两路真实 Python 启动诊断实际退出 0，并通过独立复核；正式原生模型检查仍待继续。

## Qwen：做了什么优化，测到了什么

本轮保持 Qwen/Qwen3.5-2B 的原 BF16 权重与同一设备图，仅比较标准 CPU 采样和快速 CPU 采样。两侧均为 Trn1、TP2、物理解码 batch 4、context 4096，保留相同 DEBUG 行为，计时阶段关闭采集。基线使用已有 Qwen3.5 文本适配器和专用 vLLM-Neuron 服务入口，不能称为未经修改的上游。

快速路径先从 248,320 个词表分数中取有限候选，再在小集合上计算 top-p 分布和抽样，减少完整词表上的排序与随机数生成开销。它仅支持 CPU FP32 logits、top-k 1–64；候选最多 128 个，遇到过多并列值、top-p 边界不稳定、显式请求随机数生成器或不支持的输出模式时退回原实现。温度、惩罚项、贪心和原始 logprobs 仍由 vLLM 处理；无显式 seed 时不要求两种算法消费相同的随机数序列。

收益集中在 temperature=0.7、top-p=0.9、top-k=40 的负载。贪心解码不经过相同的随机采样工作，因此本轮未见收益。以下为三轮 HTTP 吞吐量的中位数；单请求和 C4 分别统计，C4 是四并发的总吞吐量。

| 工作负载 | 单请求：标准 → 快速 token/s | 比值 | C4：标准 → 快速 token/s | 比值 |
|---|---:|---:|---:|---:|
| 贪心，输入 128／输出 512 | 10.3136 → 10.2992 | 0.999× | 39.2712 → 39.2149 | 0.999× |
| 贪心，输入 512／输出 128 | 10.1280 → 10.1078 | 0.998× | 36.5573 → 36.5910 | 1.001× |
| 贪心，输入 1536／输出 128 | 9.7499 → 9.7110 | 0.996× | 33.2014 → 33.2377 | 1.001× |
| 随机采样，输入 128／输出 512 | 8.2874 → 10.1823 | **1.229×** | 20.4985 → 37.8525 | **1.847×** |
| 混合长度，16 请求／轮，最多 C4 | — | — | 18.0902 → 30.4032 | **1.681×** |

独立复核重新计算了两侧各 124 个请求、30,848 个输出 token 的完整工作负载，包括流式请求和混合轮次，输入 token ID 与预算一致，57 对贪心文本全部相同。另有 19 对初始请求，各输入 19／输出 120 token，文本相同。这些是顺序运行的描述性测量，没有统计显著性结论，也不能直接移用于新包路径。

两侧状态复制、32 帧数值、84 帧冷缓存、1,541 步长解码及槽位复用检查通过，各 203 个原始输出向量逐位重现参考。采样捕获与原生重放各覆盖 32 次调用／80 行 logits，自己的 token 与 RNG 状态重现、完整词表分布门槛及 13 项边界控制通过。quality96 两侧均为 69/96，96 条文本全部与保存的原参考一致。

## 为什么仍不计入合格提速

实际会话 78094 最终退出 1。协调进程在全部 HTTP 测试结束后的汇总处报 `initial token budget changed`。原因是校验器把整个 `usage` 字典与仅含三个计数字段的字典直接比较；本次非流式 API 正常多返回了 `prompt_tokens_details: null`，实际 token 预算没有变化。

修正后继按三个计数字段分别检查严格整数类型和值，同时保留两侧 usage、贪心文本、请求数及吞吐量核对。26 项保存数据与反例检查通过，覆盖原失败复现、可选字段、缺字段、错误计数、浮点／布尔计数、文本和计时篡改。原实验源码及结果没有改写，修正尚未接入新的真实运行。

进一步复核发现：两侧 `host.json` 都缺少原校验器要求的 `effective_host_settings`。这会使下一步主机配置比较失败。实际 API 参数、worker 挂接和环境摘要存在，但不能把缺少的字段事后伪造为运行时记录。因此保持主机配置门槛未通过；原 driver／coordinator 成功结果以及最后一次图复用核对也未产生。

本轮独立审计确认 54 个进程身份、21 个服务均已结束，原串行锁已释放。保存数据复核的前三版分别遇到遗漏常量导入、遗漏 hashlib 导入、以及上述真实主机字段缺口；这些失败和最终明确保留缺口的复核均保存。它们属于本项目工具问题，不能归因于 Qwen、Python 或上游 vLLM-Neuron。

下一轮先补齐实际运行时主机配置记录及其两侧比较，再使用不可变后继完成原有全套验收。[独立包路径](qwen35-package-20261112.md)仍需自己的编译、原生导入、模型与性能验证。
