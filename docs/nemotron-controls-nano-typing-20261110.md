# Nemotron 投影单行对照与 Nano4B 真实 typing 源码检查

2026-11-10 UTC：Nemotron 9B 的八种投影形状均已完成原始／候选配对，候选 48 次设备输出比较全部逐位一致；Nano 4B 已增加使用实际 typing 源码和函数代码定义的认证回调，并接入模块来源检查测试。整模型和提速结论尚未新增。

## 单行对照进一步缩小投影问题的范围

| 投影输入形状 | 原方式：逐位一致 | 候选：逐位一致 | 原方式：地址错位／抽查数 | 候选：错位 |
|---|---:|---:|---:|---:|
| [1,1,11328] | 6/6 | 6/6 | 0/9 | 0 |
| [4,1,11328] | 0/6 | 6/6 | 27/36 | 0 |

单行正对照中，原方式本身正确。增加到四行后，原方式失败、候选仍正确。结合[此前六个长度 128～4096 的结果](nemotron-projection-nano-origin-20261110.md)，原方式在七种跨行形状上失败，在一种单行形状上通过；候选在八种形状、共 48 次设备输出比较中全部通过，抽查地址均正确。

这进一步支持当前 Neuron 转换路径中的行步幅处理问题。结论没有独立归因到某个上游组件或其他版本。原精度 BF16、原投影尺寸 [5120,6144,64] 及消费者均保留；候选明确使用切分边界 [5120,11264]。

四个新增阶段均保留实际退出和结果记录。本次只读取结果元数据，没有重新读取原始张量，也没有完成全实验的独立原始证据审计。完整 52 阶段实验已进入后续卷积切分检查；整模型冷缓存 4096、长解码、槽位复用、生成质量和 HTTP 配对性能仍需验证。单行原方式通过不能替代整模型基线资格，失败形状也不能用作提速分母。

## Nano4B：从接口兼容推进到实际源码检查

前一步 v4 已能正确处理 Python 把 typing.io／typing.re 类对象放进模块表的行为，但调用方仍需认证其所属 typing。新增 TypingSourcePolicy 读取并核对实际 typing.py 完整内容，编译但不执行该源码，将已加载函数的代码定义与源码中的定义比较，再绑定原模块、加载器、代码对象、默认参数和闭包对象身份。

| 实际环境 | typing 源码字节数 | 源码代码定义数 | 检查到的函数数 | 代码定义不匹配 |
|---|---:|---:|---:|---:|
| Python 3.10.12 / Neuron 环境 | 92,557 | 263 | 185 | 0 |
| Python 3.12.16 / 原生参考环境 | 118,836 | 291 | 200 | 0 |

两次实际观察均保留 -B -S、禁用用户 site、关闭优化并使用独立空缓存目录。没有执行原环境 site 钩子、SDK、模型或显式读取原生库。

Python 3.12 中的 _lazy_load_getattr_static 使用 functools 的原生缓存包装器。源码检查将它保留为独立边界，要求外部认证回调明确返回 True，并在后续检查中持续重验。测试中的此回调仍是替身，尚未证明真实原生包装器来源已通过认证。

新的回调已连接 ModuleOriginAudit v4，并完成一次实际 typing 对象、生成源码导入和来源检查的组合测试。两套环境各发现 19 项测试：3.10 通过 16 项、跳过 3 项不适用的原生包装器场景；3.12 通过全部 19 项，总计 35 次通过、3 次跳过。测试覆盖源码哈希和版本错误、代码对象替换、函数替换、默认参数身份变化、加载器替换、命名空间导出变化、认证拒绝和撤回。

首次观察因启动时漏带禁用用户 site 的环境项被检查拒绝；修正调用后成功，源码未改。最初测试草稿有语法错误，发生在创建测试文件前；失败草稿和退出记录也已保留。

这些检查仍不能证明所有任意全局变量、可变默认参数／闭包内容、传递依赖或映射内存正确。源码清单是本机候选快照；完整解释器、原生依赖、主进程／rank／辅助进程启动接入和资源生命周期仍待完成。后续文件身份复核还依赖实际运行期间排除并发写入。
