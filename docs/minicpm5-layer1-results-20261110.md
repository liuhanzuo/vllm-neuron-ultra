# MiniCPM5 完整缓存验证与 Nemotron r11 阶段进展

MiniCPM5 新增结果验证器、独立字节还原器和有界读取接口，最终 **28 项测试通过**，完整后继源码计划准备退出 0。测试使用原 JSON 元数据和合成字节，没有执行新的模型或读取真实保存张量。原 30 项观测准备检查的源码和证据保留。

截至 **2026-11-10 06:44:41 UTC**，Nemotron r11 的 52 阶段中已有 **15 阶段**成功退出并独立核对：1 个准备阶段、9 个状态读写阶段、5 个张量切分阶段；正在运行 512 token 投影的 tensor-split 检查。现有串行任务继续，没有新增整模型合格结论或提速倍数。

## MiniCPM5 具体补了什么

旧运行器只接受“不保存缓存”的结果格式。后继结果验证器保留了原完整数值检查、原阈值、BF16 投影条件、权重证明、三配置／两分片的全部 84 次调用和跨调用历史检查，仅增加第二层观测格式、计数和完整缓存描述检查。源码结构比较确认原验证逻辑仍被保留。

这里有两种不同的历史关系，二者都必须成立：

| 检查 | 正确的前序对象 |
| --- | --- |
| 当前模型输入缓存 | 上一次调用实际返回的缓存 |
| 当前压缩记录的差分页基底 | 上一次已记录的输入缓存 |

混淆二者会导致记录读错历史。新检查拒绝跨 rank、跨配置、跳过调用、错误基底、缺页、页重排和错误物理行映射。元数据检查成功时仍明确标记真实字节验证待完成，不能直接升级成“原始数据通过”。

独立还原器仅使用标准库，不导入写入端或其解压实现。它按两分片、三配置、各 14 次调用／32 帧的完整顺序还原 168 条 K/V 记录，对应 **726,663,168 字节**的完整缓存。每条包含 4 个槽位和全部 4224 个位置，空闲区与填充区也被整缓存哈希覆盖；三个已有预测位置观测点逐项核对。实际缓存可能因分片而不同，两个 rank 都必须保存，不能当作两次独立性能试验。

文件读取接口校验路径、文件身份、所有者、大小和完整哈希，拒绝符号链接、硬链接、截断、增长及读取中途失去外部许可。真实读取必须由另外准入的串行审计调用；当前接口本身不提供运行准入或启动模型。

## 测试结果和期间发现的问题

最终 28 项测试覆盖完整 84 次调用的元数据流程、168 条合成缓存记录、原数值检查保留、错误历史、损坏压缩数据和文件读取失败。初版 17 项以及中间版 27 项是测试迭代，不能与最终 28 项相加。

复核中有一次测试失败：同大小文件被立即改写后，文件时间字段未必变化，读取器实际用完整哈希正确拒绝了内容，但测试只接受“文件身份变化”的报错。修正的是测试对报错来源的假设，并新增“元数据相同但完整哈希不同”的专门检查；读取器的文件身份和哈希门槛均未放宽。失败源文件和实际退出证据已保存。

这些测试尚未证明真实观测无干扰或压缩后的真实数据可装下。原每 rank 128 MiB、合计 256 MiB、单文件 16 MiB、最多 512 个文件限制仍保留。此前原 CPU 对照 29／32 数值通过、top1 32／32，两个候选 28／32、top1 31／32，继续不合格；本轮没有把失败对照用作提速分母，也没有据此认定上游缓存 bug。

## 下一步与运行边界

完成后继采集运行器、两路进程接入及清理路径；在证明进程组完全退出前保持串行所有权。当前 Nemotron r11 尚未结束，必须等其真实终止与释放证据产生后，绑定完整队列历史，才能为 MiniCPM5 生成实际运行规格。

随后运行完整原轨迹，检查导出前后全部 logits、213 个观测点、84 个输入及返回缓存、七个输入和全部位置／掩码路线。再串行读取真实输出，由独立还原器核对完整缓存，并保留原完整 logits／HF 数值复核。只有相同当前输入加自身历史能复现第二层 decode 注意力输出，才进入配对历史的因果实验。prefill 记录仍只有预测位置，不能当作完整 prefill 中间张量。

Nemotron 此次 15 阶段的服务实际退出码、保留的调用身份、原进程消失和进程组清空均已核对；控制器仍持原串行锁。后续切分、真正模型服务启动、冷缓存至 4096、长解码、请求槽位复用、生成／质量、真实 HTTP 四并发、配对性能及最终原始数据复核仍待完成。
