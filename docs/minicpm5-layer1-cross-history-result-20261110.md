# MiniCPM5：缓存历史交叉对照定位第二层差异来源

**144 次真实完整四行注意力调用完成，退出后的独立复核重新读取全部 2,359,296 字节并通过。** 仅在预填充阶段替换首层输出投影的候选，其第二层 decode 当前输入与原对照相同；交换历史 K/V 就能复现第二层注意力的差异。两个阶段均替换的候选，同时受当前输入和历史缓存影响。

这是原 SDK 在 CPU 上的局部正确性诊断，使用官方 BF16 权重及原注意力计算。没有执行 Neuron 性能测量，也没有新增合格提速。整模型数值结果仍是原对照 29/32、两个候选各 28/32；首选 token 分别是 32/32、31/32、31/32。两个候选继续拒绝采用。

## 做了什么

延续[已成功的自身历史重放](minicpm5-layer1-own-history-result-20261110.md)，把原对照、仅预填充替换首层投影、预填充和解码均替换首层投影三组轨迹组成交叉矩阵。第二层在代码中编号为 layer 1。

每个 rank、每个原 decode 调用，分别固定三种当前归一化输入，配上三种完整历史缓存。K 与 V 始终来自同一个候选、同一个 rank 和同一次原调用。保持原 mask、位置、请求槽位、分桶及缓存物理布局。

| 覆盖内容 | 实际结果 |
| --- | --- |
| 交叉矩阵 | 2 ranks × 6 次 decode × 3 输入来源 × 3 历史来源 = 108 次 |
| 恢复对照 | 每组交换后恢复自身历史，共 36 次 |
| 原历史对照 | 矩阵内 36 次对角调用先执行，再交换历史，最后恢复；全部精确复现原字节 |
| 恢复对照结果 | 36/36 精确复现原字节，未发现调用间缓存污染 |
| 完整输出 | 144 × 4 行，共 2,359,296 字节；全部有限，两 rank 的输出副本相同 |
| 去除 rank 副本 | 54 个唯一矩阵单元、18 个唯一恢复对照，总计 288 行；每个候选的解读使用 24 个唯一 decode 帧 |
| 模型 | 每 rank 构造一次原 42 层 decode 模型，仅调用第二层注意力；核验 Q/K/V/O 官方 BF16 分片 |
| 实际退出 | 模型会话 87981 退出 0；两个 rank 均退出 0；独立复核会话 40637 退出 0 |

运行前核验全部既有服务历史，并额外检查前次自身历史重放和独立审计的五个原进程已退出。运行中保留串行锁、16 GiB 内存上限、禁止 swap、CPU 6–7、根盘 28 GiB 和 NVMe 30 GiB 空间下限。未扩容 EBS，也未删除模型数据。

## 观察到什么

以下比较均以“原对照当前输入 + 原对照缓存”的第二层注意力输出为参照。相对 L2 是输出差值的 L2 范数除以参照输出的 L2 范数，表内是 24 帧的算术平均；它是局部变化幅度，不是整模型误差率或质量通过率。

| 首层投影候选 | 只换历史缓存：变化帧／平均相对 L2 | 只换当前输入：变化帧／平均相对 L2 | 两者同时替换：变化帧／平均相对 L2 |
| --- | --- | --- | --- |
| 仅预填充替换 | 24/24；0.8046% | 0/24；0% | 24/24；0.8046% |
| 预填充和解码均替换 | 24/24；1.0371% | 24/24；1.1670% | 24/24；1.3042% |

仅预填充候选的归一化当前输入，在全部 12 次物理 rank 调用中都与原对照哈希一致；完整 K 和 V 缓存则全部不同。因此这一组的“只换当前输入”实际上是相同字节输入，零变化有直接的数据解释。结合真实缓存交换，支持以下有限结论：**在本次 24 个 decode 帧的第二层注意力边界，该候选的差异经历史缓存传入。**

两个阶段均替换的候选，12 次物理 rank 调用的当前输入、K、V 哈希全部不同。单独交换当前输入或缓存都会改变 24/24 帧的输出；历史影响大于当前输入影响的帧为 7/24。两者合并后的变化并非简单相加，不能把平均相对 L2 当作可加的误差贡献率。

这些实验没有运行替换缓存后的完整模型后续层，因而不能声称已经找到了所有最终 logits 失败的根因，也不能据此把原对照缓存当作候选的可部署修复。原对照自身尚有 3/32 数值帧未通过，仍需对齐官方参考。

## 实现与验证中发现的问题

新增了独立的交叉历史调用、执行器和结果验证规则，未修改已执行并冻结的自身历史源码。注意力调用表达式与已成功的自身历史重放通过语法树检查保持一致。新规则明确分别校验当前输入和缓存来源：对角及恢复调用必须精确相等，交叉调用允许变化，但必须保存完整有限输出。

13 项针对性检查通过，覆盖错误槽位／位置／mask、错缓存来源、缺失恢复对照、错输出路径、非有限输出、权重精度变化、缺失实际退出，以及把局部结果提升为整模型合格或提速的错误声明。准备时首次生成新函数的脚本替换范围过宽，测试在初始化阶段报未定义变量；修正生成范围后 13 项全部通过，首次失败日志保留。真实模型实验只启动一次且成功。

运行日志仍出现 SDK 配置项提示和 `torch.cuda.amp.autocast` 弃用告警；本次实验在 CPU 上完成。这些告警不是本轮失败，也不能单凭其名称判断使用了 CUDA 设备。此前严格 FP64／FP32 指标标量审计的 75 项余弦超容差继续保留，本轮未修改容差或重新标记其为通过。

独立复核在全部模型进程退出后重新获得串行锁，读取所有完整 BF16 输出，核对来源、布局、对角／恢复精确性、有限性和 rank 副本一致性；描述性距离用标准库 FP64 运算生成，未导入 Torch、NumPy 或模型运行库。

## 下一步

优先核对第二层预填充缓存与官方参考的偏差，并区分 K 和 V 的作用。这需要新的明确干预规则；本轮规则仍只允许成对交换同一来源的 K/V。后续候选必须回到原完整 32 帧数值门槛，再执行冷缓存、长解码、槽位复用、质量和配对真实 HTTP 性能检查，才能计入优化配置或提速表。

全部 15 个模型家族继续保留。Nemotron r11 的存储下限失败、Nano 原生基线和 Dory 七个 FP32 长轨迹失败均未因此解决。
