# DeepSeek 捕获图：空间需求与 SDK 编译重试目录

本次追踪本机固定 Neuron SDK 的编译、加载和缓存源码，为 DeepSeek-R1-0528-Qwen3-8B 原 BF16、TP2/B4/context4096 对照建立完整空间预算。没有实际编译或修改 SDK。作者与主任务独立复核各 **8 项源码模拟控制通过**，17 份所引用源码的哈希和文件身份已核对。

原配置 `save_sharded_checkpoint=False`。编译调用 `trace(initialize_model_weights=False)`，随后跳过保存分片的分支；加载调用 `shard_checkpoint()`，不传保存目录。所审 Python 路径因此不会写出 `tp{rank}_sharded_checkpoint.safetensors`。历史两份 TP 文件合计约 15.26 GiB，不能直接计为本次新生成的磁盘副本。加载仍会读取原 checkpoint、构造两个 rank 的张量，并进入原生内存与设备布局转换；这项源码结论不证明总峰值，也不证明共享内存或其他临时文件为零。

编译资源必须分别计入：

| 位置 | 已确认的写入 |
|---|---|
| 模型产物目录 | 序列化模型、配置和构建报告 |
| 各桶编译目录 | HLO、NEFF、配置、日志、元数据及编译临时产物 |
| 持久编译缓存 | HLO、NEFF、编译参数、状态标记及原子写入的临时副本 |
| Python 临时目录 | HLO、返回用 NEFF，以及可选布局优化的临时数据 |
| 内存与共享内存 | checkpoint、分片、布局转换及设备加载的实际峰值仍待测量 |

缓存使用文件复制，不能把不同目录中的相同内容只计费一次。捕获入口认证的 39 份图文件也不是完整空间清单。两个完整对照的原始输出预算仍为 **47,150,344,192 字节**；没有据此下调预算或认定当前磁盘足够。

源码模拟还确认一个有条件的 SDK 问题：`libneuronxla/neuron_cc_wrapper.py` 的 `compile_cache_entry` 重试递归没有传递 `work_dir`。启用重试后，专用桶目录会变成 `/tmp/<USER>/neuroncc_compile_workdir`。当 `create_subdir=False` 且回退目录已经存在时，原函数还会删除该目录再创建。这里的目录与删除操作全部使用内存模拟，没有发生真实目录回退或删除。

适用条件必须保留：ModelBuilder 使用 LAZY 模式；默认重试次数为 0，此时第一次编译异常直接抛出，不进入递归。配置允许重试后，异常路径才会触发上述问题。EAGER 客户端直接返回非零值的分支另有重试次数检查差异，本次未运行真实 EAGER 客户端。仅设置 `TMPDIR` 无法改变源码硬编码的回退路径。

后续运行需要认证实际模式和重试配置，并把所有可达临时目录纳入保护和计费。本次没有证明当前模型曾因这个问题失败，也没有产生模型提速结论。完整原生与设备对照、原权重和分片布局验证、长解码、槽位复用、quality96 与匹配 HTTP 均保留。
