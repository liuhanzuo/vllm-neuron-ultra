# Qwen 缓存写入首次设备测试：原实现的特殊 BF16 值检查失败

缓存槽位合并写入候选已在 trn1 上开始实际设备测试。卷积历史布局的原实现和 NKI 候选都编译成功，但**原实现第一次正确性调用就未通过完整字节比较**，整轮按原规则停止。候选还没有执行正确性调用，计时也没有开始，不能据此判断候选内核错误或计算提速倍数。

[Qwen 独立包原生预检通过](qwen-package-preflight-passed-20261112.md)的结论保持；它与这项设备原语实验属于不同验证范围。现有研究路径的[模型提速表](model-speedups-20261112.md)不变。

## 实际执行到哪里

准备过程保留全部 150 条历史记录、48,211 项来源绑定和 1,031 项补充输入。薄准备代码修正了“把当前增量源码行当成完整映射”的错误，旧版本保留；9 项独立检查和完整历史预核通过后，原 serial v3 在 session `23987` 启动，最终 terminal `57d44c`、退出 1。

全空闲槽位应原样保留旧缓存。失败日志明确来自 `standalone/reference/correctness`。后七种布局、持久状态别名模式及候选运行均未执行。两张图的编译耗时不是推理性能。

## 特殊值线索与验证边界

原始 `raw` 输入包含有意保留的负零和不同 NaN 位模式。这一检查用于判断缓存搬运是否真的逐字节保留数据，不能因失败而删除这些输入或改成近似数值比较。

源码重建发现，报告中首 16 个不同字节都落在负零符号位或 NaN 的 payload。将完整预期 BF16 输入中的负零 `0x8000` 改为正零 `0x0000`、所有 NaN 改为 `0x7fc0`，其完整输出摘要与实际报告一致。原输入没有负 NaN，因此还不能判断 NaN 符号是否保留。

这给出了具体的值规范化线索，但不能定位到输入传输、原实现的编译图或输出转换中的哪一层。当前报告只保存了完整摘要及首 16 个差异位置，没有保存实际完整输出字节。后继诊断会分别运行已编译的原实现、候选及真正经过设备的搬运对照，并保存完整原始字节和差异；该诊断不替代原八布局资格测试。

## 保留的门槛与后续

原八种布局、32 张图、46,368 次调用，以及全部 625 种 B4 槽位映射的正确性要求保持。没有降低原始字节比较标准，没有把失败改为通过，也没有扩大存储或内存限制。完整模型数值、冷缓存、长解码、槽位复用、quality96 和匹配 HTTP 验收仍然必要。

本次真实执行已越过之前修复的 SDK 导入和两次 trace 环境恢复路径；这只证明已执行路径的检查通过。主任务的首次退出审计还有一处记录格式错误：把含 `observation` 的三字段握手封套当成了两字段封套，导致审计在物理核验前停止。后继审计保留原始记录并正确检查引用和值，完成了实际退出、清理和产物哈希核验。此问题与设备输出差异无关。
