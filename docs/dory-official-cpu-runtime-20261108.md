隔离环境位于 NVMe，运行依赖解析后的 139 个待装包均保存下载地址和 SHA-256，并按锁定文件安装；`pip check` 通过。原 Neuron SDK 和既有参考虚拟环境没有被覆盖。系统增加 G++ 12 开发组件和 TCMalloc，实际新增约 59 MB；没有扩容 EBS。

本地 wheel 的元数据版本是 `0.1.dev1+g75fc05a53.cpu`，这是浅克隆下生成的版本标签，不能把它解释成历史 vLLM 0.1 发布版。复现应使用完整 Git 提交、依赖锁与 wheel 哈希。构建实际耗时约 2,082 秒，退出码为 0；这是构建耗时，不是模型性能。

这台 Xeon Platinum 8375C 实测支持 AVX-512，没有 AMX，也没有 AVX-512 BF16 指令支持。官方运行环境选择 `CpuPlatform`，oneDNN 可用，FP32 matmul 设置为 `highest`。预加载 Intel OpenMP 和 TCMalloc。后续双循环实验在每种精度下实际观察到 903 次 `onednn_mm` 调用，确认了实际投影后端；`custom_ops=["none"]` 并不意味着线性层使用 `F.linear`。

官方测试保持源码原样，在隔离目录执行两个官方测试文件，避免加载仓库其他测试的全局配置。结果为 **43 passed、0 failed、0 errors、0 skipped**。它们保留真实 vLLM 线性层、embedding、权重加载及加载后处理，但注意力使用上游测试自己的 `ReferenceAttention`，不是生产分页注意力或完整服务调度器。

额外双循环对照使用合成小模型：8 个物理层、hidden size 16、Q/KV 头数 2/1、head dim 8、两次循环、6 份独立历史、词表 32。每种精度先输入 6 个 token，再逐 token 解码 27 次，共 33 个 token、28 次调用；滑动窗口为 3。FP32 是诊断控制，BF16 是与原模型精度一致的小规模测试；这仍不是原模型的 72 层、56 份历史或原始投影尺寸。

小型 QKV、gate/up 投影在 batch 1 和 6 的 8 组条件下，官方 oneDNN、合并 `F.linear` 和分开 `F.linear` 的三组比较都精确一致。这个结论只覆盖保存的合成输入与尺寸。完整双循环中，FP32 首次预填充准确相同，27 次解码出现差异；**预先要求的精确一致性仍记为失败，没有放宽阈值**。

两种精度都实际检查了参考槽位重新开始：清空官方 fixture 的缓存，释放并重新创建候选请求，得到与第一次预填充相同的输出；候选拒绝旧 epoch 的句柄。这是小型参考状态检查，生产调度器的完整请求槽位复用验收仍待执行。

为定位 FP32 差异，使用保存的合成权重和 6-token 历史，独立重放首次解码位置 6、token 13 的第 0 层注意力。Q、K、V、SDPA 输出及归一化后的输出投影输入完全一致。相同输入与原矩阵下，oneDNN 和 `F.linear` 的 16 个输出元素中有 10 个不同，最大绝对差 **1.4901161e-8**。重新调用 oneDNN 精确复现官方输出，使用同一输入调用 `F.linear` 精确复现候选输出；新算出的第 0 层 KV 也准确复现先前保存状态。

因此已确认这一处局部差异来自投影计算路径。它不是模型权重变化或缓存串用的证据，也不能据此宣称所有最终 FP32 logits 差异已经被解释。原始 BF16 权重在实际尺寸上的后端一致性仍需验证。

退出后的独立程序仅使用 Python 标准库，读取受限 ZIP/pickle 张量元数据和保存字节，不导入 Torch/NumPy、不重跑模型或矩阵乘法。66 个归档中 **808 项比较字典全部精确重现**，同时确认 BF16 一致与 FP32 失败。局部投影重放的 **12 项比较和原矩阵字节**也独立复核通过。槽位重用的第二次输出没有单独保存，因此这部分只有实际运行中的检查，没有宣称独立保存字节复核。
