## LFM3 具体完成了什么

目标软件栈为 Python 3.12、vLLM 0.16、vLLM-Neuron 0.5.3、NxDI 0.10 和 NKI 0.5。固定原始 `LiquidAI/LFM3-1.7B` 权重版本，保留 BF16、TP2、数学核心与 tokenizer；候选范围是 B4/B8/B16、上下文 2048/4096。

| 改动 | 目的与验证边界 |
|---|---|
| 显式启用的模型注册 | 接入新版 vLLM、Transformers 与 NxDI；检测已有注册冲突。 |
| 独立编译产物身份 | 绑定模型、配置、源码和软件栈；在通用自动删除／重编译路径之前拒绝不完整或不匹配的产物。 |
| Typed NKI writer 接线 | 多行更新使用候选 writer，单行保留原操作；实际设备数值及 MUST_ALIAS 验证仍待运行。 |
| 新 runner 的 CPU sampler 接线 | 保留 execute、延迟采样、请求顺序恢复及 grammar mask 的顺序；保留显式随机生成器等回退行为。 |
| 请求生命周期检查 | 在修改槽位之前检查请求、位置和容量，拒绝未实现的抢占恢复、prefix cache、chunked prefill 等模式。 |
| 真实状态与调度预算分离 | 调度器使用含 null block 的 B+1 个代理块；设备模型仍有 B 个请求槽位、TP2 合计 70 个混合状态。代理预算不当作实际 HBM 占用。 |

主任务独立执行的 25 项标准库/mock 测试全部通过，另独立重放了 7 步完整 runner 生命周期模拟，覆盖 prefill、decode、暂未调度的请求、请求乱序、结束后同 ID 新请求、不同 prompt 长度和最终释放。模拟使用真实 runner 的状态更新与槽位方法，张量计算及采样输出仍为 mock。

29 份交付文件和 16 份原始来源均已核对。数学核心、helper、CPU sampler、tokenizer fixtures 及 typed wrapper/selector/dispatch 保持原字节；模型适配器的 AST 相同；typed JIT 只调整包内导入。原数值标准、冷缓存、1529 步长解码、槽位复用、quality96 和配对 HTTP 门槛完整保留。

截至 05:49 UTC，已有完整 CPU r2 仍是唯一活动串行实验：原环境与新环境各 3,716 例及控制组已完成核验，候选回归 123 批／1,648 例已独立通过；扩展阶段写出 101 批／1,298 例，目标 168 批／2,068 例。扩展阶段尚未结束，874 个子进程的完整终态验收仍待完成。后续设备矩阵保留 105 个任务、127 图、4,304 项检查，其中包含 LFM 自身两个 KV 头的 4096 形状。

## MiniCPM5 已明确的环境缺口

实际 SDK 使用 Python 3.10。已独立核对三份 APT 明文索引与既有签名 Release 记录、八个精确包地址；没有把 Python 3.12 的验证当作 Python 3.10 的验证。

首先缺少 Python 3.10 可执行文件、stdlib／动态 `_ctypes`、libffi 的完整归档及成员核验。三个必需包共 4,150,014 字节；另五个候选依赖共 2,960,850 字节。八包合计 7,110,864 字节，准备核验 12 个成员。候选依赖是否被实际加载仍未知，整个集合也尚未构成完整依赖闭包。

现有 Dory 下载与 tar 核验实现可以复用，但旧输入绑定固定六包，旧 recorder 最多收 32 条事件；八包下载需要 41 条、重放需要 33 条，直接运行旧脚本会失败。已完成六份后继源码，保持旧 82 份来源摘要，共绑定 88 份源码。主任务独立运行 24 项标准库/mock 检查通过；实际文本认证也独立通过，核对八包、12 个目标及 14 处索引条目。运行器和 worker 只改变接线，保留原下载、tar、串行锁、启动确认及排空实现。实际下载与归档重放仍待新鲜串行运行绑定。

归档准备是独立串行步骤，使用原 inventory 的 128 MiB 总输出预算；原 Mini 科学诊断的 9 项原生检查、1,284 行、900 秒、AS 2 GiB 和单文件 2 MiB 限额保持不变。

本轮没有安装依赖、下载归档或启动新实验。已有同路径系统库的来源记录可以复用，但仍需当前内容及实际加载关系核验；此前动态库映射失败的根因尚未确定。

## 接下来

等待现有 LFM CPU r2 真正退出，核对完整结果和进程释放，再按串行队列推进实际验证。Mini 的八包核验源码现已通过独立复核。Qwen r6 的 API 启动失败仍保留为待诊断问题，已修复的 Sampler 导入问题不能直接当作它的根因。

LFM 设备阶段仍需满足 30 GiB 保留空间加 24 GiB 输出预算。目前 NVMe 约有 43.1 GiB 可用，已退休数据的条件候选约 4.84 GiB，即使全部能回收也不足。`neuron-work` 和编译缓存中发现后续恢复及数值比较依赖，未删除；活动 swap、模型和待比较数据也保留。按用户不扩盘的要求，先推进输出较小的 Mini/Qwen 工作，同时保持 LFM 原预算和全部检查。没有为了启动实验降低保留线。
