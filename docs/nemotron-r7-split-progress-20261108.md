源码里的改动是将长度列表换成明确的累计边界。两种表达的预期数学含义相同，输出形状也相同：

```python
# 原写法，指定三段长度
parts = projected.split([5120, 6144, 64], dim=-1)
# 候选写法，指定两处分界位置；5120 + 6144 = 11264
parts = torch.tensor_split(projected, (5120, 11264), dim=-1)
```

一个具体例子：输入 `[1,128,11328]` 的第一段输出在坐标 `[0,1,0]`，应该读取输入的平坦元素索引 `11328`。原写法生成的 HLO 计算图却映射到 `5120`，仍落在第一行中。第二行另外两个被抽样的通道同样映射错误。这把问题缩小到当前编译路径的拆分及后续布局映射；只比较形状、编译是否成功或 CPU 结果都不足以验收。
