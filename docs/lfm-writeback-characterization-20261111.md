# LFM3：BF16 模拟器写回问题的完整对照结果

2026-11-11，LFM3 的 NKI 0.5.3 数据搬运诊断完成。候选通过 **32/32 项检查**，覆盖 **65,536 种 BF16 编码**；恢复原实现后，原输入被改动的问题再次出现。本轮没有新增整模型合格结果或推理提速倍数。

| 对照组 | 实际结果 | 解释 |
|---|---|---|
| 原实现 | 恒等操作返回的 4,096 字节完全正确，但输入中的 27 个 BF16 字、共 81 位被改动 | 变化全部发生于 NaN 的位模式；返回值正确不能代替输入不变检查 |
| 精确 BF16 写回候选 | 全部 32 项通过，输入保持不变；完成 132 次提取，其中 40 次使用精确 BF16 写回 | 支持该模拟器写回路径对本组失败的解释 |
| 恢复原实现 | 与第一组相同的首例失败再次出现 | 对照可复现，实验结束后原函数已恢复 |

原路径把 BF16 输入通过 FP32 提取后写回，可能改变 NaN 的 payload 位。候选仅在已确认的 BF16 输入写回位置使用精确提取。对每个替换点保留默认提取和精确提取的完整差异记录；没有修改已安装 SDK 文件。

测试包含恒等、复制、置换、槽位选择，以及 B4/B8/B16 的 inactive、重复槽位最后写入者等情况；保留 FP32 搬运、算术和 round-to-nearest-even 转换对照，以及错误 dtype、shape、槽位、复制方向和位模式等负控。此前诊断的 Python 运算符兼容错误通过显式 `nl.equal`、`nl.subtract` 修正，测试范围没有缩减。

工作进程与外层工具实际退出码均为 **1**。这是运行器在完成对照后主动保留原实现失败的约定，并非把候选 32 项判为失败。独立终态记录同时核对候选结果、原失败、恢复对照、真实进程退出和服务排空；不能只看顶层退出码或单个 `complete` 字段。

这个结果仅适用于当前 NKI 模拟器的主机输入写回。它没有证明真实 Trainium 芯片存在同样问题，也没有补过旧 3,716 项检查或模型完整门槛。原权重/BF16、cold4096、长解码、槽位复用、quality96 和相同 HTTP 工作负载仍是模型优化的必要条件。

MiniCPM5 的已审计记录仍保留：48 组 BF16 注意力概率全部相同，47 组有效 V 相同，而合并 context 全部不同。下一项固定输入 P×V 诊断设计先复现两环境的原输出，再分别检查分块、布局、padding 与显式舍入；目前只有设计，没有新算术结果或因果结论。
