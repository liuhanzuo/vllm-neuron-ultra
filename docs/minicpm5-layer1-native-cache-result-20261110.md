# MiniCPM5：官方第二层缓存已采集，局部误差缩小没有带来整模型改善

**官方原生 32 次前向采集、退出后独立复核及 288 组缓存比较均已完成。两个候选的第二层缓存整体更接近官方参考，但原整模型数值通过率仍从 29/32 降到 28/32，继续拒绝采用。** 本轮没有新增模型资格或提速倍数。

这是 [K/V 分别交换实验](minicpm5-layer1-kv-factorial-result-20261110.md)的后续。此前只能比较本地 CPU 适配实现的三种历史；本轮补齐了同一批输入的官方完整第二层 K/V，得以直接比较数值差异。这里的“第二层”是索引 1；整个模型仍为原完整 42 层。

## 官方采集与独立复核

沿用官方 revision `f97400052a43d642bbc6e9975e2397e3ae6a6b52`、全部 381 个 BF16 权重张量、原 Transformers eager 实现、B1 无填充输入、两个 CPU 线程及原 8 个 fixture。每个 fixture 执行一次预填充和三步原续写 token 的前向，共 32 次；最长有效序列为 1,234。采集在前向之后读取缓存，没有额外模型前向、缓存更新或计算精度修改。

| 核验对象 | 完成结果 |
| --- | --- |
| 完整第二层 K/V | 32 帧、64 个张量、两个 KV head 的全部有效位置；5,894,144 字节 |
| 完整 logits | 32 × 130,560 个 FP32 数值；16,711,680 字节，全部与旧官方参考逐字节一致 |
| 选定中间输出 | 每帧 213 处，共 6,816 份；36,143,104 字节，全部与旧参考哈希一致 |
| 原生历史延续 | 8 个 fixture 各 3 次缓存扩展；两个 head 的 K/V 旧前缀全部逐字节保留 |
| 退出后复核 | 模型进程全部退出后，独立标准库程序重新读取全部 58,748,928 字节，验证通过 |
| 实际退出 | 采集会话 91116、独立复核 1797、缓存比较 20068 均退出 0；进程组清空，串行锁可重新取得 |

213 处是选定的中间输出位置，包含各层子模块及输出头，并非 213 层。预填充时这些选定输出覆盖预测位置；完整 K/V 则覆盖全部有效历史。原 4,096 冷缓存、长解码及请求槽位复用验收仍是另外的完整门槛，不能用这 32 帧替代。

## 如何与 CPU 适配实现对齐

针对原 24 个 decode 帧，将 SDK 本次调用使用的缓存匹配到同一个 fixture 的**上一步官方前向输出缓存**。官方 head 0/1 分别对应 TP2 rank 0/1，fixture 保留原物理请求槽位。每个 rank 仍完整重建 `[4, 1, 4224, 128]` 的 SDK K/V 存储并核对旧哈希，距离只计算该请求当时有效的历史位置。

三种路径 × 24 帧 × 两个 head × K/V，共 288 组比较。两个 head 存储不同内容，均保留，没有把它们当成重复副本删除。全部 84 次原调用的缓存链重新验证后，再提取其中 36 次 rank/路径/decode 调用的历史。

**本轮比较的是 CPU 上的 SDK 参考适配实现与官方 CPU 实现。没有采集新的 Neuron 设备缓存，不能直接归因到 Trn1 芯片。** 没有进行注意力重算或官方缓存替换干预。

## 缓存误差的实际变化

下表为全部有效历史的汇总相对 L2：`sqrt(所有差值平方和 / 所有官方值平方和)`。每格汇总 24 帧 × 两个 head；较长历史权重更大，同一提示词前缀会出现在连续多个缓存快照中。它不是独立样本成功率、质量损失百分比或提速。

| 路径 | K 相对 L2 | V 相对 L2 | K 最大绝对差 |
| --- | ---: | ---: | ---: |
| 原严格对照 | 0.3208% | 0.4630% | 0.125 |
| 仅预填充替换首层输出投影 | 0.2548% | 0.3584% | 0.0625 |
| 预填充与解码均替换首层输出投影 | 0.2548% | 0.3584% | 0.0625 |

三种路径的 K 和 V 都没有逐字节完全相同的 head/帧对：每项均为 0/48。候选减小了汇总误差，仍未消除差异。

分开查看提示词历史与续写新增部分，可以看到两种效果：

| 历史部分 | 原对照 K / V | 仅预填充候选 K / V | 两阶段候选 K / V |
| --- | ---: | ---: | ---: |
| 提示词位置 | 0.3208% / 0.4632% | 0.2543% / 0.3575% | 0.2543% / 0.3575% |
| 续写新增位置 | 0.3259% / 0.4478% | 0.3259% / 0.4478% | 0.3321% / 0.4523% |

第一步 decode 的输入历史尚无续写新增位置，因此第二行汇总的是后两步的 32 个 head/帧对。仅预填充替换的改善集中在提示词历史；两阶段替换没有进一步降低汇总误差，其续写新增部分的 K/V 误差略有增大。

上一轮显示“更换 K 对局部注意力输出的影响大于更换 V”；这一轮显示“相对于官方缓存，K 的归一化差异小于 V”。两者衡量的对象不同：**输出敏感度与缓存数值误差不能互相替代**，也不能据此给 K/V 分摊整模型错误贡献。

原整模型对照仍为数值 29/32、首选 token 32/32；两个候选均为数值 28/32、首选 token 31/32。本轮未重新运行整模型候选，因此这些是既有结果。下一项有意义的因果验证是固定当前注意力输入，分别使用官方 K、官方 V 和官方 K/V 做完整输出对照，并保留原历史恢复控制，以检验这些缓存差异是否能解释输出偏差。

## 检查与证据

采集和完整原始数据校验的 15 项针对性检查通过；另有 6 项标准库对齐和距离检查通过，覆盖错 fixture/步骤/槽位、错误 head 形状、不完整存储、非有限数据、BF16 解码、官方范数分母及空续写区间。即使重算文件哈希，改变旧历史、选定输出或 logits 的数据也会被拒绝。独立复核和比较均不导入 Torch、NumPy 或 Neuron 运行库；比较汇总的数量和平方范数还在程序实际退出后重新核算。

完整采集采用 16 GiB、禁止 swap、CPU 6–7；标准库比较限制为 2 GiB 地址空间和 CPU 6。原存储下限为根盘 28 GiB、NVMe 30 GiB。本轮未扩容、未删除模型数据；此前 75 项 FP64/FP32 余弦标量超容差失败没有改判，全部 15 个模型家族及原质量、冷缓存、长解码、槽位复用和真实 HTTP 配对性能门槛继续保留。
