# Nemotron 9B 启动修复接入与 r11 复验

本轮将已审查的分段启动期限和完整写入就绪标记接入 v26 控制器、worker、生命周期校验和运行配置。**81 项适用检查通过，实际配置准备与完整协议检查均退出 0。r11 已通过实际准入，控制器持有串行锁并启动第一阶段 prepare；整模型验证仍在进行，当前没有新增整模型合格或提速结论。**

此前未跟踪诊断测得，原完整启动前校验单独耗时 66.144 秒，已超过旧流程共用的 60 秒。新流程分别给予准备校验 300 秒、执行切换 60 秒、独立确认 60 秒；保留原校验内容和进程身份约束。执行意图文件写完并同步后，子进程才发布独立的 0700 就绪目录。父进程等待该标记，避免读取半写入的 JSON；生命周期证据也必须包含准备记录。

这次接入保留原 52 个阶段、模型 revision、BF16、参考数据、资源上限和完整验收要求。冷缓存至 4096、长解码、槽位复用、生成／随机性／停止／文本／质量、真实 HTTP 四并发和配对性能均须继续通过。12 个执行模块及 worker 的科学计算函数，经版本导入名归一化后与 v24 的语法树一致。

## 验证和运行边界

81 项适用检查由 15 项源码／存储、14 项生成器／历史记录、30 项启动集成、16 项服务生命周期以及 6 项真实大元数据记录检查组成。生命周期测试使用模拟的系统／HTTP 观测；元数据检查读取了原记录，但未执行模型。它们不是 81 次模型实验。命名修正后重跑的 29 项属于这 81 项中的受影响子集，不重复计数。

实际准备核验了 43,067 个文本文件、3 个非 UTF-8 源文件、9 个查询依赖二进制、20 个历史数据哈希引用、16 个模型／参考文件身份和 1,337 个运行库文件身份。完整规格共有 43,099 个源哈希条目。历史链保留 1,202 个服务和 399 个已记录进程身份，启动器和控制器均在准入前完成旧进程／进程组检查；实际准入记录已生成。

准备时根盘可用 30,472,482,816 字节，NVMe 可用 57,561,714,688 字节；完整 19 GiB 新输出预留通过。运行过程中继续执行相同的容量限制。

实际观测时间：2026-11-10T05:52:18.859314+00:00。控制器 PID 387618 的启动身份及串行锁已独立核对，第一阶段 prepare 的 PID 为 391707。外部运行会话为 74703，仍在运行；不得重复提交此运行。成功准入仅表示允许执行，52 个阶段及最终独立原始数据复核尚未完成。

## 保留的模型结论

Nemotron v24 的 16 组切分候选共 96／96 次设备输出比较逐位一致；原方式仅两个单行正对照通过，14 个跨行形状失败。旧整模型运行因启动期限失败，局部算子成功不能替代整模型合格，失败原方式不能作为提速分母。

MiniCPM5 的原锚点仍为 29／32 数值通过、top1 32／32；两个候选均为 28／32、top1 31／32，仍拒绝。现有缓存元数据不足以证明因果，下一步保留完整 14 次调用／32 帧轨迹，先验证新增数值观测不改变输出，再进行相同当前输入下的历史状态对照。Dory 的七个 FP32 长序列失败和 Nano 的真实 SDK／模型准入待办继续保留。
