# MiniCPM5 算子比较准备与 Qwen3.5 采样审阅补充

本次补齐 MiniCPM5 保存数据比较工具和后续准备工具，并复查 Qwen3.5-2B 的采样采集布局、启动路径及对照数量。MiniCPM5 原生 r3 仍在执行；下述检查使用源码、元数据和小型合成输入，没有新增完整模型合格结果或推理提速。

## MiniCPM5：定位已经保存的注意力边界差异

比较工具覆盖原有 24 帧、6 次四行调用和两个 rank，完整输入为 1,284 份 capture 文件、77,790,564 字节。每次读取一整次调用对应的 214 个张量，依次检查 Q/K/V 投影、旋转位置编码、QK 与缩放、有效历史和当前词元的 softmax 概率、PV 合并及归约后的输出投影。包含三组控制的原始数据仍由独立审计器完整核验，比较工具不能代替控制检查。

这里有三处容易误比：SDK 的行按请求的实际槽位对应，不能按记录列表次序对应；两个 rank 分别对应原生的前八个和后八个查询头；保存文件已经按逻辑形状紧密排列，原张量的 stride 与 offset 只用于身份验证，不能再次当成文件偏移。原生 BF16 与 SDK FP32 的 softmax 输入采用精确位扩展比较，保留正负零，不重做张量运算。

每帧报告 44 个完整比较域及 22 个 SDK 独有域的统计。误差计数和数值指标遍历整个域，最多八个例子只用于说明。SDK 的 prior/active PV 分量与归约前局部投影没有保存的原生一对一参考，因此只报告自身统计。最先出现差异的保存边界可以缩小排查范围，但不能单凭它认定算子根因。

主任务独立复跑的 9 项测试全部通过。合成数据共 368,380 字节，最大单张量 16,384 字节；没有读取真实实验张量。六份完整报告结构的元数据序列化最大 429,837 字节，低于原 2 MiB 上限；这不是实际结果的大小测量。真实比较仍需先完成原生真实退出、独立原始数据审计，以及 SDK 已完成结果的认证，再进入原串行队列。

后续准备工具 v7 也已通过 29 项独立检查：保留旧版本验证分支，新增对记录器 v3／审计器 v4 的真实退出和完整继承来源重建；全部旧队列记录继续保留。源码通过不等于已接受尚未产生的退出结果，本工具尚未执行新一轮实际准备。

## Qwen3.5-2B：布局与启动结论的适用范围

对当前采集来源的源码复查没有发现会生成非空、重叠 stride-zero 张量的预期路径。但现有重放解码器不支持一般的重叠展开布局，实际预检仍须同时验证单元素 stride-zero 的成功往返与非空重叠布局的明确拒绝。如果真实采集出现这种布局，应停止并准备后继解码器，不能静默改变保存布局。

普通单数据并行配置的初始化和预热不会进入挂钩的 CPU 采样操作；另外存在数据并行 dummy 路径，因此结论有配置前提。实机须核对实际启动参数和干净环境，单请求、四并发各完整采到原要求的 16 次调用，并且没有采集或请求上下文错误。零份已写文件只能证明没有写出，不能证明观察器内部计数为零。该审阅没有运行模型，也没有直接读取运行时配置对象或观察器计数。

数量勘误：原命名清单实际包含 **13 项采样拒绝／回退控制**。较早源码注释和交付文字中的“14 项”是计数错误；13 项原控制全部保留，冻结源码不改写。该数量与另行新增的布局预检数量不同。

Qwen3.5 的实际运行接口仍在修正和审阅中。最终比较继续保留原 BF16 权重、FP32 循环状态、TP2/B4/context4096、全部 203 份向量、冷缓存、1541 步长解码与槽位复用、质量96及原完整 HTTP 协议。此前 GDN 候选的文本变化仍判为不合格。
