# MiniCPM5 保存观测点重放：执行修复与验证边界

2026-11-10 UTC。本轮继续分析已保存的三组 MiniCPM5 中间结果，目标是解释第 0 层完整 BF16 投影的局部改善为何没有改善最终输出。此前两个候选的整模型退化结论仍保留：原 CPU 对照 29/32 帧通过、首选 token 32/32 一致；两个候选均为 28/32、31/32，尚无可采用的提速。

## 两个实验脚本问题及修复

Nemotron v24 已以失败状态完成资源释放，队列随后转入 MiniCPM5。首先，v2 准备程序拒绝生成配置：实际累积来源清单约 6.72 GB，超出原定 2 GiB 累计读取上限。后继 v3 允许最多 8 GiB 的累计来源读取；实际配置使用完整文件大小之和加 4 MiB，而不是直接放宽到无上限。原校验器每次只读取最多 1 MiB，2 GiB 地址空间、30 分钟时限、输出限制、磁盘余量、所有文件哈希与资源检查保持原值。v3 在两套 Python 环境共通过 66 次测试。

r1 随后实际启动，通过 43,016 个来源文件的校验，并完成 1,202 个历史服务、396 个历史进程的清空检查。它在创建准入记录后、读取原始观测点之前失败：调用方将整个引用字典作为一个位置参数传给需要 `path, sha256` 两个参数的 `read_observation`。实际外部退出码为 1，失败原文、进程身份、准入和来源校验结果完整保留。

v4 用命名参数传入原路径与原哈希，并在执行测试中启用真实函数签名约束，避免宽松的测试替身再次掩盖接口不匹配。新增检查直接读取并核验真实的查询依赖元数据，同时确认旧的一参数调用会被拒绝。35 项检查在两套 Python 环境均通过，共 70 次成功执行；其中大部分生命周期与数值报告测试仍使用明确标记的生成数据，不能代替真实重放。

重试使用新的 r2 输出目录。完整保留 r1 的失败和来源记录，将 r1 的实际进程身份加入历史清单；因此重试仍检查 1,202 个历史服务，进程身份增为 397 个。运行时重新校验全部来源并检查进程组。以上两项缺陷属于本地实验准备与调用代码，尚未形成上游模型或 Neuron 缺陷的证据。

## 本轮真实重放

r2 已完成全部原始数据读取、数值描述和最终查询清理，实际外部退出码为 0，已确认该进程消失且三个 canonical 状态文件不变。共核验 3,145,728 字节 BF16 数据、84 个数据包和 384 次比较；两个 rank 的内容逐字节一致，统计未重复计数。整个诊断约 330.68 秒，包含历史来源与服务检查，不是模型推理性能。

最有用的发现来自“只改预填充”的候选：

| 阶段 | 帧数 | 第 0 层注意力发生变化 | 第 0 层输出发生变化 | 第 41 层注意力发生变化 | 第 41 层输出发生变化 |
|---|---:|---:|---:|---:|---:|
| 预填充 | 8 | 8/8 | 8/8 | 8/8 | 8/8 |
| 解码 | 24 | 0/24 | 0/24 | 24/24 | 24/24 |

这里的“发生变化”只指与原 CPU 对照的向量不同，不代表通过或失败。预填充的层输出相对 L2 差异中位数，第 0 层约为 0.259%，第 41 层约为 4.501%；解码的这两个值分别为 0 和约 3.367%。因此，解码后段的差异不能仅用当前解码步的第 0 层输出变化解释。下一项应检查预填充之后的中间层激活和各层缓存状态，定位首次分歧；这些四点观测尚不能确认具体原因。

两种候选相互比较时，8 个预填充帧的四个观测点全部相同；24 个解码帧的四个点全部不同。额外替换解码投影并未消除原先的高优势首选 token 失败。帧 1 的原 KL 0.101269543 与候选 0.329327852、首选 token 1062→15182 保持原记录；帧 9 改善，而新增失败帧 16、17 仍保留。四点描述统计不改变此前 29/32→28/32 的拒绝结论。

分析范围是 84 份 BF16 数据包、32 帧、三组方案的两两比较以及四个观测点：第 0 层注意力、第 0 层输出、第 41 层注意力、第 41 层输出。完整比较为 32 × 3 × 4＝384 次。两个 rank 的重复数据必须逐字节一致，统计只计一次；原始输入哈希、物理行映射和原端点指标均保留。

这些统计描述方案之间的差异。CPU 对照本身仍有失败，因此差值不是相对合格 HF 参考的绝对误差。后层与前层差异的比值也不能单独证明因果放大；其余 209 个阶段没有数值观测点，原 FP32 指标和门槛不会被新的双精度描述统计替换。
