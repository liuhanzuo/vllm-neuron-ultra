# MiniCPM5 原生依赖清单与运行器检查修正

原生 r2 已完成 24 个检查点的局部采集，但最终源码校验失败，实际退出码为 1。本次修正让缺少依赖的问题在模型加载和采集之前暴露，同时减少反复处理静态配置的开销。修正版尚未进行新的模型实测，没有新增合格模型或推理提速倍数。

## 查到的问题及修正

原认证清单包含 44,665 项来源，但实际采用的可编辑 Transformers 包只列出 28 个 Python 文件。固定的包版本共有 3,151 个 Python 文件，缺少 3,123 个；包初始化时必定导入的依赖版本检查、版本表及 utils 文件也不在原清单中。错误日志没有记录第一个失败模块，因此不能声称已确定它的具体路径。

新版保留全部旧摘要，再单独收集所选 Transformers 包的完整 Python 清单，覆盖延迟与条件导入；没有把任意其他环境纳入模型依赖。准备过程仍保留独立的 2,048 文件调度依赖图上限，运行前仍逐份认证完整源码。

实际已加载模块现在接受三次关键检查：模型分配前、正式采集前、采集结束后。失败记录会提供模块名、路径及具体原因。原科学采集继续调用未改动的 v4 实现，保留 24 个检查点、每点三个对照分支、936 份原始张量，以及原权重和函数恢复要求。

## 减少实验运行器的重复工作

旧运行器每次检查进程、存储及输出时，都会重新序列化完整配置、计算摘要并构建同一份输出目录规则。新版在入口完整认证后保留不可修改的目录规则，并在原有每轮检查时点核对全部相关配置内容及容器身份；嵌套修改和内容相同但对象被替换都会失败。入口与成功退出边界仍执行原完整校验，实际进程、锁、存储、写入者、输出大小和时间限制的检查顺序及频率保留。

仅针对静态校验的合成微基准中，44,503 项模拟来源和 8,791 项输入、九轮交替测试的中位耗时从 92.02 ms 降至 39.51 ms，约 2.329×。该测试模拟了实际文件和进程检查，没有运行模型；它不代表每 token 延迟、整轮实验耗时或推理吞吐的改善，不能放入模型提速表。

## 验证及剩余边界

主任务独立复跑共 28 项检查通过：8 项包来源边界检查、16 项配置绑定及完整输出规则检查、4 项实际新驱动的纯模拟集成检查。后者确认检查失败会阻止模型加载或采集，成功时完整转交原科学实现的全部七个参数和返回值。完整的 936 份张量、144 份元数据、97 个目录模拟规则与原实现一致。

失败的 r2 不能事后改记为成功：执行前漏掉的依赖认证、最终投影权重摘要及恢复凭据均不能靠事后补清单重建。保存数据继续保留，成功审核和原生／Neuron 对照仍须等待新一轮真实运行及独立数据复核。

[源码、检查与取证清单](evidence/minicpm5-native-source-fix-20261111/manifest.json)包含本次整合的 runner v12、outer v5、preparation v6 等后继源码。旧执行源码保留，原模型、权重、BF16、冷缓存 4096、长解码、请求槽位复用、质量 96 和配对 HTTP 要求不变。
