# MiniCPM5：同时替换当前输入与历史，局部误差降至 0.4464%

**180 次完整四行注意力调用及退出后的独立复核已完成。原对照同时使用官方当前归一化输入和官方历史 K/V 后，第二层注意力输出的汇总相对 L2 从 1.2720% 降至 0.4464%，24 帧全部改善，但仍没有一帧完全等于官方输出。** 这是局部数值诊断，不是整模型修复、质量通过或提速结果。

上一轮[只替换官方历史](minicpm5-official-history-20261110.md)将原对照距离降至 1.1048%，仍有 6 帧变差。本轮加入当前输入因子，实际执行输入来源 × 历史来源的 2×2 组合，并恢复原输入和历史检查结果。

## 改变与保持的内容

当前输入来自官方同一 fixture、同一步的 `layers.1.input_layernorm` 输出；过去 K/V 来自该 fixture 的前一步。当前输入一旦改变，本步的 Q、K、V 都会一起改变，因此不能把本实验解释为只替换 query。

每组仍调用原 SDK 的完整四行注意力，保持 `[4,1,2048]` 输入及原 `[1,4,4]` stride、BF16 官方权重分片、原 mask、位置、RoPE、分桶、物理请求槽位和完整 `[4,1,4224,128]` 缓存存储。只替换有效的过去 K/V 前缀；当前位置、未来位置和填充区保留。干预结果不进入下一组历史。

两个 TP rank 都构造完整原模型，但只重放第二层注意力。计算运行在 CPU 上的 SDK 参考适配实现；目标来自官方 CPU 参考，没有新增 Neuron 设备或真实 HTTP 性能测量。

## 2×2 实测结果

每格汇总该路径 24 帧的完整 2,048 维输出，计算 `sqrt(差值平方和 / 官方输出平方和)`。数值表示局部距离，不表示质量损失率、误差来源占比或速度。

| 原路径 | 原输入＋原历史 | 官方输入＋原历史 | 原输入＋官方历史 | 官方输入＋官方历史 |
| --- | ---: | ---: | ---: | ---: |
| 原严格对照 | 1.2720% | 1.0653% | 1.1048% | **0.4464%** |
| 仅预填充候选 | 1.2394% | 0.9907% | 1.1048% | **0.4464%** |
| 两阶段候选 | 1.2709% | 0.9664% | 1.1003% | **0.4464%** |

改善与变差均相对于该路径自己的原输入＋原历史：

| 原路径 | 只换当前输入：改善 / 变差 | 只换历史：改善 / 变差 | 同时替换：改善 / 变差 |
| --- | ---: | ---: | ---: |
| 原严格对照 | 21 / 3 | 18 / 6 | 24 / 0 |
| 仅预填充候选 | 20 / 4 | 19 / 5 | 24 / 0 |
| 两阶段候选 | 19 / 5 | 15 / 9 | 24 / 0 |

所有替换均改变全部 24 帧；所有模式与官方完全一致的帧数仍为零。两项均来自官方时，三个路径的完整输出逐字节一致。因此这里是相同 24 帧结果在三种原路径下的对照，不能算成三份独立样本。

只换其中一项仍有明显偏差，同时替换的改善更大。以四组输出向量 `y00 / y10 / y01 / y11` 表示原组合、只换输入、只换历史、同时替换，交互向量为 `y11 - y10 - y01 + y00`。其相对于官方输出范数的汇总距离，在三条路径分别为 1.2586%、1.2032%、1.2618%；每条路径的 24 帧都有非零交互。这说明两项替换的影响不能简单相加，也不能将单项距离下降解释成各自的错误贡献比例。

## 哪些对照确实复现了

新实验先读取并验证上一轮真实输出，再逐字节比较：新原样状态对应旧 `own`，新仅换历史对应旧 `official_both`，新恢复状态对应旧 `restore` 和旧 `own`。这些控制均通过。

| 验证 | 结果 |
| --- | --- |
| 完整调用 | 2 rank × 3 路径 × 6 decode × 5 状态＝180 次 |
| 原样与恢复对照 | 各 36 次，精确复现原输出 |
| 与上一轮实测输出比较 | 108 次完整输出逐字节一致 |
| 官方输入／历史干预 | 108 次完整输出均有限 |
| 两个 rank | 全部完整输出逐字节一致；两个不同 KV head 分别验证 |
| 退出后独立复核 | 重读全部 2,949,120 字节输出，重新构建输入和历史替换并计算距离 |
| 针对性检查 | 15 项核心、19 项集成、6 项分析，合计 40 项通过 |
| 实际退出 | 模型会话 10509 退出 0；独立审计会话 86683 退出 0 |

独立审计不导入 Torch、NumPy 或 Neuron，用标准库 FP64 处理 BF16 向量。测试覆盖错误当前帧／前一步、fixture／槽位／位置、重新计算哈希后篡改对照、恢复失败、跨 rank 不一致、非有限输出及不完整退出记录。模型保持原 16 GiB、无 swap、CPU 6–7 限制，全部计算与存储任务串行；模型和审计进程均已退出。

## 结论与下一步

在这个固定局部调用中，当前归一化输入和历史 K/V 的联合替换能显著减少差异，但剩余 0.4464% 尚未解释。原 SDK 的投影分片、求和和注意力数值路径仍在运行，原 B4 调用与官方 B1 调用的形状也不同。不能据此认定缓存实现或 Neuron 芯片存在缺陷。

下一项有意义的检查是固定官方输入与历史，区分 B4/B1 调用形状和 SDK 投影／规约路径的影响，并保留完整四行的原样与恢复控制。该后续实验尚未准备或执行。

整模型结果仍沿用原记录：严格对照数值 29/32、首选 token 32/32；两个候选各为 28/32、31/32，候选继续拒绝采用。此前 75 项 FP64/FP32 余弦标量超容差仍保留。原精度、完整数值、冷缓存、长解码、请求槽位复用、质量和配对真实 HTTP 性能门槛没有降低。

本轮没有新增提速倍数。[各模型已有倍数与适用范围](multi-model.md#existing-results-and-provenance)继续沿用原测量。
