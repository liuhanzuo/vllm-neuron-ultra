# MiniCPM5：完整缓存复核完成，指标审计失败原因已对齐

本轮完整采集和独立保存数据诊断均已实际结束。**两个 rank 的完整 logits 一致；168 份完整 K/V 缓存及跨调用历史衔接核对通过。** 三组各 32 帧的结果仍是原对照 29/32、两个候选各 28/32，两个候选继续拒绝采用，没有新增提速倍数。

严格标量审计没有通过：75 项双精度余弦与原 FP32 记录的差值超过预设容差。后续诊断保留这项失败，并确认它与 [11 月 8 日已查明的指标布局差异](minicpm5-full-bf16-trajectory-20261108.md)相同。不能把“诊断执行成功”写成“严格审计全部通过”。

## 本项目审计工具的问题

新审计入口重新使用了旧的 FP64 对 FP32 标量容差，并把超限设为立即终止，却没有接入此前已完成的原布局 FP32 重放证据。实际会话 70717 因 `Original independent float64 tolerance: cosine` 退出 1，没有写入成功终结记录。失败及物理释放记录已保存；旧源码、原模型门槛和容差未修改。

新增诊断入口记录全部超限项，并继续核对其他数据。它使用独立的诊断结果格式，明确输出 `audit_passed=false`，不能冒充原审计通过，也不能直接触发自身历史重放。针对超限保留、重复 rank、失败分类、首选索引、非有限值、原容差和无原生依赖的 7 项标准库检查已通过。

进一步通过有哈希绑定的元数据链比较本轮与 11 月 8 日的全部 84 次调用：完整 logits 哈希及生产布局、原指标字典、物理行映射、输入、213 个观测点及缓存元数据均相同。原官方参考和指标源码相同；全部 96 份指标字典均对应此前实际完成的原布局精确重放。此次是确认旧重放证据适用于同一份数值和布局，**没有宣称重新执行了原生指标重放**。

各项最大 FP64 差值也与旧独立分析完全相同。已知现象是非连续视图和 FP32 归约影响标量计算；不能据此认定模型数据损坏、Neuron 编译器错误或 Trn1 硬件故障。本轮暴露的是我们后继审计入口遗漏了既有结论。

## 后续工作

下一步需要把“原 FP32 指标精确复现”“独立 FP64 判定一致”和“完整缓存字节一致”作为明确的独立证据接入后继重放入口，同时继续保留严格 FP64 标量容差失败。当前 v2 入口仍要求旧审计成功，因此本轮没有越过它启动自身历史注意力重放。

之后先要求相同当前输入加自身历史精确复现完整四行注意力输出，再进行配对历史干预；只有这样才能判断历史差异是否构成因果影响。冷缓存、长解码、槽位复用、质量和真实 HTTP 配对性能门槛均保留。Nemotron r11 仍是存储下限导致的失败释放状态；没有重启它、扩容 EBS 或删除新的模型数据。

现有全部模型的提速及限制继续见 [汇总](multi-model.md)、[四模型历史 INT8 结果](dense-int8-results-20261030.md)与 [CPU 采样优化](trn1-optimizations.md)。本轮没有增加可发布的优化配置。
