# Nano4B：把原始导入分发函数接入启动检查

2026-11-10 UTC：新增 `BootstrapDispatchPolicy`，为已有启动上下文提供具体的 `authenticate_bootstrap` 检查。此前该接口仍需调用者自行实现；现在它要求解释器检查已经绑定原始冻结模块，再核对即将被检查钩子替换的原始函数。

这个改动属于运行准备，没有执行真实 SDK 或模型，也没有新增提速结论。

## 检查的内容

函数必须来自解释器内嵌的 `_frozen_importlib` 顶层代码定义，使用原模块的全局变量字典，并保留已审查的默认参数、代码及对象身份。`importlib._bootstrap` 和 `importlib.util` 中的两个分发入口必须指向同一原始函数。即便替换后的代码内容相同，新的代码对象也会被拒绝。

检查发生在安装导入钩子之前。安装期间，已有启动上下文负责检查当前钩子；新模块继续检查保留下来的原始函数，因此正常安装不会被误判为来源变化。上下文结束或发生异常时恢复原入口。

## 实际验证

Python 3.10 与 3.12 各通过 12 项测试，共 24 次成功执行。测试实际安装了导入检查上下文，通过固定源码加载器导入生成的模块，并检查正常恢复、异常对象原样传递和异常后的恢复；另覆盖错误别名、不同全局变量字典、默认参数变化、代码对象替换、缺少前序绑定及资源守卫拒绝。

原始环境的只读观察证明，新分发函数候选清单对应此前固定的解释器清单。Python 3.10 与 3.12 的函数代码摘要不同，分别记录，不跨版本混用。测试中的解释器二进制和进程映射证据仍为合成数据；本次没有读取原始原生文件内容，也没有执行原环境启动钩子或模型。

## 仍然需要什么

本模块只补齐原始分发入口检查。其他已加载源码、完整原生依赖，以及实际主进程、双 rank 和辅助程序入口仍需接好。已有模型精度、冷缓存至 4096、长解码、槽位复用、生成行为、质量与配对性能要求全部保留。
