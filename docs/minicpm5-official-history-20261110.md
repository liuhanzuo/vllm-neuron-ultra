# MiniCPM5：官方 K/V 能减少部分注意力偏差，但不能消除它

**180 次完整四行注意力调用及退出后的独立字节复核已完成。固定原对照当前输入，换入官方 K/V 后，输出相对误差由 1.2720% 降至 1.1048%；24 帧中 18 帧改善、6 帧变差，仍无一帧与官方输出完全一致。** 缓存历史可以改变局部偏差，但本轮没有证明整模型失败的根因，更没有得到可部署修复或新增提速。

这是[官方第二层缓存采集与比较](minicpm5-layer1-native-cache-result-20261110.md)的后续。之前只知道候选缓存更接近官方，本轮实际把官方历史代入同一个注意力调用，检查输出是否改善。

## 实际改变了什么

三种既有路径分别保留自己的当前输入：原严格对照、仅预填充替换首层输出投影、预填充与解码均替换首层输出投影。每条路径、每次原 decode 调用依次执行五种状态：原历史、官方 K、官方 V、官方 K/V、恢复原历史。

官方历史来自同一个 fixture **上一步**原生前向的完整缓存；比较目标则是该 fixture **当前帧**官方注意力输出。两者不混用。官方两个 KV head 对应原 TP2 rank，四个请求仍使用原物理槽位。

只替换有效的过去位置，保留完整 `[4, 1, 4224, 128]` SDK 存储中其余字节，包括当前位置、未来位置和填充区。当前输入保持原 BF16 数值和非连续布局，权重分片、mask、位置、分桶、RoPE 和 SDK 注意力调用均保持原实现。每次调用前后重新检查输入、完整缓存及权重不变；干预结果不会成为下一组的历史。

这是一项 CPU 上的 SDK 参考适配实现与官方 CPU 参考对照，没有新增 Neuron 设备执行，也不测推理吞吐。三个路径的整模型资格仍未通过。

## 输出变化

每格汇总该路径 24 个 decode 帧的完整 2,048 维输出，相对 L2 为 `sqrt(差值平方和 / 官方输出平方和)`。它是局部数值距离，不是质量损失率、错误贡献占比或提速。

| 固定当前输入的路径 | 原历史 | 官方 K | 官方 V | 官方 K/V |
| --- | ---: | ---: | ---: | ---: |
| 原严格对照 | 1.2720% | 1.1458% | 1.2280% | 1.1048% |
| 仅预填充候选 | 1.2394% | 1.1394% | 1.2041% | 1.1048% |
| 两阶段候选 | 1.2709% | 1.1301% | 1.2360% | 1.1003% |

整体距离下降，并不意味着每个请求都更好：

| 固定当前输入的路径 | 官方 K：改善 / 变差 | 官方 V：改善 / 变差 | 官方 K/V：改善 / 变差 |
| --- | ---: | ---: | ---: |
| 原严格对照 | 14 / 10 | 23 / 1 | 18 / 6 |
| 仅预填充候选 | 13 / 11 | 24 / 0 | 19 / 5 |
| 两阶段候选 | 15 / 9 | 22 / 2 | 15 / 9 |

每项均覆盖 24 帧，官方缓存替换都改变了全部 24 帧的输出。所有路径、所有状态与官方输出完全一致的帧数仍为零。恢复原历史后，全部输出精确回到原值。

官方 K 的汇总改善幅度通常较大，官方 V 的改善覆盖更多帧；两者同时替换不保证每帧更好。不能简单相加，也不能据此认定某一个缓存有实现缺陷。将缓存换成官方数值后，当前输入、当前 token 的 Q/K/V 计算及注意力计算的数值路径仍是原 SDK 路径，这些因素仍需进一步区分。

原严格对照和仅预填充候选在同时使用官方 K/V 时得到相同汇总距离，与它们先前记录的当前归一化输入完全相同相符。完整逐帧输出和哈希保留在证据中；不将两个路径计作两份独立样本。

下一项有意义的对照是当前归一化输入 × 历史来源的 2×2 组合：固定完整原调用形状，分别使用原输入或官方当前输入，以及原历史或官方历史。若两者均来自官方仍有差异，再检查原 B4 调用与官方 B1 调用的计算形状效应。本轮没有执行这些后续实验。

## 验证覆盖与限制

| 检查 | 完成结果 |
| --- | --- |
| 原始调用范围 | 两个 rank × 三条路径 × 六次 decode × 五种状态 = 180 次完整四行调用 |
| 原历史与恢复对照 | 各 36 次，全部逐字节复现原输出 |
| 官方历史干预 | 108 次，完整输出均有限 |
| 原数据链 | 所有 84 次 SDK 原调用的完整缓存链重新重建；官方 32 帧缓存及当前目标绑定原成功采集 |
| 跨 rank 输出 | 全部完整输出逐字节一致，分析只计一个副本；两份不同 head 的缓存仍各自验证 |
| 退出后复核 | 全部 2,949,120 字节输出重新读取，逐组独立重建历史替换范围，重新计算距离 |
| 实际退出 | 模型会话 89158 退出 0，两个 rank 均退出 0；独立审计会话 65038 退出 0 |
| 针对性检查 | 16 项缓存/原调用检查、18 项运行与结果检查、2 项分析检查，合计 36 项通过 |

独立审计不导入 Torch、NumPy 或 Neuron 运行库，使用标准库 FP64 计算 BF16 向量距离；退出后再次核算改善帧数和汇总平方范数。测试包含错误 fixture/前一步/槽位/head、伪造退出、缺失恢复对照、重算哈希仍改变恢复输出、错误当前官方目标、非有限输出以及跨 rank 不一致。

模型调用保持原 16 GiB、禁止 swap、CPU 6–7 的限制，并逐次检查根盘 28 GiB、NVMe 30 GiB 下限；独立审计单核、2 GiB 地址空间。所有模型、编译、性能、存储工作串行。

原整模型结果仍为对照数值 29/32、首选 token 32/32，两个候选各数值 28/32、首选 token 31/32。这里未重新执行整模型候选，也未把局部改善当成门槛通过。此前 75 项 FP64/FP32 余弦标量超容差失败保留；完整数值、冷缓存、长解码、槽位复用、质量与真实 HTTP 配对性能门槛继续保留。
