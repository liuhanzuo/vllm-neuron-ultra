# MiniCPM5：减少历史解析期间的重复检查

上一轮重复数据清理在删除前失败，独立失败归档仍在运行。源码检查发现归档工具的一项开销：解析历史清单时，每个读取回调都会重新核对全部来源、控制目录和最新串行状态。随着历史增加，这会反复扫描同一批无关文件。现有清理运行入口已按 0.5 秒周期执行这类全局检查，但归档入口没有相同处理。

新 v4 仅调整只读历史解析阶段：每次回调继续检查锁、停止信号、原 7,200 秒限时和旧进程已退出；完整全局检查在首次回调、显式强制检查和距离上次检查起点至少 0.5 秒的下一次回调执行。进入和离开解析阶段都强制完整检查，异常出口也执行。每次完整检查重新读取哈希，不缓存此前通过的判定。

这会改变变化的发现时机：全局来源或目录的持续变化可能在下一个到期回调或阶段出口才被发现，两次回调之间的短暂变化可能不被观察到；阻塞操作也可能推迟回调。因此不宣称与逐次检查完全等价，也不保证固定 0.5 秒墙钟检测。每份直接读取的内容和身份检查仍然执行。后续物理检查、文件占用检查、保留副本复核和结果写入继续逐次执行原完整检查。

主任务与独立审查各 **62 项隔离测试通过**，包括失败出口、来源变化、慢检查、强制回调和后续检查不降频等场景。完整执行来源重新核对 **674 份**，包含原 670 份及四份后继源码；新准备清单包含 688 份。此前固定历史共享文件的只读修复保持，删除事务和原科学标准保持。

本次是实验工具源码修复。合成时钟下的重复工作计数不代表实际归档或模型推理提速。新入口尚未实际运行，也未替换正在运行的旧归档进程。下一轮必须先确认旧轮次真实结束，再使用最新完整串行记录创建独立运行；预计可回收的 **9.475 GiB 尚未释放**。
