## 这次补齐了什么

读取程序只接受原始清单中的 95 份元数据和 84 个 BF16 数据包，要求文件名、指纹、大小与记录完全一致。每个文件恰好读取一次，完整结束时再核对总文件数和总字节数；任何失败都会终止该读取器，不能继续使用部分结果。

它逐级打开目录，拒绝符号链接，检查每一层目录和文件是否被替换。文件须为单一硬链接的普通文件；每次最多读 64 KiB，同时检查运行条件、长度和完整内容指纹。文件属性与内容指纹都会校验，因为仅依赖属性不够。

测试中遇到一个具体边界：在极短时间内等长改写文件，观测到的文件属性可能仍相同。原测试错误地要求属性检查一定先拒绝，实际程序继续执行必需的指纹检查。修正测试假设后通过；原失败样例和退出记录保留。这不是模型计算问题，也没有据此归因到其他仓库。

JSON 读取同时拒绝重复字段、NaN/Infinity 和溢出的数值字面量。两个候选之间与候选相对基线的比较继续分别标注，保留原始最终指标。

## 验证覆盖与限制

| 验证 | 实际覆盖 |
|---|---|
| 19 项文件读取检查 | 替换文件或目录、等长改写、符号链接/硬链接、截断或多余数据、错误指纹、分块读取失败、运行条件失效、未读完或重复读取、文件描述符回收 |
| 11 项输入绑定与连接检查 | 完整 95+84 清单、文件与逻辑调用重复、错误 rank/方案/阶段、指纹或大小变化、JSON 边界，以及生成数据的完整 384 组比较 |
| 真实文件身份快照 | 179 个不同文件身份，包含 95 份 JSON 与 84 个张量文件；目录逐级检查，无原始张量内容读取 |
| 真实新读取器检查 | 95 份 JSON 的完整指纹和全部 27,711,882 字节核验，通过后在首次原始张量读取前停止 |

生成数据的连接检查使用内存数据验证报告流程，文件读取检查使用临时测试文件；二者均不代表真实模型张量分析已经完成。原始张量内容的完整核验和数值计算仍需在正式串行窗口执行。
