# MiniCPM5：第二层自身历史注意力重放全部复现

**两个真实 TP2 rank 共 36 次完整四行注意力调用，全部逐字节复现原输出。进程退出后的独立复核也通过，重新读取了全部 589,824 字节。** 这补齐了后续缓存历史干预所需的自身历史对照：可以用已保存的当前输入和缓存，复现原 SDK 的第二层 decode 注意力计算。

这是 CPU 正确性诊断，未执行 Neuron 设备推理或性能测量。它不说明整模型已经正确，也没有证明缓存历史是误差根因。原 32 帧模型结论仍是对照 29/32、两个候选各 28/32；没有新增提速倍数。

## 本轮实际执行

| 项目 | 实际范围与结果 |
| --- | --- |
| 模型与精度 | 原 42 层完整 decode 模型，每个 rank 构造一次；原官方 BF16 权重、原 SDK 注意力实现 |
| 投影权重 | 每个 rank 的第二层 Q/K/V/O 四个官方分片逐字节核验；未转换精度或替换投影公式 |
| 配置 | 原对照、仅预填充替换首层投影、两个阶段均替换首层投影，共三组已保存轨迹 |
| 解码位置 | 每组原调用 4、5、6、11、12、13；每次保留全部四行、原 mask、位置、槽位与分桶 |
| 缓存 | 各配置自己的完整输入 K/V 历史；读取全部 42 次历史调用／rank，保留空闲槽位及填充区 |
| 重放结果 | 每 rank 18 次、共 36 次，全部输出逐字节一致；共 144 个物理输出行，去掉 rank 副本后是 72 行 |
| 保存与复核 | 36 份完整 BF16 输出，共 589,824 字节；结束后由标准库程序再次完整读取并核对 |
| 实际结束 | 外层会话 88390 退出 0；协调进程记录两个 rank 均退出 0；外部核对四个原进程消失、服务结束、进程组为空 |

重放恢复了原非连续的归一化输入布局、完整缓存及 SDK 消费视图，继续使用原旋转位置编码。每次调用前后检查输入、缓存及官方参数字节没有变化。调用只执行第二层注意力，不重跑完整模型前向；没有交换不同配置的缓存。

原 16 GiB 内存上限、禁止 swap、CPU 6–7、串行锁、根盘 28 GiB／NVMe 30 GiB 余量下限均保留。实际输出树约 3.57 MiB、48 个文件；模型运行时间包含历史验证、构造和反复字节检查，不计作推理性能。

## 如何接通此前的审计证据

[上一轮完整数据诊断](minicpm5-layer1-saved-data-result-20261110.md)已确认 84 份 logits、168 份缓存与历史衔接，但严格 FP64／FP32 标量比较保留 75 项余弦超容差。旧入口把这项失败作为停止条件，尚未使用此前已经完成的原布局 FP32 精确重放。

新入口分别验证三类证据：

1. 84 次新旧调用的完整输出哈希、生产布局和观测元数据相同；全部 96 份指标字典对应此前实际执行的原布局 FP32 精确重放。
2. 独立 FP64 数值判定和首选索引与原报告一致，且完整 FP64 结果与此前分析相同；逐项重算超限清单，仍保留 `strict_float64_scalar_tolerance_passed=false`。
3. 两个 rank 的完整输出、全部缓存字节和历史衔接已独立核验。

这是新的明确证据格式，没有把失败结果改名为旧审计成功，也没有扩大任何容差或改变模型数值门槛。读取流、重放执行器和输出验证器共同使用新格式。期间还修复了本项目输出验证器仍引用旧版审计接口的问题；不涉及上游模型、编译器或芯片实现。

共 **48 项标准库检查通过**，覆盖真实元数据链及错误退出、替换进程／会话、错帧、改变布局／精度、隐去标量失败、放宽容差、不完整缓存、错误历史和伪造合格结论。五项入口检查在接到当前构建器后重跑通过，属于这 48 项的子集。一次测试选择器写成不存在的类名导致测试未执行，修正选择器后通过；失败记录保留。

原计算驱动和输出验证函数的函数体通过语法树逐项比较保持一致，仅更新导入的证据处理模块。冻结旧源码、实际采集和失败记录都未改动。

## 退出后的独立复核

独立程序在获得串行锁后核对实际退出、原进程消失、空进程组、源码哈希、两 rank 结果、官方权重分片证明与原调用身份。它重新读取全部 36 份输出，复算完整哈希，并核对两 rank 副本一致和原注意力输出哈希；总计 589,824 字节，没有导入 Torch、NumPy 或模型运行库。

复核会话 41777 实际退出 0，外部再次确认复核进程已结束并取得串行锁。一次尝试捕获运行中的服务身份时，任务已先行成功结束，因此存活检查拒绝；随后以真实终止结果完成核验，没有把已经结束的进程写成仍在运行。

## 下一项因果对照

已有元数据确认同一调用在三组配置间的 mask、位置、槽位、分桶及完整缓存布局兼容。下一步固定当前归一化输入，仅替换一对完整 K/V 历史，形成三种输入来源 × 三种历史来源的交叉矩阵。

计划覆盖两个 rank、六个 decode 调用，共 108 个矩阵单元，另加 36 次恢复自身历史的重复对照，总计 144 次完整四行调用。每组先要求自身历史输出精确一致，干预后再恢复并重复检查；K 和 V 始终来自同一配置。完整输出约 2.25 MiB。该矩阵目前只有设计和兼容性验证，**尚未实施交叉历史干预**。

固定当前输入换历史，可检测历史变化的影响；固定历史换当前输入，可检测当前隐藏状态的影响。即使出现局部因果差异，也还需要完整模型的数值、冷缓存、长解码、槽位复用、质量与配对 HTTP 性能验证，才能采用为优化配置。全部 15 个模型家族目标继续保留。
