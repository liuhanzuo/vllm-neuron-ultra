# Nano4B 进程启动参数接入与 Nemotron 卷积四组验证

2026-11-10 UTC：Nano 4B 已增加五类进程的明确启动参数与父进程放行连接，19 项测试在两套原始 Python 中全部通过，共 38 次成功执行。Nemotron 9B 卷积切分的正确性验证已推进到长度 1024，四组候选共 24/24 次设备比较逐位一致。本次没有新增整模型提速倍数。

## Nano4B 新增了什么

新增 AttemptInvocations 为原生参考进程、两个 TP rank 和两个 SDK 辅助进程分别构造启动参数。原生参考仍使用 Python 3.12，rank 和 helper 仍使用 Python 3.10。环境从原科学计划明确构造，不继承调用终端的环境；缓存输出映射到 v3 后继目录，保留原模型、BF16、TP2、batch 4、上下文 4096 和 FP32 SSM 状态要求。

每个进程使用独立、权限为 0700、身份固定且保持为空的字节码缓存目录。命令保留 -B、-S，并通过 -X pycache_prefix 指向各自目录。参数解析只接受确切顺序、角色、尝试编号、准入文件引用和两个握手描述符。

ParticipantBinding 在放行前后检查实际 Python、命令行、工作目录、完整环境和进程组；父进程必须先记录子进程身份，再放行。启动恢复工厂现在接收已分配描述符对应的确切参数，并要求与来源检查上下文使用同一个缓存对象和检查器。生成的轻量子进程已验证原生、rank 和 helper 三类路径。

这些是实际启动流程的准备组件。准入文件和引导脚本的引用格式检查不等于内容认证；真正的主入口仍需完成来源清单、原生库认证、资源与串行准入、整个进程组的生命周期接入。当前没有执行真实 site、SDK、模型或读取权重。

## 测试与本轮发现

两套 Python 各通过 19 项测试，共 38 次成功执行。测试包含正常父子握手、父进程持久记录失败时拒绝放行、环境与尝试编号不符、缓存非空或被替换、错误参数、角色、权限和描述符，以及启动工厂放行顺序。启动来源认证和准入为明确标记的测试替身；这些成功不能计入模型正确性。

初轮 15 项测试中有两项测试问题：一项在生成参数前先改动缓存目录，触发了正确的目录身份拒绝；另一项依赖早期握手失败时的 stderr，而现有子进程监督器在该阶段可能没有收集到错误输出。已保留初轮输出和源码快照，修正生成顺序，并让生成的子进程写出确切的放行前错误记录，核对拒绝原因。后续又补充了启动工厂测试。

现有 supervisor v2 的早期失败输出收集不完整仍是工具限制，尚未改写冻结版本。完整失败诊断需要后继修复；本轮没有将空 stderr 当作成功。Python 3.12 还报告旧收据源码中正则字符串的无效转义 SyntaxWarning；测试退出成功，原冻结源码保留。

## Nemotron 9B 卷积切分结果

输入为 BF16 [1,6144,T]，转置后按 [5120,512,512] 切分，再恢复原消费者形状。候选使用明确边界 [5120,5632]，保留精度和尺寸。

| 长度 T | 原方式逐位一致 | 候选逐位一致 | 原方式抽查地址错位／总数 | 候选错位 |
|---:|---:|---:|---:|---:|
| 128 | 0/6 | 6/6 | 1,143/1,152 | 0 |
| 256 | 0/6 | 6/6 | 2,295/2,304 | 0 |
| 512 | 0/6 | 6/6 | 4,599/4,608 | 0 |
| 1024 | 0/6 | 6/6 | 9,207/9,216 | 0 |

八个阶段均保留成功退出记录；原方式退出成功表示预期数值失败已复现，其内层 primitive_passed 和 device_exact 均为 false。它们不能作为提速分母。候选四个长度的 24 次比较全部逐位一致，输入未改变。

本轮汇总读取的是已结束阶段的 JSON 记录，核对其数值结果与进程身份、退出记录，没有重新读取原始张量或 HLO 文件。整次运行仍需最终独立原始证据审计。问题目前仅限已复现的软件栈与转换路径，尚未独立归因至某个上游仓库或其他版本。
