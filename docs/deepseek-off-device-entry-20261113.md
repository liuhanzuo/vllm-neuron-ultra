# DeepSeek 冷启动诊断：补齐关闭采集的设备入口

DeepSeek-R1-0528-Qwen3-8B 的后续诊断需要比较开启和关闭边界采集时的完整输出，先确认采集过程不会改变被观察的计算。已有关闭采集的完整测试循环，但它接收的是已经加载好的模型；本次补齐新进程中的原模型加载，以及加载前的外部文件哈希验证。

新入口使用原始未采集模型、原配置和 BF16 权重，保留 TP2、batch 4、context 4096。它调用原完整控制程序，保留 **42 次模型调用、84 帧、12 个图、144 个状态对象和 6,048 份设备 KV 张量**；原 14 个数值失败必须完整重现，不能把只比较失败行的结果当作完整对照。

模型文件、配置和两份原生参考文件的预期 SHA256 由外层提供，并在原生导入、模型加载和参考数据反序列化前验证。只有完整报告、缓存清单和状态检查都符合原协议时，才会记录预期的数值失败；执行条件失效或提前异常仍然失败。结束或异常时恢复两个模型入口原有的调用方法。

主任务和独立审查各运行 **18 项隔离测试，全部通过**，另核对 89 份本地源码摘要及八份原依赖。模型加载和张量访问在测试中使用模拟对象；本次没有编译、设备执行、原始数据等价性或提速结论。

真实运行仍需完成原权重、SDK 和完整环境验证，以及实际工具退出与进程清理检查。两组对照的原始输出预算仍为 **47,150,344,192 字节**，还不包含编译缓存、模型产物、权重分片和共享内存，不能假设可以直接放入当前剩余空间。完整原始数据比较、2,041 步长解码及 93 个检查位置、槽位复用、quality96 和匹配 HTTP 验收都保留。
