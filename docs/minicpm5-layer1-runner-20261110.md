# MiniCPM5 完整采集运行器接入与 Nemotron r11 投影对照

MiniCPM5 的第二层完整缓存采集已接入后继运行器源码，**29 项源码、真实元数据和模拟生命周期测试通过**。实际准备核对了 2,348 个源码／文本文件，合计 160,491,700 字节，保留原科学输入、精度、阈值和完整轨迹。尚未创建实际运行规格、启动 MiniCPM5 或读取真实保存张量。

Nemotron r11 仍串行运行。截至 **2026-11-10 07:17:10 UTC**，已独立核对 **23／52 个阶段**成功退出，包括准备、9 项状态读写及 13 项切分阶段。六种 128–4096 token 投影候选的设备输出比较为 **36／36 通过**；原切分路径仍能编译但数值不正确，不能作为性能分母。完整模型服务启动和后续验收仍待完成。

## 运行器接入了哪些内容

新运行器使用已完成源码审查的完整缓存观测 worker 和结果验证器。两个 rank 各执行三个原配置，每配置 14 次调用、32 帧，共 84 次模型调用。协调进程和 rank 的原科学执行逻辑经源码结构比较确认保留，仅换成新的观测 worker；原完整数值、输入、状态历史、物理行映射、权重与投影条件继续验证。

任务仍使用原 CPU 6–7、16 GiB 内存上限／14 GiB 高水位、无交换空间和两小时上限。输出仍是每 rank 128 MiB、合计 256 MiB、单文件 16 MiB、最多 512 个文件。根盘剩余空间要求 28 GiB；NVMe 沿用当前串行队列的 30 GiB 剩余空间底线，比早期 MiniCPM5 的 8 GiB 更严格，没有扩大输出额度或删除范围。

源码接入时发现，原清单含模板、补丁、历史日志和其他文本，不能限制成仅 Python／JSON。后继恢复原有文本类型规则，仍校验每个文件的完整哈希和 8 MiB 上限；模型张量和原生二进制不在这条源码读取路径中。该兼容问题已在源码检查中处理，没有启动失败模型任务。

## 完整历史与退出清理

旧 MiniCPM5 运行器只核对较早的前序任务，而且其清理报错后仍可能走到释放串行锁。新运行器独立接入当前 Nemotron r11 的真实结束证据，保留 1,202 个历史服务和 399 个历史进程身份，再加上 r11 的 53 个服务，共 1,255 个服务的完整检查范围。

必须匹配实际已观察的 r11 启动会话、进程开始时间、原命令、规格和源码审查。成功分支要求真实完整审计；失败分支要求原失败退出，以及独立完成的受支持失败释放操作。缺失阶段、替换身份、缺失实际退出、将失败升级为成功，均不能通过。r11 尚未结束，因此当前没有虚构这些未来记录。

新退出路径先校验原服务身份再停止它，逐个确认记录的进程消失，并递归检查整个进程组。清理失败、写入失败、中断或仍有未记录子进程时，继续持有串行所有权，等待可验证的清理完成。未知或被替换的服务不会被盲目停止。实际证明清空后才能释放锁；输出里的“成功”字段不能代替物理退出。

原完整历史检查和新 53 个服务都保留双次稳定观察。为避免重复保存大量无关系统配置，结果文件只保留相关状态、退出码、调用身份和全部进程组观察，并记录完整观察内容的哈希；没有跳过历史服务。

## 验证范围

最终 29 项测试包括成功／失败两条历史衔接、1,255 个服务记录完整性、原失败结论保留、错误运行身份、原始数据审计缺失、服务替换、仍存活的进程／子进程、清理写入失败和中断下的持锁行为。使用实际源码清单与原轨迹元数据核对全部精度、冷缓存、长解码、槽位复用及质量要求。测试没有调用真实新模型或当前任务的资源释放操作。

早期 22 项和中间 27 项是最终 29 项的子集，不能相加。最初测试脚本有一次条件表达式空格缺失的语法错误，未运行任何测试，修正后才执行测试集。源码扫描还显示原冻结文件中的正则转义弃用提示，未改写这些历史文件。

此前 MiniCPM5 原 CPU 对照仍是 29／32 数值通过、top1 32／32；两个 BF16 候选仍是 28／32、top1 31／32，保持不合格。运行器接入与模拟测试没有改变这些结论，也没有证明缓存差异的因果关系。

本次独立复核读取了原 JSON 结果、服务实际退出码、调用身份和进程组清空状态；最终全量保存字节审计仍待完成。36／36 是局部投影切分比较，不能据此宣布整模型通过、说明服务已恢复，或计算整模型提速。

## 接下来的实际执行

先让现有 Nemotron r11 完成原全部切分、模型服务启动、状态复制、数值、冷缓存至 4096、长解码、质量、真实 HTTP 四并发、配对性能和最终原始数据复核。若失败，则保留失败并完成既定独立释放，不重复启动未终止任务。

得到真实退出／释放记录后，生成 MiniCPM5 具体计划和审查，在串行所有权下重新核对完整历史和物理退出，再执行全部 84 次调用。采集需要每次与冻结的原调用完全一致，并证明导出没有改变输入、返回状态、logits 或观测点；真实压缩输出仍须装入原上限。

之后进行独立完整缓存字节还原及原完整 logits／HF 复核。先让相同当前输入加自身历史重放得到原 decode 注意力输出，再比较配对历史；prefill 的预测位置观测不能充当完整 prefill 中间输入。Nano 的真实 SDK／模型接入与其余模型家族继续保留在完整目标中。
