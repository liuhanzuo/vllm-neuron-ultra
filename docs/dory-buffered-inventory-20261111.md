# Dory 环境清单写入修复与实际失败核验

Dory 的第五轮环境清单检查在接入分块写入后实际退出 0，独立审计也退出 0；原 600 秒 CPU 上限保持不变。第四轮 CPU 耗尽失败与不完整输出全部保留。本轮修正的是实验工具的 JSON 写入开销，没有新增模型推理提速倍数。

## 实际运行结果

父进程实际退出 1，子进程返回 -24（SIGXCPU）。独立审计随后重新取得原串行锁，确认父子进程退出、子进程组清空，完整计算所有输出文件的哈希，并重新解析保存的描述符证据。审计本身实际退出 0，主任务另行核对了审计进程退出。

| 输出 | 核验结果 |
|---|---|
| `inventory/native-files.json` | 7,011,456 字节；完整文件哈希已核验，但 JSON 未写完 |
| `events.jsonl.gz` | 6,131,670 字节；完整压缩文件哈希已核验，但缺少 gzip 结束标记 |
| 可解码的日志前缀 | 70,763 条事件、40,170,742 字节；仅代表成功返回的前缀 |
| 原历史状态 | 核对保存的 1,318 组稳定服务记录及已知运行标识；未声称重新遍历全部服务 |
| 模型资格 | 环境清单未完成，原生 ABI、整模型质量与速度均未据此通过 |

本轮没有保存到描述符检查失败或重复锁记录。它不能证明此前间歇锁问题已经修复，也不能把失败清单视为成功。对应内核源码和可能机制见[锁表调查](serial-lock-kernel-findings-20261111.md)。

## 修复了什么

原写入器直接遍历 JSON 编码器产生的小片段，每个片段都执行预算检查，再触发完整的进程与锁观察。逗号、引号等短片段也有这项开销。新版本先将相同字节流合并成最多 64 KiB 的块，再逐块检查预算并写入。

同一份 345,781 字节合成 JSON 的结果如下：

| 指标 | 原写入器 | 分块写入器 |
|---|---:|---:|
| 预算检查与写入次数 | 42,001 | 6 |
| 总 guard 调用次数（含完整回读） | 42,008 | 14 |
| 最终 JSON 字节 | 完全相同 | 完全相同 |

这是调用次数对照，不能当作耗时加速比，更不能填入模型提速表。尚未通过测量确定这项开销在第四轮 CPU 耗尽中占多大比例。

新版本保留原始编码方式、非有限数值拒绝、独占创建、单文件和总容量上限、文件与目录刷盘，以及写入后完整哈希、文件身份和 EOF 核对。失败时保留已写部分并传播原异常。2 GiB 地址空间、600 秒 CPU、900 秒墙钟及存储下限均未提高。

12 项模拟测试通过，独立追加 102 组确定性字节一致检查通过。父子入口的集成只改两行：父入口选用新 worker，worker 导入分块写入器；原串行锁策略、启动确认、历史检查和子进程清理保持原代码。4 项集成检查通过。

## 第五轮实际完成，但仍有 30 项待补证

第五轮父子进程均退出 0。退出后的独立审计重新取得原锁，核对全部输出文件、完整 gzip、每条文件事件与导出的清单、最后完成事件及保存的描述符证据；审计退出 0 后，主任务另行确认审计进程退出。

| 核对范围 | 结果 |
|---|---:|
| 文件清单 | 48,986 项，共 3,169,981,978 字节的被记录文件内容 |
| 安装环境 / 官方源码文件 | 40,522 / 8,464 项 |
| 完整事件日志 | 70,764 条，解压后 40,170,999 字节 |
| 完整清单 JSON | 10,735,415 字节 |
| 本次输出实际占用 | 41,824,256 字节 |
| 待补证项目 | 30 项 |

30 项包括：11 项系统库尚未绑定独立软件包字节证据；13 项 vLLM 扩展的 PyTorch 动态库依赖未确定加载来源；2 项 OpenMP 库存在多个候选；4 项 CPython 时间戳缓存内容待验证。这些是当前证据与静态解析的缺口，不能直接称为上游仓库错误或库实际缺失。

因此，本次通过的是清单生成与完整性审计，`complete_authenticated_inventory` 和原生 ABI 资格仍为 false。下一步补齐这 30 项来源和加载规则证据，再推进原生兼容性检查。此次没有观察到锁检查失败或重复记录，仍不能证明旧问题的历史原因。

## MiniCPM5 同期进度

MiniCPM5 原生验证的生命周期核心已通过 17 项模拟测试及 4 项追加检查，补齐持久化进程身份、启动前确认和只执行一次的清理流程。它使用原始恢复记录中的两个 SDK rank 结果，保留原驱动输出，不将原外层失败改成成功。实际进程适配器和启动入口仍在整合，原生对照尚未执行。

所有模型仍保留原权重、精度、冷缓存 4096、长解码、请求槽位复用、质量 96 和匹配 HTTP 要求。已有模型倍数见[提速总表](multi-model.md#existing-results-and-provenance)。
