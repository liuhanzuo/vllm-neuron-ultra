# MiniCPM5：向注意力、残差和归一化追踪差异

MiniCPM5 下一轮诊断的完整采集与局部重放代码已准备，**35 项源码、已存元数据和模拟回调检查通过**。这次没有加载权重或运行新的模型计算；设备队列仍由 Nemotron r6 占用，Dory 排在其后，MiniCPM5 仍需另行准备并审核实际执行配置。

## 已有证据决定了下一步

已完成的 r3 重放说明：固定同一个 CPU 输入时，gate/up/product 可以一致，down 路径足以解释该局部输出的差异，但不能解释最终 logits 的 KL。此前把完整 down 投影替换为另一种计算形式，32 帧数值通过数虽从 29 增至 30，最高分 token 一致数却从 32 降至 31，第一帧 KL 也从约 0.101270 增至 0.196323；该候选继续拒绝。

r3 的独立原始数据复核还显示，原生与 CPU 路径在 **MLP 输入之前** 已有差异：2,521,088 个真实位置元素中有 584,829 个不同。这是已有实测，不是本轮新增计算。

本轮回读第一帧的最后一个位置记录：embedding 和第一层 input RMSNorm 的指纹一致，attention 输出、post-attention RMSNorm 输出及 MLP 输出不同。这个结果只约束该位置，不能冒充整个前缀一致。

两套固定 Transformers 源码中的 `LlamaRMSNorm.forward` 计算语句相同：转 FP32、平方均值、加 epsilon、rsqrt、乘回输入，再转换为输入精度后乘权重。SDK 在 CPU 模式下选择的是这一普通 RMSNorm 分支。源码相同不保证不同 Torch 版本、输入或布局下的结果相同，因此未来运行还会核验实际类、方法、权重和调度，并要求原输入重放通过。

## 七处完整边界

| 边界 | 要回答的问题 |
|---|---|
| 第一层输入 | 两条路径的原始残差是否已不同 |
| input RMSNorm 输出 | 第一处归一化是否引入全前缀差异 |
| attention 输入 | 归一化输出是否原样进入注意力 |
| attention 输出 | 注意力之后的差异是什么 |
| post-attention RMSNorm 输入 | 实际残差相加后差异如何变化 |
| post-attention RMSNorm 输出 | 第二处归一化是否改变差异 |
| MLP 输入 | 与 r3 已保存的完整输入是否精确一致 |

保留原生 `[1,1231,2048]` 和 CPU 两个 TP rank 各自的 `[1,2048,2048]`，包括真实 stride 和 offset，不压缩成最后一个 token。七处乘三个角色共 **21 个完整张量，152,735,744 字节**；另保存六份完整归一化权重，共 24,576 字节。每份权重还会与原始 checkpoint 的精确区间比较。

原六个预测位置检查点、七个 CPU 输入参数、原权重装载和 MLP 参数检查均保留；新采集的完整 MLP 输入必须与 r3 原始记录一致。新增的两个相邻边界也要完全一致。采集不替换 forward，不开启融合内核或精度干预；运行到第一层完成即停止，禁止进入下一层或使用旧历史。

## 重放如何限制结论

先从保存字节恢复完整 shape、stride、offset 和 BF16 数据。每个角色都要重放 input RMSNorm、实际残差相加和 post-attention RMSNorm，并验证两个相邻边界；必须同时满足原始字节和布局一致，才能进入下一步。原生控制保留双线程，CPU 控制保留单线程。重放只使用获准的重放解释器，不冒充分别重用了原生解释器或实际 Gloo 通信。

之后在完整 CPU 2048 行和原布局上做三组局部对照：仅替换为原生残差输入、仅替换为原生 attention 输出、同时替换两者。只替换 1231 个真实位置，CPU 的填充部分原样保留。比较各组相加、归一化后的结果与原始 CPU 和原生结果，记录整个桶、真实前缀与预测位置三个范围。

如果原输入重放不能精确复现，保存失败控制结果并停止后续替换。即使全部重放和替换完成，结论也只适用于局部残差/归一化关系，不能认定 attention 内部或最终 KL 的唯一原因；attention、后续层与最终 logits 没有在这一步重新执行。

## 检查结果与剩余工作

35 项检查覆盖原 prompt/shape/布局/epsilon、原 r3 完整输入、实际回调顺序、缺失/重复采集、原生与 SDK 不同 attention 返回类型、异常安装清理、融合残差与历史路径拒绝，以及缺失角色、失败数值控制和布局变化时禁止继续对照。只在标准库中解析、绑定了原 RMSNorm 函数，没有执行其 Tensor 运算。

最初测试草稿有一处缺少空格的语法错误；新增重放也曾把集合交给只接受 JSON 值的旧比较函数，六项测试因此报错。两处已修正，原草稿与失败收据保留；相关的字节比较也改用专用的严格字节检查。它们是我们尚未执行的新诊断代码问题，不是模型或 Neuron 的已证实缺陷。

实际运行前仍需完整串行执行器、当时的真实前序任务退出记录、运行环境与源码指纹、独立保存字节复核及资源限制审核。本次没有启动 MiniCPM5 后继实验，也没有降低原 32 帧、冷缓存 84 项、长解码 2049/93 标记、槽位复用、96 题质量及成对服务验收要求。
