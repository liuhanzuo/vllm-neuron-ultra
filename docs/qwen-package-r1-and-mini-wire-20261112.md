实际导入链是 vLLM 配置 → Transformers → SciPy → NumPy testing。固定 NumPy 的 `check_support_sve()` 在导入时执行 `subprocess.run('lscpu', capture_output=True, text=True)`，以检测 ARM SVE 特性。预检禁止子进程并抛出 `RuntimeError`，而 NumPy 只处理 `OSError`，因此异常传播并使导入失败。这是预检与依赖初始化的兼容问题，不是模型数值不一致的证据。

后继修复正在准备：在本机 x86_64、固定源码和精确探测调用下，仍在启动子进程前拒绝执行，以 NumPy 原有的可处理异常进入其正常回退分支。它不会伪造 `lscpu` 输出，也不会放开任意子进程。父进程和全新 spawn 都必须独立验证这条路径，然后继续原有的注册、SDK 配置往返、CPU BF16 split、完整分词与采样器检查。修复后的原生结果尚未取得。
