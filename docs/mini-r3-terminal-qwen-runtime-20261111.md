# MiniCPM5 原生 r3 完成与 Qwen3.5 运行准备

MiniCPM5 原生 r3 已完成全部 24 个检查点、72 次直接注意力调用，外层工具实际退出 0。新写出的结果报告三组对照输出与完整缓存均精确复现官方参考，原权重和函数已恢复；外层、协调器和原生进程均已消失。结束记录正在独立执行，原始数据审计和 SDK／原生逐算子差异比较尚未完成。本轮仍没有新增整模型合格结果或推理提速。

这次是第二层注意力的局部重放，使用已保存的官方输入和历史缓存。它没有重新执行完整模型或 prefill。结果记录了 936 份原始文件、28,490,724 字节；这些数量和精确相等结论目前来自已退出运行的结果，仍须由独立审计器重新读取全部数据确认。此前 r1、r2 的失败记录继续保留。

服务的成功退出状态由外层在清理前保存并绑定到原 InvocationID；现在该临时服务已经卸载，进程组也不存在。根线程首次临时核对误要求服务仍加载，断言失败；随后按现有运行器原本支持的“完整保存退出凭据＋当前服务完全消失”路径重新核对，未修改运行器或把消失状态冒充退出成功。正式结束记录器会重新核验完整来源和退出链。

Qwen3.5-2B 的实际运行接口已准备完成，主任务独立复跑 **33 项针对性测试全部通过**。修正覆盖预检与正式实验编号冲突、启动后尚未确认身份的短暂状态、API 进程切换、快速失败清理、原子文件发布交错、临时目录计费，以及结束时使用真正清理对象的退出状态。这些是自有运行工具的问题，不是已经证实的 vLLM-Neuron 模型缺陷。

运行接口使用原串行锁，保持每次只运行一个模型阶段，并将完整历史来源保留在认证配置中。两组输出总预算为 2 GiB；原长解码保存文件约 274 MiB，因此模型单文件上限按实际序列化大小设为 512 MiB。原根盘／NVMe 保留线仍为 28／30 GiB。测试使用替身服务与小型临时文件，没有启动实际 Qwen 服务或读取实验张量。

正式 Qwen 对照仍需新的当前队列绑定和实机预检，并保留全部原模型验收：BF16 权重、FP32 循环状态、TP2/B4/context4096、203 份原始向量一致、冷缓存、1541 步长解码与槽位复用、质量96、全部 13 项采样控制，以及相同设置的完整 HTTP 比较。当前没有 Qwen 采样优化提速数据。

MiniCPM5 的保存数据读取接口也通过主任务独立复跑的 **9 项测试**。它按确切文件描述读取每次调用的全部张量，核对文件身份、完整长度和 SHA，并复用原比较工具。完整范围为 1,284 份 capture、77,790,564 字节；测试只用合成元数据和每份 6 字节的内存文件，完整六次调用的调度测试使用替身读取与比较。真实分析仍排在原生独立审计之后。
