# MiniCPM5 自身历史解码重放：完整加载与输出保存

MiniCPM5 的自身历史重放进一步完成了**完整数据加载器和原生驱动核心**。13 项流式加载检查、11 项驱动流程／保存检查通过；完整源码准备固定 2,363 个文件、160,634,812 字节，并保留原科学输入和验证条件。此轮没有运行新的模型，也没有新增合格提速倍数。

## 完整历史先于解码输入

加载器按每个 rank、每条配置的原顺序读取全部 14 次调用，共 2 × 3 × 14 = 84 次。预填充调用也必须读取，用于恢复连续的完整 K/V 历史；只有原第 4、5、6、11、12、13 次解码调用会输出完整重放输入。

每份记录都核对原始 JSON、整份观测载荷、三个预测观测值以及两个完整缓存。恢复出的字节和缓存历史必须逐项等于已经独立审计的记录。全过程每个 rank 保留全部 42 次调用，只向注意力重放提供其中 18 次解码；两个 rank 总计 36 次，每次四个物理请求槽位。

这防止跳过预填充历史、少读一次调用、使用另一个 rank 的载荷，或把保存后发生变化的数据带入重放。预填充仅保存预测位置，仍不能作为完整预填充输入。

13 项测试使用原元数据模板和新生成的合成字节。完整覆盖 84 次历史和 36 次解码，还检查缺失／重排审计记录、载荷哈希不一致、跨 rank 路径、原 JSON 认证失败、布局变化、部分消费及许可撤销。测试中的数值审计前置证明是夹具，不能证明真实官方参考已经审计完成。

## 原生驱动核心接入了哪些步骤

驱动要求外层已取得串行运行权、认证成功的采集和独立审计退出记录、固定输入与源码、并建立原 gloo TP2 环境。随后每个 rank 按原构造器建立完整 42 层解码模型，使用官方第二层 Q/K/V/O 逐字节校验器，再按原桶选择方法调用原注意力。

完整输入、原 `[1,4,4]` 布局、原 SDK 缓存视图、非空 RoPE 缓存和原参数验证继续由[上一份边界报告](minicpm5-layer1-decode-boundary-20261110.md)中的源码约束。每次注意力必须返回与原记录完全相同的四行 BF16 输出，且输入缓存与权重不变，才允许保存。

每份输出保存 16,384 字节；每 rank 18 份、294,912 字节，双 rank 共 589,824 字节。写出后会重新读取并核对全部字节。少一行、缺一次、重复调用覆盖旧结果、仅成功标志正确但返回字节错误，都不能形成完整结果。

**11 项驱动检查模拟了模型构造、权重校验、桶选择、注意力和输入流**。它们证明调用顺序和输出保存的拒绝条件，未执行原生计算，不能用作注意力输出复现证据。测试首次因合成夹具中一个缺失空格的条件表达式失败；修正测试后 11 项通过，原运行源码未因此改变，失败记录保留。

## 距离实际执行还缺什么

真实完整采集和独立保存数据审计仍须先执行并记录实际退出。外层串行运行器、TP2 rank 入口和具体运行计划还要接入这些已完成的实际记录，实施资源、存储、输出与进程清理约束。当前驱动是核心函数，不是可独立启动的模型实验。

实际运行时必须比对八个官方 BF16 分片，并完成全部 36 次自身历史解码、完整四行输出的逐字节复现；完成后才能做配对历史因果实验。此前原 CPU 对照 29／32 数值通过、top1 32／32；两个 BF16 候选 28／32、top1 31／32，拒绝结论均不变。

冷缓存至 4096、长解码、请求槽位复用、生成／随机数／停止／文本／质量、真实 HTTP 四并发和配对性能仍是整模型要求。其他模型继续按原 15 个家族范围推进。Nemotron r11 原会话仍在整模型编译；没有重复启动实验。
