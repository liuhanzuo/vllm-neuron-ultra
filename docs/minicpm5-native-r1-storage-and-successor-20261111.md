## 实际失败与空间恢复

2026-11-11 14:22 UTC，根盘可用 30,146,777,088 字节；14:25 UTC 核对时为 29,438,353,408 字节，低于 30,064,771,072 字节的原门槛。外层真实工具会话 `88265` 以退出码 1 结束，终态记录 `0f7129`。失败发生在原两小时上限之前，不能写成超时失败。空间下降的具体写入来源尚未归因。

外层、协调、原生三个原始进程均已消失；原服务无进程、无任务，其控制组已不存在。输出保留九份启动及失败文件，包括原准入、来源认证、进程身份、失败原因和清理记录；没有原生张量、调用日志或成功结果。独立失败记录程序已启动，正重新验证原来源与退出证据，其完成状态仍待真实工具退出确认。

按用户不扩容的要求，清理了两份未使用的旧 Claude 可执行文件、未使用的 Codex 0.167.0 安装目录，以及可重新生成的 APT 二进制索引缓存。清理在原串行锁内执行，逐项保存摘要，检查当前版本指向和进程打开／映射情况。共释放 **1,181,696,000 字节**，根盘回到约 **28.52 GiB** 可用。当前工具版本、模型权重、已安装推理环境和实验结果未删除。

第一次清理预检查因旧安装目录内的链接而退出 1，未执行删除；后继只接受那个已知的内部链接，实际清理退出 0。两次真实退出均保留。释放空间不改变原保留线，也不证明后续长任务的空间一定充足。

## 后继启动程序改了什么

之前的启动改进将整个实验历史复制成只读快照。审阅发现，同一原生数据树可通过三个字段再次到达，旧实现会重复展开这些共享对象；退出检查还会构造一次临时完整快照。

新版本只为源码校验循环实际使用的计划、契约、分类结果和输出清单建立只读快照。共享容器只复制一次。完整历史和所有旧可变对象仍在进入、退出时逐段计算相同的 JSON 摘要，检测变化；不再生成完整历史的快照或整份序列化字符串与字节副本。每份源码的摘要、锁、存储和输出目录检查、失败后禁止进入模型执行，以及原生依赖认证均保留。

主任务的 **12 项**内存与接入测试、另一审阅者的 **4 项**独立测试通过。一个小型共享历史合成样本中，摘要计算的 Python 临时内存峰值从 2,039,368 字节降至 21,984 字节。这只是内存微测，不是完整进程峰值、实际启动耗时或推理提速。原固定计划校验仍会序列化部分数据；完整历史上的资源使用尚未测量。

准备程序也有两处接入修正：旧版固定选择运行器 v7，增加新文件不会切换实现；旧版还一律拒绝原生审计源码，与已经实际执行过的退出记录程序发生冲突。后继选择运行器 v9，并仅允许完整历史记录能够认证的已执行审计源码，保留旧来源、失败结果和全部历史行。未来审计版本、摘要冲突和无真实退出支持的来源仍会被拒绝。作者和主任务分别执行 **10 项**准备测试，通过。

这些修改均保存在独立后继源码中，尚未生成新模型准入或实际运行。原模型、权重、BF16、16 GiB 内存上限、两小时服务上限、冷缓存 4096、长解码、请求槽位复用、质量 96 与配对 HTTP 验收要求不变。
