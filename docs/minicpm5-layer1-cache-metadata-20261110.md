# MiniCPM5：第二层当前输入一致，历史 K/V 已不同

对完整保存记录的核对进一步缩小了问题范围。比较原 CPU 对照与“仅预填充使用第 0 层完整 BF16 投影”的候选：六次解码调用的第二层归一化当前输入哈希一致，位置与掩码记录一致，但进入第二层之前的 K 和 V 缓存哈希均已不同，首个已记录预测阶段差异仍在第二层注意力。

这使“预填充差异通过历史 K/V 影响后续解码”成为明确的下一步实验假设，**还没有证明因果，也没有证明缓存实现有 bug**。

## 核对范围

读取并验证 95 份原始 JSON，共 28,101,099 字节，包括完整三方案 × 两个 rank × 14 次调用，共 84 份调用记录；检查 78 个相邻调用的缓存衔接。三个方案两两比较，保留全部 32 帧、原槽位映射和第 7 次调用的请求组切换。

每份调用的 forward 前后输入缓存元数据一致；每条轨迹上一调用的输出缓存与下一调用的输入缓存数值描述和哈希一致。三个方案的七个当前外部输入及全部 42 层的掩码/位置路线记录均相同。原 SDK 源文件哈希也与原规格一致，确认缓存索引 `2×层号` / `2×层号+1` 对应 K / V。

两个 rank 的预测结果是重复副本，不能把六次解码算成十二次独立实验。

## 原对照与仅预填充候选

| 已保存的记录 | 全部六次解码调用 |
| --- | --- |
| 七个当前外部输入 | 相同 |
| 42 层掩码和位置路线 | 相同 |
| 第 0 层 K/V 缓存哈希 | 相同 |
| 第 1 层归一化当前输入哈希 | 相同 |
| 第 1 层历史 K 缓存哈希 | 不同 |
| 第 1 层历史 V 缓存哈希 | 不同 |
| 首个已记录预测阶段差异 | layers.1.self_attn |

第 0 次调用前，双方全层缓存相同；第一次预填充后，第 1–41 层缓存已不同。其后这些全张量缓存哈希保持不同。哈希覆盖完整缓存张量，尚未定位到被当前注意力读取的具体槽位、位置或数值大小，因此不能把全部缓存差异都判作当前输出差异的来源。

原始实验只保存了缓存元数据，没有完整缓存原始张量。现有第 0、41 层选定观测点的数值结果不变：原 CPU 对照通过 29/32 帧、top1 32/32；两个投影候选各通过 28/32 帧、top1 31/32，仍被拒绝。没有恢复性能比较，也没有新增提速倍数。

## 下一次实验怎么区分原因

保持原 BF16 权重、14 次调用/32 帧、两 rank 和完整槽位轨迹，先验证新增观测不会改变原输出。可在 forward 结束后导出现有观测器已捕获的第二层归一化输入、注意力输出、层输出，以及经检查未被 forward 修改的输入 K/V，避免在 forward 内再增加观测钩子。

随后固定第二层当前输入、位置、掩码与计算路径，分别使用自身历史和配对历史进行独立诊断，比较数值误差及是否改变已有端点；完整模型原方案必须继续保留。这个设计尚未执行，也不能用一次局部缓存替换的结果替代全部模型验收。

## 分析脚本问题与测试环境更正

首次元数据分析在比对旧诊断时失败，原因是 Python 字典的 `None` 键序列化后成为 JSON 的 `"null"` 键；逐项核对确认，JSON 往返规范化后所有原诊断字段完全一致。后继 v2 只修正这次表示形式比较，原失败、原脚本和原诊断均保留，未改动模型数据或通过门槛。

另更正已发布 MiniCPM5 v3/v4 测试记录中的文件名：`py312` 那组实际运行的是 `/usr/bin/python3`，当前确认版本为 **3.10.12**；另一组是 vLLM-Neuron 虚拟环境，同样为 **3.10.12**。因此正确表述为“两个 Python 环境”，不能称作“Python 3.10 与 3.12”。66 项 / 70 项测试执行结果不变，旧文件保持原样并由独立更正记录说明；此更正不扩展到 Nano 的测试记录。
