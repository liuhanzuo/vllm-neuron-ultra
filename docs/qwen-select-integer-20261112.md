# Qwen 缓存选择：12 次设备对照完成，整数路径保留全部位模式

三张新图、两套输入、两种槽位映射的 **12 次真实 Neuron 调用已完成**。单次 BF16 选择仍会改变负零与 NaN；图内按 S16 位模式选择和直接使用 S16 输入的八次调用，输出全部逐字节一致。工具 session `22831`、terminal `a07595` 实际退出 0；完整输出复核、进程退出、服务清理和原串行锁检查完成。本轮没有新增模型提速，已有结果见[全部模型提速表](model-speedups-20261112.md)。

## 实测结果

每个输出包含完整 98,304 字节，形状为 `(4, 3072, 4)`。两套输入保留原来的特殊值；槽位分别为全空闲 `[-1,-1,-1,-1]`，以及只将 update 第 0 行写到 cache 第 3 行的 `[3,-1,-1,-1]`。下表是完整输出相对原始字节拷贝期望值的不同字节数。

| 实际编译路径 | 原输入／空闲 | 原输入／单槽更新 | 补充负 NaN／空闲 | 补充负 NaN／单槽更新 |
|---|---:|---:|---:|---:|
| 单次 BF16 select | 139 | 136 | 155 | 148 |
| BF16 输入 → 位重解释为 S16 → 选择 → 位重解释回 BF16 | 0 | 0 | 0 | 0 |
| S16 输入、S16 选择与输出 | 0 | 0 | 0 | 0 |

三路沿用原编译参数，包括 `--auto-cast=none`、`-O2`、`--lnc=1`，均重新编译、保存、重新加载并在 core 0 调用。整数路径使用位重解释，**没有将浮点数数值转换为整数**。实际输入在调用后保持不变；没有计时、模型权重加载或整模型推理。

主任务重新读取全部 12 份输出、输入和完整差异偏移，再按槽位映射独立构造期望结果。BF16 路径的四次调用分别有 5、4、5、4 个负零变为正零，以及 134、132、142、138 个 NaN 变为正 `0x7fc0`；没有其他类型的 word 变化。两条整数路径没有任何 word 或 byte 变化。[逐 word 完整记录](evidence/qwen-select-integer-20261112/research/qwen35-slot-select-probe-r2-root-word-analysis-20261112-v1.json)保留全部位置和前后位模式。

## 对原因和修复方向的意义

实际 compiler-input HLO 的独立解析确认：

| 路径 | HLO 指令数 | 有效 select | 位重解释路径 | 数值 convert |
|---|---:|---|---:|---:|
| 单次 BF16 | 19 | 1 个 BF16 | 0 | 0 |
| 图内整数选择 | 70 | 4 个 S16 | 3 | 0 |
| 外部整数存储 | 61 | 4 个 S16 | 0 | 0 |

单个 BF16 select 就能复现变化，说明不需要原先四层选择链才会出现这个现象。图内整数选择保留 BF16 输入输出，同时保持全部原始字节，为缓存位拷贝提供了可继续验证的实现方向。结合[此前 NKI 条件拷贝和纯 DMA 的六次对照](qwen-slot-special-values-20261112.md)，当前证据将问题缩小到 BF16 选择所走的编译执行路径。

这些是前端 HLO 和实际输出证据，尚未定位具体编译器 pass 或最终机器指令。特殊值对照也不能直接说明正常有限值上的模型质量或性能。两条整数路径只通过本次四组输入，不能据此宣布通用缓存实现或整模型合格。

后继已完成单独版本整数参考路径的 **八布局、32 图、46,368 次调用**，覆盖全部槽位映射、持久状态和旧值读取；实际退出及独立复核通过，详见[完整矩阵与算子计时](qwen-integer-reference-matrix-20261112.md)。整模型数值、冷缓存、长解码、请求槽位复用、quality96 和匹配 HTTP 门槛继续保留。原 BF16 失败不会被后继结果覆盖。
