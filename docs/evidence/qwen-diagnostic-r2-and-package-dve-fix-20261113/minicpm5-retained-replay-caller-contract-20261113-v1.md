## Failure limits and separate retirement

An outer failure before admission or before a first actual running ACK is not a completed pair/replay run. Root retains its actual tool exit and available partial evidence; this observer path cannot turn a missing running/admission/terminal receipt into completion. It creates no new idle claim. A worker disappearing before its exit is captured, wrong invocation, wrong session, changed source, unknown later handoff, partial JSON, failed scientific comparator, or nonzero observer exit never qualifies storage retirement.

A known attempted service that exits before any live worker was observed can be authenticated by its exact typed command/nonce/invocation and drained as a failed attempt. It has no successful worker result or captured-owner exit claim. Already recorded cleanup can be safely re-observed after the service unloads; unexplained disappearance before recorded cleanup remains an error. Unknown unit invocations are never stopped.

Retirement remains a separate future admission after genuine actual paired verification, full replay equality, independent observed exit/drain, complete updated source/input compatibility, and exclusive namespace-writer proof. The previously accepted transaction's exceptional recovery limit is unchanged: complete intent followed by absent done-file can be recovered; partial intent/done JSON remains preserved and requires an independently reviewed fresh-journal migration. That migration is not implemented or authorized here. No `.pt` files, keeper bytes, original producer rows, metadata identities, old source files, or old results are changed.
