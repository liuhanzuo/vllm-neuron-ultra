# Dory Stage A 源码核心交付

本次完成六次原始宽调用的完整 input / mixer output / residual output 观察器、流式存档核心、独立字节校验核心及 43 项合成测试。实际原生模型执行仍为零；未读取任何旧张量、权重或原始二进制存档。

此交付建立在已接受的设计与 root 审阅上，读取了 v425 终态以确认任务边界。没有创建运行锁、准入、runtime builder、队列或 continuation handoff。Nemotron 的完整 r12 重跑仍由主任务串行推进；本次之后暂停进一步执行。

## 已实现的范围

- dory_stage_a_capture_core_v1.py 验证原 89 次调用 / 87 点 / 七个失败的设计范围，从绑定的原始 JSON 选出事件 1、4、7、9、11、6179。模型由调用者传入，代码没有模型构造函数或替代模型。六次完整前向始终保持 2060、2060、23、127、511、31 行。
- 观察器对 72 层的 112 次实际访问安装前后 hook，对层 32、56 的原 mixer 安装 hook。全部 hook 返回 None，不重写 attention、slerp、alpha、归一化或模型 dtype，因此不会省掉原 BF16 内层舍入。Stage B/C 的干预算术尚未实现。
- 每次保存三个目标 visit 的九个完整矩阵，并验证全部 224 个原抽样边界、hidden、logits、56 路 K/V 的原始字节哈希、输出 top-1 及 281 次 oneDNN 投影。记录实际 shape、stride、storage offset 与 dtype。
- dory_stage_a_archive_core_v1.py 向调用者传入的三个流同步写入完整目标、224 个抽样控制和 114 个原始输出。逐块限制大小、对齐与总量，检查 BF16 / FP32 非有限值，记录每个张量及整份存档哈希。发生部分写入、截断或迭代异常后不能继续或完成。
- dory_stage_a_saved_core_v1.py 独立定义 Stage A 形状，不导入 producer 的存档实现。验证所有实际字节、有限值、偏移、长度及哈希；还从新完整目标矩阵中抽取原选定行，验证它们与旧控制一致。未被抽样的行同样进入完整张量哈希。

层 32 的两个循环分别要求原缓存 32 与 104，层 56 使用 56。开始前必须有全部 56 个空原生历史，position 为 0；观察器本身不会清空或重新绑定历史。事件 6179 标注 slot 3 / epoch 2，但这次独立空缓存补采不证明生产槽位复用正确。原事件 6181 仍是 slot 3 复用之后 slot 1 继续运行。

## 合成测试与真实证据的边界

使用 stdlib 与少量临时内存字节，无 Torch、NumPy、模型载入或磁盘二进制输出。原 JSON 用于核对实际六次调用的身份、完整形状及旧控制描述；合成模型仅测试 hook 次序、记录范围和拒绝逻辑。合成 emitter 返回受控描述，不是数值正确性的证据。

43 项测试全部通过，首次实际测试退出码为 0，测试执行耗时约 0.70 秒，外部工具 chunk 为 a118eb。测试包括：

- 六次调用完整行数与完整对象传递，9 / 224 / 114 个记录集合和原 281 次计数。
- 错误调用顺序、缺失或重复 mixer、错误 loop 缓存、旧缓存残留、错 token / position、输入缩水、dtype 改变。
- 原抽样边界、缓存、top-1 或投影次数不一致时失败。
- 原模型异常不被吞掉，异常后的实例不能重试；hook 部分安装失败会清理已安装 hook。
- BF16 / FP32 NaN 与正负 Inf、未抽样行篡改、错哈希、错行选择、错 offset / shape、缺张量、重复 / 错序记录。
- 截断、尾随字节、部分写入、产生字节的迭代器中途异常、超预算、过大或未对齐块。

测试与 root 提醒后的文件操作均通过实验根目录的 nemotron9b_package_window_v27.py --observe --timeout 45 -- 命令执行，避开已声明的性能窗口。未占用为 Nemotron 预留的 49 GiB NVMe。

## 后继预算：新增独立抽样控制

旧接受设计保持不变。为了让独立 reviewer 能检查全部 224 个边界，而不仅相信 producer 的哈希，新方案把六次调用的 70 个抽样行完整另存：

70 × 224 × 2560 × 2 = 80,281,600 bytes，约 76.56 MiB。

| 计划项目 | 原始字节数 |
| --- | ---: |
| 六次原始 hidden / logits / 全 56 路 K/V | 1,165,094,912 |
| 三个 visit 的完整 input / mixer / residual | 221,736,960 |
| 新增 224 个边界抽样控制 | 80,281,600 |
| **Stage A 总量** | **1,467,113,472** |
| **Stage A/B/C 后继总量** | **2,046,031,872，约 1.906 GiB** |

原提出的 3 GiB 新 NVMe 预算仍能容纳这些原始记录，但还必须保留元数据、日志及余量，并在新执行前重新核对实际容量。根盘 28 GiB、NVMe 30 GiB 的空闲下限不能借用，Nemotron 预留 49 GiB 也不能借用。当前只是计算结果，没有新增张量文件或有效运行准入。

## 尚需解决的接入条件

1. **原生适配器**：实现并冻结 describe / integers / select / top1 / iter_bytes，使用原有 CPU PyTorch、BF16 和逻辑行序。验证切片、非连续 stride、空缓存之后的真实行形状与完整输入没有被伪造或缩减。合成测试无法证明这些原生接口。
2. **原模型与身份**：调用原完整官方构造、原 507 个权重张量及 399 个物理参数的完整映射；保持 182 个原 oneDNN linear、56 路 ReferenceAttention 和原 RoPE。补齐源码、环境、权重、原档案、原进程实际退出及当前终态的身份绑定。本核心没有声称已证明这些条件。
3. **新存档的持久化与失败保留**：调用者负责独占创建文件、实际容量限制、flush / fsync / close、记录部分文件和成功退出。ArchiveWriter.finish() 只代表传入流已接受全部字节，不等同于文件落盘或独立复核成功。
4. **完整独立审核器**：producer 实际退出后，以稳定且有界的文件句柄调用字节 verifier；绑定每次调用的元数据、实际源布局和三份新存档，审计六次调用与完整原输出集合。当前只有校验核心，没有可运行的审核程序。
5. **六次调用之间的原生隔离**：调用者以原始完整模型和独立诊断 owner 清空 / 绑定 56 个缓存，再交给观察器。观察器在入口拒绝任何旧缓存；不替调用者做请求生命周期清理。
6. **资源与串行执行**：在 Nemotron 实际完成后重新测算完整模型初始化、原生库和存档重建的内存、CPU、墙钟和文件上限，验证最新实际终态和性能窗口。当前没有 native admission 或 executable runner。
7. **后续推理结论**：完成 Stage A 原生采集及独立复核后，才推进全部 87 点的 Stage B/C。原 cosine ≥ 0.995、max_abs ≤ 2、KL ≤ 0.02、冷缓存、长解码、槽位复用、质量和 HTTP 门槛仍保留。

Dory 仍有原七个 FP32 数值失败。本次没有新的模型通过结论、根因认定或提速倍数。
