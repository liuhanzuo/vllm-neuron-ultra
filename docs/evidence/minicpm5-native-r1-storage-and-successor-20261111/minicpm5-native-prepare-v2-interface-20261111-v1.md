## Historical allowance

Before merging static or loaded additions, preparation and bind authenticate the complete current catalog through the frozen `serial_catalog` function using the supplied authenticated reader. All original catalog rows, terminal references, tools, owners, units and source maps are retained. Duplicate terminals, conflicting hashes, incomplete scope or non-idle handoff fail as before.

Only the following concrete root terminal schemas can witness historical auditor pins:

1. `minicpm5_native_model_exit_recorder_actual_exit_v1`: root observer, `actual_tool_exit_observed=true`, exact actual tool, original owner in the catalog, `owner_gone=true`, and false self-exit/qualification/speedup flags. Its existing `model_exit` must bind `ended.recorder`, `recorder_spec`, `recorder_review`, and `recorder_source`. The root terminal's `recorder_spec/review/source_extension` must agree with those hash references and the exact executed recorder spec/review. Both successful and failed model result schemas are supported. Recorder's own actual tool may be a call or session, with its true integer exit code 0..255; nonzero is retained and is not promoted.
2. `minicpm5_native_independent_audit_actual_exit_v1`: exact schema and fields from the separately reviewed saved-data entry interface, original lock, actual successful session/tool, gone original owner, exact `audit_spec/audit_review/result`. The authenticated output must bind its auditor owner, spec/review, model/recorder references and diagnostic flags. This existing contract supports exit 0 only; a failed auditor has no accepted external failure schema in this delivery.

Both paths require an exact reviewed source extension, original limits, producer output path, full owner argv binding the script/spec/review hashes, and every executed extension pin retained at the same hash in that catalog row. Recorder permits the actual frozen imports auditor v2 / core v2 / core v3; auditor permits auditor v2 / core v2. The whitelist is for these precise local paths, not versions matched by the general rejection regexp. A historical spec listing a future auditor does not make that future auditor executable history.

Every auditor/core pin anywhere in the merged catalog or new static/loaded extension must equal an exact pin from those witnessed executions. Historical rows from unrelated later work may retain such already-witnessed pins. No independent standalone pin assertion, source-review-only record, arbitrary terminal schema or new future version grants permission. Current source bytes and loaded modules are still authenticated by the original preparation checks.

## Explicit rejection limits

- Negative actual tool exits remain negative. Frozen serial validation accepts 0..255, so a negative exit is rejected, never normalized to 137 or omitted.
- A failed recorder that did not write an authenticated `model_exit` cannot satisfy this particular witness path. Its catalog row stays intact and preparation fails; no replacement failure schema is invented.
- A future/unexecuted auditor/core, changed hash, mismatched source review, owner, command, result or actual tool fails. There is no blanket name waiver.
- The success-only external auditor schema cannot be used for failed auditor history.
