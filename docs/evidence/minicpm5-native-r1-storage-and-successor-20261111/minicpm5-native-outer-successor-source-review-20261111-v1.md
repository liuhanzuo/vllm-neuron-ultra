## Accepted minimal memory successor design

Root accepted the following design and owns seal v3/context v3/runner v9 implementation. The phase actually consumes only the immutable context plan, contract, partition, and native runtime catalog. Seal only those objects, optionally sharing a private per-phase identity memo across them. Do not retain an unused immutable full resolved/permit history. Complete mutable aliases remain bound at both entry and exit using exact-JSON validation and streaming SHA256.

Streaming bytes must be exactly the existing `json.dumps(value, sort_keys=True, separators=(',', ':'), allow_nan=False).encode()` bytes, including default `ensure_ascii=True`. Use the standard encoder's `iterencode` and update the hash per UTF-8 chunk; establish equality on representative scalar, Unicode/escape, finite-float, nested, insertion-order, and shared-DAG mocks against the existing digest. This removes the whole string/bytes temporaries, while serialization still visits each logical occurrence to preserve the original digest. It must not substitute a DAG/identity digest.

Exact-type validation can memo completed input-container identities within each traversal while checking active identities first to reject cycles. At exit, validate/hash each complete original alias without creating another immutable tree. Keep the original classifier, original lifecycle binding, source partition checks, every text/python hash, lease/storage/output checks, restoration/receipt ordering, permanent failure latch, and immediate successful cleanup. Mutable alias changes anywhere in history/permit still change the full original-value digest; identity rebinding guards remain separate. No broad caching framework or frozen-file mutation is needed.
