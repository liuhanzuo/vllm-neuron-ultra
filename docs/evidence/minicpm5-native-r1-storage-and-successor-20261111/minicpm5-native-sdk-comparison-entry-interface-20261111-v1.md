# Saved-data comparison entry: external native audit exit contract

Source-only design, 2026-11-11. No actual terminal values are generated by this document or the comparator. Root records the actual completed native auditor tool session and supplies the resulting immutable JSON reference. The original SDK model exit remains 1.

## Exact external native auditor exit JSON

The object has exactly these fields:

- `schema`: `minicpm5_native_independent_audit_actual_exit_v1`.
- `reviewer`: `/root`.
- `audit_spec`, `audit_review`, `result`: exact `{path, sha256}` references to the executed frozen auditor's spec, independent source review, and completed audit output.
- `owner`: the complete original auditor process identity, exactly equal to the output's `auditor_owner`; its `argv` is exactly `python3 -B <frozen auditor_v2> --spec <path> --spec-sha256 <sha> --review <path> --review-sha256 <sha>`.
- `actual_tool`: exactly `{kind: tool_session, session_id: positive integer, terminal_chunk: 6–64 lowercase hexadecimal characters, exit_code: 0}`. Boolean integers are rejected. A tool call cannot substitute for the requested actual auditor session.
- `actual_tool_exit_observed`: true.
- `exact_owner_gone`: true. The entry additionally rechecks this exact owner under the original retained lock; the field alone is not process proof.
- `lock_identity`: the original lock identity `{device: 66306, inode: 8294421}`.
- `self_exit_claimed`, `full_model_qualified`, `new_speedup_claim`: false.

The result must match the original native post-exit independent audit schema and spec/review/model-exit/recorder-exit bindings, successful full 24-frame / 72-call / 936-raw audit, and preserved external-exit-pending and diagnostic flags. The comparator authenticates the external audit terminal before any model result or comparison payload can become usable. It does not create another recorder chain.

## Existing catalog compatibility

`minicpm5_layer1_operator_sdk_runtime_completion_v3.serial_catalog` already accepts a nonempty producer-terminal JSON referenced by an exact catalog row. It validates the row's existing `terminal`, `tool`, `owners`, `units`, and `source_sha256` fields. No catalog schema change is necessary. The new entry checks that the current complete catalog retains every row from the native audit's original catalog, plus the exact native model, model-exit recorder and independent native auditor terminal references, tool handles and owners. Source hashes remain in the original additive union. Native audit session must differ from model and session-based recorder handles. Current freshness and all historical owners/services are checked using the existing machinery.

## Single saved-data entry

A small independent entry will accept a reviewed spec containing `native_audit_exit`, `current_serial_catalog`, additive `source_extension`, fresh output path and unchanged audit resource limits. It reuses frozen auditor_v2's lock acquisition/release, Lease, AuditGuard, Metadata, recovery completion, overlay resolve, original terminal core, complete physical-pair checks and NativeAuditIO. Native payloads and 72 arm JSON files go through NativeAuditIO after final inventory; SDK payloads use the existing authenticated SDK payload reader. No model or operator is reexecuted.

The SDK cases use the original pure `boundary.boundary()` on exactly 12 authenticated original anchor-call JSONs, selected from the completed original collector plan in rank/call order. Every case binds its original `source_case_sha256`; each rank retains and validates the complete original `source_stream` metadata, including 42 historical calls / 18 decode calls and 12 skipped non-anchor calls. No historical payload is reread solely to rebuild cases. The 12 extra call JSON reads and existing authentication metadata reads are outside the comparator's exactly 1,632 reads (936 native raw + 624 SDK raw + 72 native arm JSON).

The output contains the entire previously reviewed bounded lossless report envelope plus a small wrapper binding original audit/source/catalog references and original flags. Both inner envelope and complete wrapper, including JSON overhead/newline, remain strictly below the original 2 MiB file cap. Root records the comparator's own actual tool exit separately. Failed or unfinished native/audit evidence cannot yield a comparison success.

All existing model/weight/BF16, native 16 GiB/14 GiB/7,200 s, 128 MiB native / 256 MiB total output, root 28 GiB / NVMe 30 GiB floors, source closure, cold-cache, long-decode and request-slot-reuse constraints remain unchanged. Entry computation uses the original standalone audit limits (2 GiB address space, CPU 600/605 s, wall 900 s, CPU 6, nice 19, 2 MiB output file). Source/mock acceptance does not admit a real launch.
