Only the completed split-v4 artifact is eligible: `/mnt/nvme/neuron-artifacts/latest-20261031-qwen35-2b-text-bf16-cpu-tp2-b4-ctx4096-split-v4`. Its saved model.pt inode/size/mtime/ctime anchor comes from the frozen sampler source delivery, and split-v4 terminal evidence confirms 12 compiled graphs; r10 later qualified the same artifact. The scanner never opens model.pt or any other regular payload. Root still must prove that the tree is outside active scopes and provide its fresh root lstat identity under the existing serial guard.

The historical workdir was `/tmp/nxd_model`, and the launch selected `/mnt/nvme/neuron-cache`. Both are shared, with no exact preserved completed-tree identity sufficient to attribute their present allocation to split-v4. The scanner refuses these paths and every other unlisted target before filesystem IO. No scan of those trees is implemented. This evidence gap remains explicit.

Call `inventory(TARGET, expected_root_identity, execution_guard)` from the existing root-owned metadata child and persist its returned dictionary with the existing output mechanism. `expected_root_identity` is the pure `metadata(os.lstat(TARGET))` mapping obtained by root under admission. The guard returns `admitted=True`, `exclusive=True`, `completed_tree=TARGET`, `target_not_active=True`; these are root's actual proofs, not facts created by this helper. The helper has no CLI, lock, scheduler, subprocess or current-history lookup.

The accounting follows dory_build_artifact_inventory_v1's stat-row digest and unique-inode method. It opens only directories with O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC, walks each absolute ancestor relative to an already-held directory descriptor, lists with scandir(fd), and stats entries with dir_fd plus follow_symlinks=False. Every opened descriptor is closed on success and exceptions. Child directories cannot cross filesystems; malformed names, special files, repeated directories and changed identities fail. Regular files and symlinks are never opened or followed. Symlink inode blocks count toward the selected tree; link targets are neither read nor charged.

Two full metadata passes must match exactly. The result includes entry counts/types, unique-inode allocated bytes (st_blocks*512), path-counted allocation, maximum logical and allocated regular file sizes, top eight by each size, external hardlink counts and a digest of every complete stat row. Hardlinks are charged once and must have consistent metadata. Sparse logical sizes are not mistaken for allocation. This is allocation evidence, not content-integrity proof, current-peak compile storage or a deletion/reclaimability authorization.

Fixed limits are 65,536 entries, depth 32, 16 MiB complete metadata and 120 seconds. Root supplies its existing serial ownership, finite child memory/CPU limits, actual external exit and drain evidence. The helper cannot establish those independently. Eleven mock tests pass without any real filesystem target scan: they replace all scanner filesystem functions with an in-memory descriptor model, block regular file open, and test link/race boundaries, root/model anchors, sparse/hardlink accounting, changing passes, wrong shared targets, missing admission and all bounds. Source AST checks restrict filesystem calls to directory open/close and stat/fstat/scandir.
