The generated domain accepts a later catalog only if its complete first 164
rows exactly equal the authenticated r2 catalog. This preserves history while
adding permission only for the fixed 38 r2 source pairs. It is not arbitrary
future-domain acceptance: a new external r3 helper path is still rejected by
the original checker, even if a later mock catalog has an extra row.

If geometry r3 runs before Mini, root must wait for its actual independent
terminal and finalization. Then author a narrow successor from the real

actual owner/unit/lock/status records. Preserve the existing exact164 prefix
and r2 failure. Authenticate each new external path/hash in that actual ended
row; do not permit a directory, wildcard, future helper name, or draft finalizer.
Update the shared domain module and mechanical source list/wiring as needed,
then redo the real complete Mini prepare/acceptance. This r2 generator must not
be used to claim that future r3 source-domain compatibility is already proven.
