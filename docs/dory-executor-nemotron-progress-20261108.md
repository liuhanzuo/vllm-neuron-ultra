## Dory：下一步实际计算已具备受检的执行代码

执行器先要求 Nemotron 实际终止、全部计划任务完整记账，以及结束记录生成进程的真实退出，再获取串行锁。原来的 925 条服务与 182 条进程历史不会被覆盖；结束记录生成器的 13 项检查已通过，但尚未生成未来的 978 条完成记录。

Dory 将使用固定的 CPU PyTorch 2.9.1 环境、单线程及 CPU 6，导入前校验解释器、标准库和 11 份依赖安装清单对应的文件。执行时关闭自动 site 加载，避开可编辑 Transformers 路径及启动钩子。当前只解析了安装清单、检查文件元数据并估算记录大小，**尚未执行运行库内容核验或导入 Torch**。

边界保持为 8 GiB 虚拟地址空间、600 秒 CPU、900 秒运行时间、16 MiB 输出和 28 GiB 根盘剩余空间。8 GiB 是地址空间上限，不是实测 RSS 或 cgroup 内存限制，其充分性仍需实际运行验证。禁止原生算术发起 Python 子进程；异常子进程只按实际归属清理，无法清理时保留串行锁等待恢复。

39 项检查覆盖活动前序任务、缺失真实退出、被改动的源文件/解释器/安装清单、删减比较条件、缩短原缓存、放宽资源预算、输出链接与特殊文件、输出超限、重复覆盖结果以及子进程清理。测试中使用的模拟终止记录不构成真实运行证据。完整安装文件清单预计约 5.31 MB，低于单个元数据 8 MiB 上限。原始草稿保留；结束记录测试曾因合成样例缺少必需字段失败，已明确记录。

实际科学范围保持：两个 theta、FP32/BF16、两组输入、Q/K、六个位置，共 96 种条件；无采集与有采集各运行一次，共 192 次比较。原 262,144 位置缓存不缩短，保存 53 个完整张量、2,230,320 字节，要求两轮一致及有限值、数值与字节全相等，再由独立标准库程序重放。细节见[采集与复核设计](dory-rotary-capture-20261108.md)。

Dory 仍没有实际原生数值结果、官方 dispatch 证明或原权重整模型基线。此执行器不是性能优化成果；其作用是让下一次实验可控制、可复核，避免再把源码检查误认为模型通过。原生和 Neuron 基线、两次循环、56 份历史、停止 ID 2/11，以及冷缓存、长解码、槽位复用和质量门槛继续保留。

## Dory：实际退出后再次复核，才进入下一项实验

新增完成记录工具要求真实工具会话的退出码、原进程身份和固定请求/源码审核记录，并重新检查 Nemotron 全部前序任务已退出、串行锁可取得。它不启动或重启任何模型。若 Dory 写出完整结果，工具将在原生进程退出后，再次独立读取原 53 份完整张量（2,230,320 字节），复算全部 96 组比较，并要求复核结果与运行中保存的独立复核完全一致。

独立运算仍只利用保存的旋转系数重放乘加，不重新计算三角函数，不执行官方模型调度或加载原权重。即使这一步通过，也只记录局部算术通过，不能把 Dory 原生整模型、Neuron 基线或提速标成合格。

原 r6 的全部 978 条计划服务记录、先前进程、来源哈希、释放记录和所有模型结论必须原样保留；只追加实际 Dory 进程与本次完成记录进程。后者不能宣称自己已经退出，下一次实验仍须核对它的真实退出。非零退出永远不算成功；若进程被终止而未能保存 Python 失败文件，记录“原因未知”，保留真实退出码，不编造故障原因。原先 MiniCPM5 r2 的具体例外记录继续保留。

40 项源码和模拟数据检查通过，覆盖丢失前序记录、改写旧失败、伪造通过、错用进程或请求、缩小保存数据范围、缺失实际退出及重复覆盖文件。首轮 36 项测试也通过，后补 4 项边界检查；两轮不累计成 76 项覆盖。测试没有执行 Dory 原生计算、读取真实张量或生成未来完成记录。实际执行还需绑定当时的真实退出和单独源码审核，并受单核、2 GiB 地址空间、300 秒 CPU、600 秒运行时间及 28 GiB 根盘余量约束。

新 MiniCPM5 执行器仍需接入真实的 Dory 完成记录与已准备的完整输出复核，不能直接拿旧 r3 执行器启动新采集版本。
