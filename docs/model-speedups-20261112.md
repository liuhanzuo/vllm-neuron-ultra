# Trn1 已测模型提速总表（2026-11-12）

目前有两个模型完成了指定范围内的 BF16 配对验证；另有四个早期模型的 INT8 历史性能结果，以及 Qwen3、LFM3、Granite 的主机开销优化测量。以下倍数均为候选吞吐量除以同一工作负载的参考吞吐量。不同基线、精度和请求长度的倍数不能相乘，也不能据此比较模型质量。

## BF16 配对结果

两组均为 Trn1、TP2、物理解码 batch 4、prefill batch 1、context 2048，使用同一模型的参考适配器作为基线。该基线包含模型移植代码，不能称为未经修改的上游 vLLM-Neuron。数据为三轮暖机后的 HTTP 吞吐量中位数，含 prefill、decode 与客户端开销，不含编译。C4 指四个并发请求的总吞吐量。

| 模型与优化 | 短输入 128 / 输出 512：单请求 / C4 | 中输入 512 / 输出 128：单请求 / C4 | 长输入 1536 / 输出 128：单请求 / C4 | 随机采样 128 / 512：单请求 / C4 | 混合长度，最多 C4 |
|---|---:|---:|---:|---:|---:|
| [LFM3-1.7B：NKI 条件缓存写入](lfm3-results-20261107.md) | 2.02× / 1.80× | 1.87× / 1.68× | 8.51× / 6.70× | 1.99× / 1.72× | 5.92× |
| [SmolLM3-3B：NKI 缓存读取与写入](smollm3-results-20261105.md) | 8.16× / 8.05× | 8.08× / 7.80× | 8.00× / 7.51× | 7.13× / 5.31× | 5.50× |

LFM3 两侧均使用相同的快速 CPU sampler，因此此表衡量缓存写入优化的增量收益。原数值、冷缓存、长解码、槽位复用和质量检查通过；96 条质量输出全部相同，两侧均为 63/96。8.51× 来自较慢的长输入参考路径，不代表所有请求都提高该倍数。

SmolLM3 两侧均使用标准 CPU sampler，且最小解码桶固定为 2048。指定流程通过，96 条质量输出全部相同，两侧均为 60/96。长轨迹参考是原生 cached-HF；历史 full-causal 交叉检查的两个失败，以及自然小桶路径的问题仍保留。后继 write-only 方案的输出相等性失败，不能继承此表资格。

这些结果对应各结果页列明的已测实现提交。统一分支保留了代码与证据，但后续合并源码仍需重新完成运行验收。

## 四模型 INT8 历史结果

以下是 2026-10-30 的 BF16 权重与逐通道对称 INT8 对照：TP2、batch 容量 4、context 2048、设备端 greedy 采样，每请求强制生成 120 token，三轮暖 HTTP 中位数。各模型的输入分别为 19、36、12、17 token，跨模型不是相同输入的竞赛。

| 模型 | 单请求 BF16 → INT8（输出 token/s） | 单请求倍数 | C4 BF16 → INT8（输出 token/s） | C4 倍数 |
|---|---:|---:|---:|---:|
| Qwen3-8B | 29.7014 → 45.3709 | 1.53× | 115.2669 → 176.4441 | 1.53× |
| Qwen2.5-7B-Instruct | 23.3669 → 48.0433 | 2.06× | 91.4602 → 184.9556 | 2.02× |
| DeepSeek-R1-Distill-Qwen-7B | 24.1490 → 50.5899 | 2.09× | 94.1531 → 196.2946 | 2.08× |
| Mistral-7B-Instruct-v0.3 | 32.5331 → 53.2569 | 1.64× | 126.7001 → 205.6425 | 1.62× |

[完整记录与原始证据](dense-int8-results-20261030.md)保留量化方式、兼容适配和质量问题。这四组只通过当时的小规模检查，没有通过后来完整的数值、冷缓存、长解码、槽位复用和 quality96 验收，不能称为无损量化或新分支合格结果。DeepSeek 这一行是 **R1-Distill-Qwen-7B**，与仍在诊断的 DeepSeek-R1-0528-Qwen3-8B 不同。

## CPU 采样与主机开销的历史测量

这些实验在同模型、同精度、同设备图下比较标准与快速主机路径，均为 TP2/B4/context2048，temperature=0.7、top-p=0.9、top-k=40。Qwen3 和 Granite 每请求生成 120 token；LFM3 为输入 128／输出 512。数字是各自实验实现的端到端测量，不能归因于后来插件中的某一个函数。

| 模型 / 精度 | 单请求：标准 → 快速（输出 token/s） | 倍数 | C4：标准 → 快速（输出 token/s） | 倍数 | 限制 |
|---|---:|---:|---:|---:|---|
| Qwen3-8B / BF16 | 20.21 → 28.74 | 1.42× | 42.65 → 105.41 | 2.47× | 早期有限路径验证 |
| Qwen3-8B / INT8 | 26.62 → 43.91 | 1.65× | 48.70 → 154.80 | 3.18× | 早期有限路径验证 |
| LFM3-1.7B / BF16 | 21.98 → 29.53 | 1.34× | 47.13 → 98.56 | 2.09× | sampler 与 DEBUG 开销的组合改动 |
| Granite 4.2-3B / BF16 | 36.94 → 55.21 | 1.49× | 71.57 → 192.75 | 2.69× | 整模型尚未通过完整数值验收 |
| Granite 4.2-3B / INT8 | 44.18 → 72.42 | 1.64× | 77.86 → 245.28 | 3.15× | INT8 数值失败，不能作为合格替代 |

LFM3 同次主机优化的混合长度为 16.88 → 20.75 token/s（1.23×）；贪心短、中、长输入的 C4 比值分别为 1.056×、1.046×、1.012×。收益主要出现在随机采样负载。Granite 两种精度各自开关快速采样的 96 条贪心文本相同，但不消除其原有整模型数值失败。随机采样的随机数消费方式可能改变，不要求随机文本相同，也不代表 HTTP seed 支持。

以上主机收益不能与 NKI 或量化倍数相乘。见[实现与验证范围](trn1-optimizations.md)及[本次保存数据核对清单](evidence/model-speedups-20261112/manifest.json)。

## 仍未得到合格倍数的工作

以下保留计时和反例，均不能提升为合格模型收益：

| 方案 / 工作负载 | 单请求 / C4 计时比 | 未采用原因 |
|---|---:|---|
| Qwen3.5-2B NKI GDN，长 1536/128 | 1.03× / 1.10× | 43/96 质量文本、57/57 贪心负载文本改变，等价性未闭合 |
| Granite 4.2-3B INT8，输出 120 | 1.32× / 1.29× | 严格数值门槛 4/32 失败 |
| Granite 4.2-3B flash，中 512/128 | — / 0.97× | 没有实测收益，原数值问题仍在 |
| SmolLM3 仅读，短 128/512 | 0.98× / 0.98× | 没有实测收益 |
| SmolLM3 仅写，短 128/512 | 9.61× / 9.47× | 57/76 确定性文本不一致，拒绝采用 |

Nemotron Nano-9B-v2、OLMo3-7B、rnj-1.5-instruct 的特定历史配置，短输入 128／输出 512 的单请求／C4 吞吐量分别为 **13.18／51.06、6.00／23.67、14.59／56.36 token/s**。原路径分别存在 NaN、解码图编译失败或没有合格参考等问题，缺少可用分母，因此倍数记为“无法计算”。RNJ 的该配置显式将官方 FP32 转为 BF16，不能当作原精度无损结果。

MiniCPM5、Phi-4、Gemma、Nanbeige、Ministral、Dory、Qwen3-4B、DeepSeek-R1-0528-Qwen3-8B，以及其他尚未合格型号的数值诊断、算子对照和编译进展，均不自动构成配对提速结果。原 15 个模型家族仍在研究范围内，没有任何家族被宣布“优化完成”。各模型问题、详细证据与本轮状态见[统一分支记录](multi-model.md)和[完整飞书报告](https://ccnawh1pxwn1.feishu.cn/docx/Gjsfd0eJroJDrLxKQxXcJ4HwnVw)。
