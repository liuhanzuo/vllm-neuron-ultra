2026-11-12：修正后的 Qwen3.5-2B 完整实验已启动，实际工具会话为 38957。外层进程与协调进程均已独立确认，运行握手已完成。**整轮结果仍待完成，没有新增合格提速。** 上一轮的 1.229×／1.847× 随机采样与 1.681× 混合长度仍按[已复核、未完成整轮验收的实测值](qwen-r9-results-mini-bootstrap-20261112.md)保留。

本轮修正针对实验运行器，采样实现沿用已发布的快速 CPU sampler。原模型、BF16、数值判据、冷缓存、长解码、槽位复用、采样重放、quality96、配对 HTTP 和最终编译图复用检查全部保留。

## 两处汇总问题的修正

初始 HTTP 检查继续使用上一轮已验证的修正：逐项检查 `prompt_tokens`、`completion_tokens`、`total_tokens` 的严格整数类型和值，同时核对两侧完整 usage 和贪心文本。正常 API 增加 `prompt_tokens_details: null` 不再被误判为 token 数量变化。

运行器现在从实际 API 进程读取完整启动环境，并与执行前记录的环境摘要、PID／启动时间、实际命令和所属进程组交叉核对。检查通过后，才把完整环境、命令及可比较配置写入启动观察。每次就绪检查都会重新核对；旧运行缺失的字段没有补写。

两侧比较保留全部命令参数与环境设置，仅在分别验证其精确绑定后，排除 worker 类和随运行侧变化的身份、输出路径、临时目录、采集目录。线程设置、模型参数或额外日志开关变化仍会失败。这里记录的是实际启动环境与参数，没有声称直接观察到内部线程对象或全部 vLLM 配置对象。

driver 在每个服务开始接受测试请求前检查这些记录，再将 `effective_host_settings` 带入 `host.json`。候选侧启动 HTTP 测试前就与基线比较，最终完整 HTTP 汇总仍再次执行原比较器。这样可提前发现配置或记录问题。

## 独立验证与实际运行范围

主任务独立复跑 17 项源码／模拟检查通过。覆盖实际 `api_ready` 方法的模拟进程输入、完整 driver 调用链、两侧配置比较发生在候选计时之前、缺字段和篡改拒绝，以及失败后清理。driver 的严格计数修正与上一版 AST 完全相同；模型、采样和质量阶段顺序未改。模拟中的执行标记不作为真实模型结果。

退出后审计也已准备：实际工具 session 必须与运行握手及 ACK 对应，实验 contract 必须与本轮 admission、协调进程和源码绑定一致；六次服务观察及最终 HTTP 主机记录逐项重算。9 项独立模拟检查和 AST 保留检查通过，原 20 个阶段、21 个服务与两次完整清理观察保持。实际退出后才能执行该审计。

r10 使用包含 142 条已结束记录的当前串行目录，完整保留 r9 的 48,048 个源码绑定；结合新增的 Mini 启动来源与 Qwen 接线后，共 48,062 个绑定。原串行锁和资源门槛不变，六个 IPC 路径为 96–100 字节，低于原 107 字节上限。实际进程已完成运行前检查和握手，随后继续原全套流程。

原交接函数会保留前一条记录的顶层 `running=false`；本轮独立确认文件明确记录这一历史字段问题。当前执行状态应读取实际工具会话、进程身份和 `qwen35_sampler_current_execution`，不能凭这个继承字段启动重复实验。
