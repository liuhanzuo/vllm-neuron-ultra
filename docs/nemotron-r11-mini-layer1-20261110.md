# Nemotron r11 收尾与 MiniCPM5 第二层采集（2026-11-10）

Nemotron r11 已因根盘空闲空间触及原定 28 GiB 下限而停止，失败释放完成。MiniCPM5 第二层完整采集已接替启动：10:18 UTC 独立核对了外层、协调进程和两个 rank 的实际身份，1,255 个历史服务的清理记录齐全。当前没有新增合格提速倍数。

## Nemotron：局部比较通过，整模型验收未完成

本轮完成 42 个准备／局部诊断阶段，原计划共 52 个阶段。投影和卷积候选各覆盖 8 种形状、各通过 48/48 次精确设备比较；两类原路径均只有 batch=1、单 token 对照通过，其余 7 种形状各为 0/6。这些失败对照不作为性能分母。

日志出现 12 条计算图编译成功消息，但整个编译阶段没有完成，服务 HTTP 就绪、完整输出审计、冷缓存至 4096、长解码、槽位复用、生成和质量测试、真实 HTTP 四并发及配对性能验收均未由本轮证明。不能据此宣布整模型正确或加速。

控制器记录的首个错误是根盘空间保护检查。原始触发瞬间的精确空闲字节数没有保存，后来的剩余空间读数不能代替该瞬间证据。清理时还出现一次进程退出期间的身份核验错误；确认原进程已消失、对应进程组已空后，使用原控制器支持的重试信号完成收尾。未改变原控制器或放宽校验。

原启动会话 74703 实际退出码为 1，错误仍保留。随后执行原 v26 支持的失败释放，会话 32806 实际退出码为 0；这只代表失败任务释放成功。独立复核确认全部 53 个计划服务（含未启动阶段）都已终止且进程组为空。本次没有扩容 EBS 或增加删除范围。

## MiniCPM5：修复我们自己的历史依赖校验

第一次采集启动在加载模型前退出：旧校验遍历当前进程已导入的辅助文件，却从历史运行的较小依赖清单中直接取值。新增的 SmolLM3 辅助文件存在于历史归档，但不属于那次 MiniCPM5 运行，导致 KeyError。这属于我们的诊断工具缺陷，不是 MiniCPM5 权重、vLLM-Neuron 或 Neuron SDK 已被证明存在的计算问题。

后继 collector v2 保留全部历史规格与源码：历史依赖继续匹配旧摘要，当前实际导入的文件必须匹配本次审阅的摘要，同时满足适用的归档摘要。旧文件没有覆盖。源码结构比较确认，原历史条件只有当前导入清单的查找范围和调用入口发生变化，采集器的计算、子进程管理与清理函数保持一致。

后续独立审计 v2 也完成接入：先按原记录验证采集结果，再用当前已核验的源码清单构造仅供前置检查使用的内存视图。该视图保留全部历史摘要和科学参数，不写回历史规格。数值与缓存审计流程保持一致。自身历史重放运行器、双 rank worker、实际审计退出链及准备器 v2 也已完成后继接入；16 项审计退出链检查与 16 项运行器检查重跑通过，源码函数对照确认仅切换后继 worker 路径和当前调用者的依赖视图，原驱动、官方分片和计算公式不变。固定 2,380 个源文件、160,807,561 字节。具体运行规格仍须以采集和独立审计的实际成功退出生成，尚未执行原生重放。补充证据见[自身历史重放 v2 清单](evidence/minicpm5-layer1-own-history-v2-20261110/manifest.json)。
