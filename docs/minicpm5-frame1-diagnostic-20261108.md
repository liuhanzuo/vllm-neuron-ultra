# MiniCPM5：长提示第 1 帧 MLP 诊断结果

**r3 的原生采集、CPU TP2 采集和数值重放均已完成，15 个完整张量逐字节复现；保存数据的独立复算也通过。整模型候选仍未合格，没有新增提速倍数。**

本轮比较的是 HF 原生参考与 Neuron SDK 的 CPU TP2 诊断路径，定位在第一层 MLP。没有重新测量 Trainium 设备或 vLLM 服务性能，不能据此认定芯片有缺陷。此前全矩阵 down 候选使 32 帧通过数由 29 增至 30，却使最高分 token 一致数由 32 降至 31；第 1 帧 KL 从 0.101270 升至 0.196323，因此该候选继续被拒绝。

## 这次实际测了什么

固定 fixture 7、slot 1、step 0，预测位置 1230。原生参考使用 1,231 个实际 token，CPU TP2 保留 2,048 的物理桶。使用原始严格基线、官方 BF16 权重及实际分片，没有增加 o_proj FP32 等精度干预，也没有把完整矩阵缩成最后一个 token。

| 捕获边界 | 原生参考形状 | 每个 CPU 分片的形状 |
|---|---|---|
| MLP 输入、MLP 输出 | 1 × 1231 × 2048 | 1 × 2048 × 2048 |
| gate、up、SiLU(gate) × up | 1 × 1231 × 6144 | 1 × 2048 × 3072 |

三路共保存 **15 个完整 BF16 张量、164,515,840 字节**。原生与 CPU 各自的形状、步长和布局保留，CPU 输入为特征优先布局。重放先在各自原始输入上逐字节复现全部 15 个张量，再固定同一份完整 CPU 输入比较三条路径：完整矩阵 MLP（F）、TP2 MLP（S）、仅将 down 换成完整矩阵的 MLP（D）。

每路 6 个原预测锚点、每个 CPU 分片 4 个完整中间张量的历史锚点，以及官方权重区间也已核对。原生、CPU、replay 三个服务和外层运行器实际退出码均为 0；已确认进程退出、资源组为空。

## 实际结果及其含义

| 对照 | 实测结果 | 能支持的结论 |
|---|---|---|
| 原生与 CPU 的实际 MLP 输入 | 真实 token 范围 2,521,088 个元素中有 584,829 个不同；最大绝对差 0.03125。预测位置 393/2048 个不同，最大差 0.0078125 | 差异在进入 MLP 前已经存在，不能只检查 down |
| 固定同一输入，完整与 TP2 的 gate、up、激活乘积 | 三处完整桶各 12,582,912 个元素均逐字节相同 | 在本次输入、布局和权重下，MLP 前半段没有引入两条路径的差异 |
| 固定同一输入，TP2 输出 S 与完整输出 F | 完整桶 1,385,116/4,194,304 个元素不同，最大差 0.0078125；预测位置 607/2048 个不同，最大差 0.0009765625 | 本次固定输入下，down 的分片计算与归约路径产生可测差异 |
| 固定同一输入，仅替换 down 的 D 与 F | 全部 4,194,304 个输出元素逐字节相同 | 本次局部对照中，替换 down 足以复现完整 MLP 输出 |
| 原生与 CPU 各用实际输入后的 MLP 输出 | 预测位置 1267/2048 个元素不同，最大差 0.001953125 | 包含输入差异和后续运算差异，不能由这一项确定最终 KL 的唯一原因 |

因此，局部的 D=F 并不意味着整模型应直接采用完整 down。已有完整 32 帧对照出现了新的最高分 token 错误，仍然优先于局部相等结论。下一步应向 MLP 输入之前追踪注意力输出、残差和归一化，并在控制输入相同的情况下区分上游输入变化与投影/归约变化。

## 独立复核做到了哪一步

此前准备的 44 项元数据检查、38 项原始数据检查所对应的复核程序，这次均已对实际 r3 结果执行。元数据复核检查规格、启动记录、结果、历史锚点和采集文件的关联；原始数据复核读取全部 15 个 BF16 张量，两次核对内容哈希，检查有限数和两路 CPU 输入/输出的逐字节一致性，并重新计算五个边界在全部真实 token 和预测位置的差异。

独立数据复核使用标准库整数累加及独立 BF16 解码，没有导入 PyTorch。完整执行约 **28.33 秒，峰值内存 52.09 MiB**，在单 CPU、2 GiB 地址空间、600 秒 CPU/900 秒墙钟预算内完成。这是审查工具的资源消耗，不是模型推理性能。

独立程序没有重新执行 MLP 矩阵运算，因而不构成对固定输入 F/S/D 干预的第二次独立数学重放；这一对照来自原数值重放。最终 KL 的唯一原因、整模型正确性和设备性能均未获证明。

## 启动与归档工具修复

r1 在模型启动前被旧历史校验与新导入模块的相互影响阻断。r2 的原生服务确实启动过，但在写入进程确认记录前失败；当时没有保存被拒绝的进程参数，具体启动状态仍未知。不能把它记成“从未启动”，也不能用 systemd 管理器 PID 代替服务进程。

本轮补齐了 r2 的真实失败表示，保留未知身份；相关 13 项检查通过。新运行器在判断启动状态之前持久化启动意图和实际进程快照，只在同一服务调用、PID、启动时间和资源组内允许有时限的空参数/exec 过渡，拒绝替换身份或意外命令。退出清理支持已验证的服务回收，并保留原始错误。相关 19 项检查通过，r3 实际启动和三阶段执行成功。原采集、重放和科学判定代码未改。

完整历史现有 925 条服务和 179 条已知进程。归档程序在写完目录后的打印阶段误用了旧 8 MiB 读取函数，实际退出码为 1；该失败保留，没有重跑实验或改写源码。外部核验使用既定有界读取，确认已写文件的完整哈希、全部条目和资源回收，随后正常退出。模型和独立复核此前均已真实退出 0，二者与归档打印失败分别记录。

## 完整验收与后续工作

本轮输出总预算 192 MiB、单文件 16 MiB、根盘空闲下限 28 GiB 均保留。原生/CPU 各 900 秒、重放 600 秒；没有重复启动 r1 或 r2，也没有扩容 EBS。
