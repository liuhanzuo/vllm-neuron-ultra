# Nemotron Nano 9B：投影与卷积拆分问题及当前验证范围

2026-11-09 的 r8 已停止：完整模型编译被我们自己的文件校验规则误拒绝，进程已退出并完成失败释放。以下记录的是已完成并保留实际退出与清理证据的 **16 项投影与 16 项卷积原语阶段**；它们不是整模型验收结果。当前没有新的 Nemotron 提速倍数。

当前测试使用 `vllm-neuron-ultra-nemotron9b-v1` 的提交 `60ab7f54a2c54ef0bc9b498621a45719ee7f0e84`，vLLM 0.11.0、Trainium1、原 BF16 输入和固定编译选项。原完整协议包含 52 个阶段，其中准备、9 项状态别名、16 项投影和 16 项卷积共 42 项已完成。完整模型编译中断，后续仍须完成整模型编译、状态复制、数值、冷缓存、长解码、96 项质量检查、三轮工作负载及独立原始数据复核。新合并分支本身仍需单独验收。

## 4096-token 用例中看到了什么

对输入 `[1,4096,11328]`，最后一个维度应拆成 `[5120,6144,64]`。我们重新读取并核对了两份小型 HLO 计算图的 SHA256，用纯 Python 解析 SDK 的 protobuf 描述，没有重新编译或运行模型。

原写法的图先把输入变成一维，再取连续区间，最后还原输出形状。例如第一份输出先取前 `4096×5120` 个元素，再变成 `[1,4096,5120]`。这样，第二个 token 的第一个元素取自输入偏移 **5120**，而逐 token 切片要求的偏移是 **11328**。

第二份输出也出现同类问题：图从展平输入偏移 `5120` 开始连续取 `4096×6144` 个元素，而正确行为应逐行取通道 `[5120,11264)`。第三份输出同样应逐行取 `[11264,11328)`。

替换写法使用原三维输入上的切片，保留 batch 和 token 两个维度，只在最后一维指定切分边界。4096-token 用例的 36,864 个结构地址抽样中，原图有 36,855 个不匹配，替换图为 0；两个确定性设备输入的三个完整输出也均为 0 字节差异。

因此，在这个固定复现用例中，问题已表现为计算图中的地址映射错误。该证据不能推广为所有 split、所有版本的 Neuron 或其他硬件上的行为，也尚未确定应归责哪个上游组件或提交。Dory 的 CPU 参考差异是另一项待定位问题，不能据此归因于 Trainium。

## 卷积分支中的同类错误

卷积后的输入形状是 `[1,6144,T]`，先转成 `[1,T,6144]`，再按 `[5120,512,512]` 拆通道，最后整理成每个头的形状。此次独立计算图复核覆盖以下全部 16 个已结束阶段；随后启动的完整模型编译因下述实验校验问题中断。

16 个保存的卷积 HLO 图均已重新读取并核对 SHA256。独立解析只使用纯 Python protobuf，没有导入 PyTorch、Neuron SDK 或运行设备任务；对每个 token、每份输出的首／中／尾通道追溯原始输入位置。原图先展平转置后的张量，再连续截取；候选图保留 token 维度，沿通道维度切片。

以 T=512、第一份输出的第二个 token 为例，原输入 `[1,6144,512]` 中应读取通道 0、位置 1，即展平偏移 **1**。原图实际读取的是通道 5120、位置 0，即偏移 **2,621,440**。候选图读取偏移 1。此处是数据位置错误；CPU 的两种写法均通过。多行形状的两种确定性输入在完整设备输出比较中只在候选侧通过；B1T1 单行对照则两种写法均通过。

这项发现限于已保存的固定消费者计算图。结构抽样与工作进程的完整输出比较是两种不同证据；整套原始设备数据仍待独立读取复核。它尚不构成完整 Nemotron 模型通过或新的提速结果。

## 完整模型编译为什么中断

本次中断来自我们实验管理代码中的链接分类规则。编译器的 `sgLnk/sg00` 目录同时包含新生成的数值文件和已安装的 PWP/DVE 资源链接；原规则把所有 `sgLnk` 路径都送入数值／调试文件检查，因而拒绝了 17 个本已登记的安装资源。控制器和外部审计均因此报 `Reviewed generated numeric basename and link subgraph`。这没有证明模型、Neuron 编译器或数值计算出现了新故障。

停止后的 44 个实际链接已逐一检查：17 个调试文件、10 个数值文件和 17 个安装资源链接。修正版本仅给已有、精确绑定安装清单的资源增加该目录位置，仍要求原文件名、绝对目标及文件身份一致；未知目标、跨目录替换和文件被改写仍会拒绝。27 个生成目标已完整计算哈希，原清单中的 83 个安装资源也已重新核对内容。文件规则回归执行 82 项检查（55 项不同检查，含 7 项新增场景），全部通过；其中部分既有检查在不同组合下重复执行，不能算作 82 个独立模型测试。

编译任务在停止阶段出现超时，系统随后清空了进程组。原外部任务退出码为 1。两次释放工具尝试又被旧代码中过宽的源文件扫描规则拒绝；第三次在明确记录扩展代码、保持原源文件检查后完成失败释放。这些失败均保留，不计作编译或模型成功。原执行源码及产物没有覆盖，也未自动重新启动模型。

修正代码现已接入 v17 的存储扫描和最终证据核验，并通过 18 项源代码、文件系统与完成记录检查，详见 [v17 准备报告](nemotron9b-v17-preparation-20261109.md)。它仍是待运行版本，尚未用于新的完整编译；还需整理已完成产物以满足原磁盘预留要求，并完成新运行规格和串行启动前检查。已有 42 项阶段记录继续保留，原始设备输出独立复核、完整模型编译和全部后续验收仍待完成。没有新增 Nemotron 提速倍数。

## 优化版本的使用边界

当前修复通过累计通道宽度构造显式边界，并调用 `torch.tensor_split`。先恢复正确计算，才能继续判断速度。失败的原实现不能作为提速倍数的分母；原语逐字节一致也不能替代整模型生成、长序列、请求槽位复用和实际四并发 HTTP 验证。

全部 15 个模型家族继续保留在任务范围中。此前已发布的 [LFM3 倍数](lfm3-results-20261107.md)、[SmolLM3 倍数及限制](smollm3-results-20261105.md)与[四个历史 INT8 模型](dense-int8-results-20261030.md)没有变化；[Dory 的 7 个失败及全部既有倍数](dory-long-reference-status-20261109.md)也继续保留。
