# Qwen3.5-2B 采样优化准备与 MiniCPM5 结果核验修正

Qwen3.5-2B 已准备好独立的 CPU 采样优化候选，主任务复跑 20 项源码检查全部通过。实机对照尚未执行，因此没有新增提速倍数。MiniCPM5 第三轮原生参考仍在运行；本次还修正了它后续结果核验工具的来源绑定冲突。

## Qwen3.5-2B：减少每步 CPU 采样开销

Neuron 执行模型后，当前服务仍在主机 CPU 上处理采样。Qwen3.5-2B 的词表有 248,320 个词元；对于较小的 top-k，候选先寻找少量高分词，再在这个集合内完成 top-p 筛选和随机采样，以减少全词表排序与随机数生成开销。

候选使用仓库现有的 bounded CPU sampler，只替换当前模型实例的 top-k/top-p 操作。适用范围是 CPU FP32 logits、top-k 为 1–64，以及可选的合法 top-p。过多并列值、接近概率边界、非有限阈值或其他不支持的情况会回退。显式设置请求随机种子时整次调用回退原实现，以保留输出与随机数状态。

比较基线是已通过原声明检查的 Qwen3.5-2B 文本适配器：原 BF16 权重、FP32 循环状态、TP2、B4、上下文 4096 和修正后的 tensor_split。旧 GDN 候选出现的 43 条质量文本变化和 57 条 greedy 工作负载文本变化仍判为不合格。

这次比较会保持相同的 DEBUG 和线程设置。旧开关还会改变 DEBUG 行为，不能用于隔离采样收益。冻结的模型图及其来源记录与新增主机代码分别核验，不重新编译或改写图缓存标识。

## 必须完成的实机对照

两组都保留原完整验收：96 份状态缓冲的写入与清零、32 帧数值检查、84 帧冷缓存检查及全部 12 个图路由、1541 步长解码及槽位复用，以及全部 203 份原始输出向量与已通过基线逐位一致。质量检查仍为 96 题，两组均须复现原来的 69/96 和全部 96 条文本。

采样检查使用独立请求，记录温度和惩罚处理之后的真实完整 logits、请求及槽位顺序、采样参数、前后随机数状态。每组最多保存 64 次调用、160 行完整词表数据，总量不超过 256 MiB；实际单请求与四并发各需至少 16 次记录。验证支持集一致、总变差与最大概率误差均不超过 1e-6，并重现各组自己的输出和随机数状态。未指定种子的随机文本不要求两组逐字相同。

性能测量使用没有采集钩子的独立服务，保留原始短测试以及五类工作负载、每类三轮的完整 HTTP 对照。完整工作负载每组包含 124 条计量请求、30,848 个输出词元；57 条 greedy 文本须一致。所有结果使用新目录。

准备期间确认了旧实验运行器的一个复用行为：相同 case 名称可能直接返回历史已通过结果，或读取旧 HTTP 文件。因此新对照直接调用原评测客户端，强制写入新的组别目录，防止把历史结果当成新测量。这是本地实验运行器的行为，不能据此归因于上游 vLLM-Neuron。

20 项检查覆盖了流程、源码身份、worker 名称导入、采集边界、预算、失败顺序和服务结束后清理；使用的是纯 Python 和替身对象。真实 worker 加载、数据序列化、采样重放及端到端测试尚未运行。下一步正在补齐实际串行执行接口和资源约束。

## MiniCPM5：修正后续核验工具的来源冲突

第三轮原生参考已经启动。旧结果记录器要求若干入口源码只能出现在“新增来源”列表，而当前模型配置已经继承了这些源码；同时合并规则禁止重复来源，导致后续核验无法接受合法配置。

新记录器和独立核验器只增加真正的新文件，从完整的“继承来源＋新增来源”中核验入口，并把原模型配置、审核记录和完整来源集合绑定起来。独立核验器会重新构造完整来源集合后再检查记录器的结果。主任务已复跑 44 项相关检查；原科学比较、真实退出和进程清理条件继续适用。工具修正尚未形成新的模型结果，未来准备工具也需要相应后继版本。

当前 MiniCPM5 仍需完成原有 24 个检查点、每点三组对照、恢复检查、真实退出及独立原始数据复核。源码检查通过和进程运行都不能计作推理提速。
