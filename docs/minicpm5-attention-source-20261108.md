# MiniCPM5 注意力内部诊断准备：尚未执行模型

上一轮实测已确认：原生与 SDK CPU 双分片的完整有效前缀注意力输入一致，差异从注意力输出出现。此次准备继续定位内部边界，尚无新模型数值结果、合格候选或提速倍数。上一轮结果仍见 [完整前缀实测](minicpm5-upstream-result-20261108.md)。

新源码保留原计算函数，用 Python 调用/返回事件及原投影模块的钩子保存数据；不替换矩阵乘法、RoPE 或 attention 的实现。原生输入长度为 1,231；CPU 两个分片各保留 2,048 行及原有布局、填充和线程设置。新采集必须逐字节重现上一轮七个完整模块边界和六个预测位置的观测值，否则本轮不能用于继续定位。

| 采集范围 | 用途 |
|---|---|
| 完整归一化输入、位置编号、Q/K/V 投影 | 区分投影本身与后续计算差异 |
| RoPE 前后 Q/K、V 的多头布局、cos/sin | 区分位置编码与排列的影响 |
| 完整掩码、各头 context、输出投影前后 | 区分注意力计算与最后的投影/归约 |

每个执行角色保存 16 份完整内部张量，三个角色合计 48 份。原 Q/K/V、RoPE、attention 和输出投影还将各用自身保存的完整输入复算，输出共 21 份；CPU 输出投影保留原 Gloo 归约。RoPE 复算使用保存的 cos/sin，不能称作独立验证三角函数生成。加上原七处边界和归一化权重，预算为 353,284,922 字节，约 336.92 MiB，上限为 384 MiB。

独立字节比较器逐 token 拼接两个分片的注意力头，分别处理原生与 CPU 的 context 轴顺序，校验完整填充区域，按语义比较加法掩码和布尔掩码。它从真实保存的复算输出重新判断一致性，不直接相信报告中的通过标志。完整模型的最终 KL 原因仍需要后续受控对照才能确认。

**117 项准备检查通过：**采集/控制 39 项，内部字节与头映射 15 项，完整元数据及原边界复核 23 项，串行运行程序 14 项，运行配置生成器 7 项，以及模型退出后独立复核程序 19 项。测试使用标准库、实际 Python profiler 小函数、模拟钩子和控制调用、少量合成字节，以及已有元数据；没有导入 Torch 或运行新的模型算术。新增准备记录见文末。

完整复核程序还会读取原七个模块边界的全部 21 份张量与六份归一化权重，并独立重算 BF16 残差加法；检查四处仅涉及排列的变换、内部采集与已有边界的重合部分，以及全部 96 份原始输出的数量和字节预算。元数据检查绑定真实的上一轮结果、官方投影权重/分片证明、原始调用与位置编号，复算控制的结论由保存的输出推导。它没有独立执行 QKVO 矩阵运算、softmax、归一化或三角函数，仍需实际采集和模型验证。

串行程序保留原生、CPU 双分片、完整结果复核三个阶段，以及原解释器、线程、资源限制和启动清理规则。运行配置生成器已经通过实际依赖和十份原锚点检查；测试中新增源码闭包为 104 个文件，低于 128 个上限，继承的 2,022 个源码指纹和原科学计划不变。新配置必须绑定 Nemotron r7 的真实完成目录及归档程序的外部退出记录；当前尚未创建正式运行配置或启动新的 MiniCPM5 采集。

Nemotron r7 的归档程序另有 20 项源码检查通过，要求保留原实验历史和已完成的九文件清理记录。它只在原实验真实退出并释放资源后才可运行。这 20 项不计入 MiniCPM5 的 117 项检查。初稿语法/集合比较错误，以及后续三个测试样例的错误均已修正并保留实际失败记录；它们属于未执行的诊断草稿或测试问题，不能归为上游仓库或芯片故障。

运行状态快照（2026-11-08 15:58 UTC）：Nemotron r7 控制器仍在运行，已保留 22/52 个工作阶段退出记录；其中前 22 个阶段已完成元数据核对。128/256/512/1024/2048/4096 token 的投影拆分对照报告均显示，CPU 两种写法正确，原写法的 Trn1 输出不一致，`tensor_split` 写法逐字节一致；详细范围见 [r7 局部拆分对照快照](nemotron-r7-split-progress-20261108.md)。这不是整轮完成或整模型通过。等 r7 实际结束、释放资源并完成历史归档后，再准备 MiniCPM5 的正式运行配置和独立结果复核。原有冷缓存、长解码、请求槽位复用、质量与配对服务性能门槛全部保留；全部 15 个模型家族和 Phi/Dory 仍在范围内。
