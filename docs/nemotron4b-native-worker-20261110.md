# Nano 4B：原模型检查接入工作程序流程

本轮把原生参考与 Neuron 结构检查接入新的工作程序执行流程，11 项检查通过。六个科学检查函数与原 v2 的语法树完全一致；新增部分负责父进程放行、环境恢复、辅助程序调用和结果保存。

测试实际启动了轻量工作进程，但模型计算与环境恢复使用明确标记的模拟函数。真实 SDK、原生模型检查、完整基线和性能测量仍未执行，因此没有新增提速结果。

## 原模型检查保持什么

迁移的六个函数负责：读取实际权重头的张量清单、检查原生模型张量形状、检查 TP2 各 rank 的形状、执行 native-meta、记录实际运行环境，以及执行 nxd-meta。每个函数的语法树逐一与固定哈希的原工作程序对照，未修改原模型判断。

由此保留原来的 263 个 BF16 张量、3,973,556,832 个参数、42 层结构，以及 TP2、B4、4096 上下文、标准 CPU sampler、原缓存和 FP32 SSM 状态要求。原生参考使用 Python 3.12，Neuron 检查使用 Python 3.10，两个环境分别保留。

原 v2 源码与工作目录没有改动。后继模块指向新的 v3 工作目录，但该目录尚未创建，也没有加入运行队列。

## 新执行流程

1. 确认原计划与工作程序哈希，等待父进程完成实际身份捕获和放行。
2. 保存本进程收到的放行记录，再进入调用方提供的、已认证的环境恢复流程。
3. 检查本阶段实际 Python、虚拟环境、CPU、优先级、离线配置和原采样器设置。
4. 执行原 native-meta 或 nxd-meta；后者通过上一轮的接口调用本 rank 的辅助程序一次。
5. 保存实际环境、原检查结果、启动记录和辅助程序记录；失败时保留已完成的诊断内容，并向父进程传播原异常。

对 `subprocess.run` 的临时接管在正常退出和异常时都会恢复。额外子进程、模型权重或编译产物读取、工作目录外写入和远程网络请求继续受到原范围限制。Python 审计不是原生系统调用隔离；整个服务组清理仍由根启动器负责。

## 这次验证了什么

11 项检查包含正常原生阶段流程、Neuron 辅助程序接口衔接、启动失败、模型检查异常、原 SystemExit 传播、辅助程序失败，以及运行环境记录、启动上下文退出或结果保存阶段失败。后半程失败时，已完成的模型检查结果和环境记录仍会保存在失败记录中，不能把它们转换成成功。

其中一项组合检查实际运行两个模拟计算进程，每个进程再启动自己的模拟辅助程序。两个 rank 在同一个输出目录中使用独立文件名和记录写锁，分别保存握手、辅助程序输出和结果。四个实际进程均确认退出并被回收。这里的同步是文件标记模拟，未运行真实 Gloo 或 Neuron。

| 证据 | 可以说明 | 尚不能说明 |
| --- | --- | --- |
| 六个函数语法树一致 | 原科学检查逻辑未改变 | 原模型已经运行通过 |
| 实际轻量进程与失败注入 | 工作程序调用、保存与退出流程可衔接 | 真实 SDK 或完整服务组已验证 |
| 两个 rank 与两个 helper 共用输出目录 | 本轮模拟流程没有记录冲突，四个进程已回收 | TP2 模型、Gloo 或性能已验证 |

下一步仍需完成具体启动入口、完整根启动器、两个 Python 环境各自的真实启动来源检查，以及当前串行队列的运行准入。现有 helper 依赖准备主要针对 Python 3.10，不能用来代替 Python 3.12 原生参考的启动验证。

Dory r3 保存结果复核仍在运行；原有七项 FP32 失败仍未解释。冷缓存、长解码、请求槽位复用、生成质量、HTTP C4 和配对性能要求继续保留。
