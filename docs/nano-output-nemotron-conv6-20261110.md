# Nano4B 早期失败日志修复与 Nemotron 六种卷积长度

2026-11-10 UTC：Nano 启动监督器的后继 v3 已修复早期握手失败时漏收输出的问题，两套 Python 共 24 次测试通过。Nemotron 9B 卷积切分候选在 128 至 4096 六个长度上共 36/36 次设备比较逐位一致。当前仍没有新增整模型提速。

## Nano 启动失败现在能留下什么

此前 v2 只有在父子握手成功后才收集输出；子进程若提前退出，清理会直接关闭输出管道，丢失已经产生的错误内容。新增回归测试在两套原始 Python 下均复现了这个问题。

v3 保留原有父进程先持久记录身份再放行的顺序，以及只通过所属子进程的 PID 句柄完成回收的行为。回收后增加最多 0.25 秒的输出读取，即使握手或资源检查失败，也会保存管道中已有的标准输出和错误输出。每路输出严格受原上限约束，超出上限、未收到 EOF、读取超时分别记录。

收齐管道内容不代表实验成功。非零退出、超时和拒绝放行仍是失败；被终止的进程可能只生成了部分实验输出。若其他进程持有管道，新版也不会无限等待或据此声明整个进程组已清空。

12 项测试在两套 Python 中全部通过，共 24 次成功执行，覆盖原问题复现、提前退出、错误握手、父进程拒绝记录、正常完成、放行后非零退出、放行前后输出超限、超时回收、资源检查拒绝，以及不关闭的管道写端。二进制输出按原字节核对。

修复目前是已审查的独立后继组件；SDK helper、native worker 和整个进程组结果适配仍使用旧版引用，下一步需以兼容后继完成连接。没有修改冻结版本，也没有执行实际 site、SDK 或模型。

## Nemotron 卷积切分覆盖到 4096

BF16 输入 [1,6144,T] 转置后，原方式按 [5120,512,512] 切分；候选明确指定边界 [5120,5632]，其余尺寸、精度和消费者保持一致。

| 长度 T | 原方式逐位一致 | 候选逐位一致 | 原方式抽查地址错位／总数 | 候选错位 |
|---:|---:|---:|---:|---:|
| 128 | 0/6 | 6/6 | 1,143/1,152 | 0 |
| 256 | 0/6 | 6/6 | 2,295/2,304 | 0 |
| 512 | 0/6 | 6/6 | 4,599/4,608 | 0 |
| 1024 | 0/6 | 6/6 | 9,207/9,216 | 0 |
| 2048 | 0/6 | 6/6 | 18,423/18,432 | 0 |
| 4096 | 0/6 | 6/6 | 36,855/36,864 | 0 |

六种长度的原方式均失败，候选全部通过，输入未改变。十二个阶段保留了成功退出记录：原方式的成功退出表示预期数值失败被复现，不能当作数值通过或提速分母。

本轮汇总只读取完成阶段的 JSON 记录并核对进程身份与退出结果，没有重新读取原始张量和 HLO。还需单行对照、整模型冷缓存至 4096、长解码、槽位复用、生成质量、真实 HTTP 与配对性能，以及完整原始证据审计。算子覆盖到长度 4096 不等于整模型冷缓存检查已通过，也不能据此独立归因至某个上游仓库。
