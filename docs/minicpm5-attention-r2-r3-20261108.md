# MiniCPM5 注意力：真实缓存布局与 CPU 观测器修正

2026-11-08，第二轮原生参考采集完成并退出 0，随后两个 CPU 分片因观测器属性检查错误退出，整轮退出 1。CPU 注意力计算与保存数据重放尚未执行。这一轮没有产生整模型合格配置或提速倍数。

## 已经证实的结果

原生路径的七项上游完整边界与此前采集逐字节、逐布局一致；Q/K/V 投影、Q/K RoPE、attention context 和输出投影的七项自身输入对照均通过。新记录实际捕获了 RoPE 与缓存更新之后的 K：

| 属性 | RoPE 输出 | attention 实际消费 |
|---|---|---|
| 形状 | `[1, 2, 1231, 128]` | 相同 |
| 精度、偏移 | BF16、0 | 相同 |
| stride | `[315136, 128, 256, 1]` | `[315136, 157568, 128, 1]` |
| 全部逻辑字节 | 630,272 字节 | 哈希相同 |

完整保存的 K 字节已独立重新计算哈希。这个实际结果证明本轮缓存边界只改变了布局；第一轮未保存两端元数据的局限仍保留。注意力对照使用实际消费布局，RoPE 对照使用原生产布局，模型计算和缓存逻辑没有修改。

## CPU 为什么退出，修正了什么

错误是 `AttributeError: 'RowParallelLinear' object has no attribute 'pad_size'`。当前安装的 SDK 只在 `pad=True` 时创建 `pad_size`；实际未填充配置没有这个属性。问题来自我们观测器假定属性始终存在，不能归为模型、SDK 算术或芯片错误。

后继观测器明确检查 `pad=False`、TP2、BF16 归约、输入/输出维度 2048、局部分片维度 1024、BF16 权重形状 `[2048, 1024]`、无偏置和未启用序列并行。它不默认缺失值、不修改运算或权重，也不放宽数值容差。49 项检查通过，其中 41 项继承检查、8 项新增检查。

第二轮原生成功、CPU 失败与未启动的重放分别保存；两次确认所有计划进程组均释放。54 个部分文件，共 99,599,281 字节，完整保留。第三轮正式配置绑定前两次失败记录，保留原 2,022 个源码指纹并追加 118 个文件指纹，原始科学输入、资源限制与验收条件不变。

## 第三轮采集完成，独立复核通过

原生阶段与 CPU 双分片均实际退出 0，三路各七项自身输入对照通过。原始重放阶段因为读取器的 2 MiB 上限拒绝了固定的 4,087,706 字节实验计划而退出 1，协调程序也退出 1。这个读取错误发生在完整数据复核之前，属于我们的工具问题；原运行结果没有改写成成功。

独立结束核验两次确认三个服务及原进程均已退出，保留 126 个文件，共 353,797,936 字节，其中完整原始输出为 96 份、353,284,922 字节。新增读取器只为原路径、原 SHA-256 和准确字节数匹配的计划提供较大读取限额；其他记录仍受 2 MiB 限制。8 项回归检查通过，原冻结源码不变。

随后直接复核保存数据，没有重跑模型。独立复核实际退出 0，全部 96 份输出和 21 份上游边界通过完整字节核验，21 项自身输入对照均一致；所有原始文件前后哈希不变。复核重新计算完整比较指标、检查补齐行与 reshape/transpose，并独立执行保存数据的残差加法。它没有独立重执行 attention/softmax、矩阵投影、三角函数或归一化。

## 原生与 SDK CPU 的实际差异

以下比较覆盖完整有效前缀 1,231 个 token，并按原头映射合并 CPU 两分片。末预测位置另列，未拿单行结果代替完整前缀。

| 边界 | 有效前缀不同元素 / 总元素 | 末预测位置不同元素 / 总元素 |
|---|---:|---:|
| 归一化输入 | 0 / 2,521,088 | 0 / 2,048 |
| Q 投影及 RoPE 后 Q | 1 / 2,521,088 | 0 / 2,048 |
| K 投影及 RoPE 后 K | 0 / 315,136 | 0 / 256 |
| V 投影及分头 | 0 / 315,136 | 0 / 256 |
| attention context | 28 / 2,521,088 | 1 / 2,048 |
| 输出投影 | 802,431 / 2,521,088 | 695 / 2,048 |

位置 ID、RoPE 的 cos/sin 系数相同；有效前缀掩码语义相同，真实查询没有读入补齐键。context 最大绝对差为 0.00048828125，输出投影为 0.0078125。末预测位置的 context 差仅 1.862645149230957e-9，但输出投影差异涉及 695 个元素。

这些是实际观察到的边界差异，不能单靠元素数量认定因果。三路各自输入的重算都精确复现，说明可以进入同一份 context 的投影对照，进一步区分输入差异、矩阵计算和 TP2 分片求和。现有数据尚未证明最终 KL 的唯一原因，也没有使此前被拒绝的整模型 down 候选合格。

独立复核用时约 73.19 秒、峰值内存约 267.28 MiB。这是复核工具开销，**不是推理性能或提速倍数**。
