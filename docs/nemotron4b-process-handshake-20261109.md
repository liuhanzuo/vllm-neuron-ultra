# Nemotron Nano 4B：补齐启动前握手与子进程监督

已为 NVIDIA-Nemotron-3-Nano-4B-BF16 准备启动前握手和有输出、超时限制的子进程监督模块。22 项检查通过，包含真实但仅使用 Python 标准库的短命测试进程。原有 119 份准备源码、v2 工作程序和方案均未改变。真实 SDK 辅助进程、原生结构检查和模型推理尚未执行，本轮没有基线或提速结果。

模型仍使用固定版本 dfaf35de3e30f1867dd8dbc38a7fc9fb52d3914f，原始总参数量 3,973,556,832。后续要求保留 BF16、双分片、批量 4、上下文 4096、标准 CPU 采样，以及 FP32 的 SSM 循环状态。

## 为什么需要这项准备

此前的 v2 工作程序已准备好原生结构和 Neuron 双分片的元数据检查，但完整启动器尚缺三个环节：根监督进程、双分片监督进程，以及能可靠记录 SDK 辅助进程身份的启动方式。

SDK 的库路径发现程序很短命，启动后再轮询，可能在抓到 PID、启动时间、参数和父进程之前就退出。新握手使子进程先发出就绪消息并等待；父进程两次读取实际进程身份，在中间重新检查运行条件，随后才允许子进程继续。子进程收到允许消息后，也再次检查自身和父进程身份、原就绪消息的指纹与时间顺序。

模块通过匿名管道交换有大小上限的消息，绑定本次运行标识和参与者角色；消息不完整、重复字段、额外数据、错误身份或超时都会拒绝继续。后续真正的辅助程序须在被记录的包装进程中、握手完成后才执行。

## 监督模块的行为

监督模块在子进程仍未被回收时打开内核 PID 句柄，限制标准输出、错误输出和执行时间。超时或检查失败时，只通过该句柄向自己启动的子进程发送清理信号，防止 PID 被复用后指向另一进程；随后记录实际退出码和回收结果。

独立非零退出、提前退出、输出超限和超时都保留为失败。清理成功不能转为实验成功。失败时保留有界的部分输出，输出超限最多多保留一个字节作为越界证据。

一项初始测试假定“关闭就绪管道并返回 0”的测试子进程必定以 0 退出，但父进程发现握手失败后的清理信号可能先到达，实际记录为 -15。程序原本就保留了这个真实结果；修正测试的时序假设后通过，原失败测试和退出记录也保留。这是启动与清理的时序问题，不是模型计算或上游 SDK 的已证实问题。

## 验证范围

| 检查 | 结果与边界 |
|---|---|
| 14 项握手检查 | 覆盖完整消息、错误身份、截断/超长/重复消息、等待超时、父进程拒绝、短命进程反复启动；真实测试进程均为标准库程序 |
| 8 项监督检查 | 覆盖成功、提前退出、退出码 17、输出超限、超时、启动前后条件失效、管道和 PID 句柄回收 |
| 原准备代码复查 | 119 份源码指纹、v2 工作程序与方案一致；共享库文件属性一致，未重新读取库内容 |
| 当前任务状态 | 未启动真实 SDK 辅助程序、原生模型、编译或设备测试；没有新增串行实验占用 |

新模块只能证明测试范围内的握手与直接子进程监督行为，不能独自证明完整服务子进程树已经退出，也不能准许释放串行锁。

## 还需要完成的接入

需要先编写不可变的新辅助程序包装、工作程序及方案，再接入根监督和双分片监督。冻结的 v2 方案要求直接调用原辅助程序，其参数与新包装程序不同，不能把新的进程记录伪装成满足旧 v2 方案。

接入时保留原有模型检查：263 个原始张量、42 层混合结构、每分片 431 个学习参数条目和 1 个 rank 条目、50 个缓存，以及 FP32 循环状态。原生检查的完整后续冷缓存、长解码、槽位复用、生成和质量、真实 HTTP C4 与配对性能验证仍保留。

实际启动将使用 Dory、有限存储维护、Nemotron 串行任务链结束后的完整记录；旧的 11 月 6 日前序清单已过时，不能直接用于当前运行。所有 15 个模型家族继续在目标范围内。
