# Dory：完整原权重前向与投影后端因果对照

2026-11-08，Dory 原始 4B BF16 权重已实际完成 **72 个物理层、两轮循环、56 份独立 KV 历史**的 CPU 前向。原独立 `F.linear` 候选没有通过精确对齐；只把候选投影切换到官方模块的因果对照中，**26 次调用的全部隐藏状态、logits 和缓存，2,964 项比较逐字节一致**。两轮结果及请求重新开始的保存输出均已独立复核，官方输出在两个新进程中也完全复现。

这推进了原权重参考的建立。当前覆盖一个 32-token 固定输入轨迹，尚未完成完整长解码、生成质量、生产槽位和 Neuron 基线验收，**没有新增整模型合格提速倍数**。原 `F.linear` 候选的失败记录继续有效，因果对照不改变其结论。

模型保持 `nvidia/NVIDIA-Nemotron-Labs-Dory1.0-4B-BF16` 的修订 `f6c832e6963ddb74f62c75813a3e8c74b1af67b1`。固定官方 vLLM 提交 `75fc05a53a366068f534a61ab3ee6b50485419f2`，实际环境为 PyTorch 2.14.0+cpu、Transformers 5.20.2。507 个原始 BF16 张量共 3,975,229,440 个参数，没有修改权重、精度、学习缩放、循环次数或窗口配置。

官方模型直接按 BF16 构造，避免先创建完整 FP32 参数副本。官方加载器把原始张量映射到 399 个物理参数对象；加载后、后处理前的全部 507 个分片或完整张量哈希都与原 checkpoint 一致。循环层复用同一份物理参数。保留最大位置 262,144、SWA 1,024 和两套完整 BF16 旋转位置缓存，每套形状为 `[262144, 256]`。每次前向都检查了应有的 112 次层调用和 56 份不同存储的 KV 历史。

运行使用官方原模型、实际线性层、embedding、加载及后处理。注意力采用未修改的上游 CPU `ReferenceAttention` 测试实现。它能执行 GQA、因果遮罩、滑动窗口和增量历史，但本次不涉及生产分页注意力或服务调度器。

输入来自既有 `history_default_truncation` 模板，共 32 个 token。两条路径使用完全相同的 token、绝对位置及调用顺序：先输入 7 个 token，再输入余下 25 个 token，每次一个，共 26 次前向。后续输入是固定的原提示词 token，并非从模型输出中采样的生成结果。每次都保存全部 FP32 缩放后 logits、BF16 隐藏状态以及 56 组完整 K/V。

原候选的首轮 7-token 预填充中，隐藏状态、logits 和全部 KV 都一致。25 次单 token 调用的 logits 均出现差异；首次单 token 调用位于位置 7，官方首选 ID 为 7493，候选为 7801，该次 logits 最大差为 0.1841480434。之后各位置的首选 token 与官方一致。这个固定轨迹的首选统计不能替代生成质量评估。

因果对照保持候选源码及其非投影算术、RoPE、归一化、门控、循环和请求状态逻辑。运行时仅在候选前向期间，将 `F.linear` 调用按原矩阵的存储地址、形状和步幅映射到已经加载核验的官方投影模块；Q/K/V 和 gate/up 取对应的输出行，并恢复原单独投影的连续布局。共覆盖 289 个物理矩阵；参考与候选仍维护各自独立的缓存。

这个干预消除了本次轨迹的全部差异，支持“投影计算路径差异足以解释该轨迹的不一致”。其范围是当前模型、CPU、原权重、输入及调用形状。这里共用了投影实现，因此不能把它当成两个独立投影后端的一致性证明，也不能把它变成新的性能基线。上一轮发现的单 token 差异和两条路径各自的批量依赖仍成立。

实际调用计数也与计算图一致：官方每次前向调用 oneDNN 281 次，原候选实验含重新开始请求共 7,587 次。因果对照的候选每次调用 449 次官方投影，其中 Q/K/V 等独立调用会重复调用相应合并模块；含请求重用后候选共 12,123 次，双方合计 19,710 次。这种干预用于定位差异，没有进行性能测量。

参考请求重新开始时，先释放候选槽位并清空官方 fixture 缓存，再以新 epoch 输入相同的前 7 个 token；旧 epoch 的候选句柄在实际运行中被拒绝。两条路径各自的隐藏状态、logits 和全部缓存都与第一次一致。本轮保存了第二次输出，独立复核覆盖每轮 228 项重新开始比较。这里检查的是参考状态；生产 A→释放→B、交错请求、取消、异常及完整槽位验收仍待执行。

独立复核仅使用 Python 标准库。两轮各自重新读取完整 checkpoint 并核验 507 个张量，检查 54 个完整二进制归档和 277,092,352 字节，重现全部 2,964 项前向比较、228 项请求重新开始比较以及首选 token。合计核验 108 个归档、554,184,704 字节，没有导入 Torch/NumPy 或重跑矩阵乘法。额外逐字节比较两次新进程的 27 对官方归档，确认官方输出完全一致，干预没有改变官方参考端的保存结果。这是本次短轨迹的新进程复现，完整冷缓存门槛仍保留。

新 Transformers 5.20.2 环境中，原 13 组提示词和 token IDs 与既有记录完全一致，1,000 个附加特殊标记逐项验证通过；默认思考、停止 ID `[2, 11]`、采样开启、温度 1、top-p 0.95、top-k 0 均保留。该环境仍输出 Mistral 正则修复告警，本轮没有修改原正则。保存数据复核确认这些输入和策略一致，没有宣称独立重新执行 BPE，也不以有限用例证明任意文本都无问题。

两个原生任务及其独立复核实际退出码均为 0。两轮峰值 RSS 均约 17.17 GiB，在机器约 31 GiB 主存和预设 26 GiB 地址空间上限内完成；采集耗时分别约 112.86 秒和 120.34 秒，包含加载、校验、两条计算路径及保存开销，不是模型延迟或加速比。任务保持单核、单线程和串行锁，使用 NVMe 输出，没有扩容 EBS。
