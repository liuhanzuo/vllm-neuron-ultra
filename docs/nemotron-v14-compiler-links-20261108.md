# Nemotron Nano 9B：编译资源链接修复与 r6 复验

本次修复了实验运行器对 Neuron 编译资源链接的兼容问题，并准备了新的 v14/r6 完整复验。模型实现仍为 `60ab7f54a2c54ef0bc9b498621a45719ee7f0e84`；原来的 52 个阶段、数值门槛和资源限制均保留。**这项运行器修复没有新增模型提速结论。**

## 故障原因与修复

[r5 的实际失败](nemotron-r5-compile-interruption-20261108.md)来自我们自己的输出目录检查：编译器写入十条 PWP 内部资源链接后，检查程序把它们判为非法输出并中止编译。现有证据不能将其归为模型数值错误、Neuron 编译器缺陷或 Trn1 硬件故障。

新版本只接受已核验的十个安装资源，总计 228,068 字节，限定在 `compile-work` 下的 context/decode 模型、TP0/TP1、原六个桶及编译子图目录内。每条链接必须指向固定的绝对目标；目标内容哈希和文件身份均被绑定。其他目标、目录链接、替换后的链接和错误位置仍被拒绝。链接本身的占用继续计入输出预算。

修复同时接入运行中的存储检查和结束后的原始证据清单校验，避免仅在编译期间放行、到最终复核时再次失败。原模型视图、临时通信文件与目录改名期间的完整重扫规则继续保留。

## 验证结果与历史记录

- 94 项运行器集成检查通过，覆盖真实安装资源的内容核验、存储与最终证据路径、错误目标与身份、通信文件、改名竞态和服务退出处理。
- 13 项配置生成检查通过，使用真实的历史记录；拒绝删减阶段、改动资源限制、丢失历史任务、复用服务名或把失败基线用于提速分母。
- 配置准备重新核对 40,162 个源码和元数据指纹、16 个输入的文件身份及 1,337 个运行时二进制身份。此步骤没有重新读取模型权重内容，不能代替运行期输入核验。
- 完整历史保留 925 条服务、182 条进程记录，包括 MiniCPM5 r2 未收到启动确认的原始状态。旧历史的完成证明与本轮实际启动检查分别验证。

初始移植测试沿用了旧版本预期；真实历史测试还发现，新一轮的完整释放记录不能直接拿来验证更早的 Smol 历史片段。两处均已修正后通过检查，原失败记录保留。构建器不自行生成源码批准；本轮由根任务另行检查源码差异与精确配置，再执行完整源码校验。没有第二个审查者参与。

## 空间回收

按用户已授权的策略，删除了两份已结束 Qwen3.5 编译的可再生中间文件，以及可再下载的 npm/uv/pip 安装缓存，共回收约 1.76 GiB NVMe 和 64 MiB 根盘空间。模型权重、服务产物、NEFF、科学结果和已安装运行库保留；282 个受保护文件的身份未变，三个主状态文件的哈希未变。

首次回收尝试因无法读取某进程的文件描述符而退出，未删除任何文件。随后使用限定目标的只读进程核验完成检查，第二次实际回收成功；两次真实退出和最终核验均保留。没有扩容 EBS，也没有降低启动空间要求。
