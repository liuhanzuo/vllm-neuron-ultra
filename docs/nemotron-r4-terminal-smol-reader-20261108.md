# Nemotron r4 编译中断与 SmolLM3 下一轮准备（2026-11-08）

Nemotron Nano 9B v2 的 r4 实验在编译启动阶段中断，完整模型验证未完成。42 个阶段保留了成功退出记录；编译阶段被实验管理程序停止，后续 9 个阶段未启动。本轮没有新增可计入模型提速表的结果。

## Nemotron：问题在实验文件检查

已完成的 42 个阶段包括准备、9 项别名检查、16 项投影拆分检查和 16 项卷积拆分检查。实际外层工具退出码为 1（会话 50501，记录 64a936）。

存储检查要求输出目录内除明确允许的模型视图链接外，其余文件都必须是普通文件。但编译启动后，临时目录出现了 3 个 UUID 命名的 Unix socket。检查将这些合法的进程通信文件判为异常，抛出 `Ordinary new output file`，控制器随即停止编译。因此目前没有证据把该错误归因于模型数学实现、Neuron 编译能力或上游 vLLM-Neuron 本身。

首次显式失败回收也被同一检查阻止。确认原 owner 已退出、全部 53 个计划服务组均已终止清空，且 socket 不在活跃 Unix 端点表中之后，将 3 个零字节 socket 原 inode 移到独立保留目录。没有改动模型权重或被冻结的运行源码，也没有手工改写观察器登记。原版 v10 回收流程随后正常退出，仍明确保留实验失败和模型未通过验证的结论。

独立终结检查保留正常退出、主动中止、未启动三类事实；未将运行中的停止前快照冒充成功退出。完整历史由 785 个服务和 147 个独立进程增补为 838 个服务和 161 个独立进程。22 项终结元数据检查通过，完整终结程序实际退出码为 0。一次未捕获进程身份的失败回收被明确标注，未虚构 PID。

已准备新的存储检查候选：只有调用方明确指定的临时目录可以接受 UUID 命名、单链接、零字节的 Unix socket，并限制数量；普通文件、日志大小、硬链接、目录链接和其他特殊文件的检查保留。11 项检查通过，包括真实标准库 socket 重现和当前实机输出目录的占用对照。候选尚未接入新一代完整运行配置，也尚未用于新的模型实验。

## SmolLM3：完成最新历史记录兼容

旧读取器继承的 Nemotron 元数据版本不认识最近新增的记录格式。新读取器改为继承 v10，保留原来的精确安装回执、非 UTF-8 源码例外、8 / 16 / 32 MiB 分类上限及哈希核验。较新的 Smol 完成清单必须提供明确的预期哈希。

25 项读取器检查与 6 项九模块衔接检查通过。新的模块版本保留上一轮已验证的标题握手计时调整、全部状态机检查、原有 15 秒握手限制和实验参数。随后在真实完整 r4 历史上核对了 38,129 项源码与元数据，全部通过；14 个历史模型数据指纹单独保留，没有作为源码读取其数据正文。

该步骤是实验准备验证，不是推理基准。仍需完成新源码模板、完整运行配置、输出预算和内存检查、终结流程与执行审查，才能启动新的 sio14 运行目录。3 种配置、12 轮、264 个请求、33,696 个输出 token，以及冷缓存、长解码、请求槽位复用和质量检查均保持原要求。
