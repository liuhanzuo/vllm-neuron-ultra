# Nemotron 临时通信文件修复与 SmolLM3 实机进展（2026-11-08）

SmolLM3 的 sio14 实验仍在运行。第一轮已通过之前失败的 EngineCore 启动握手，模型列表接口返回正常响应，测试客户端已经进入推理请求阶段。启动期间，外层、控制器、服务端和客户端的实际进程身份均已核对，完整握手记录与当时 EngineCore 身份一致。第一轮 r00 随后完成，22 个请求、2,808 个输出 token 的原始请求和响应已重新计算校验值，解析记录与汇总逐项一致。客户端正常退出，服务按授权关闭，原服务、客户端和 EngineCore 均已退出，服务组已清空；第二轮 r01 也已通过启动握手，模型接口就绪，客户端正在执行推理请求；其实际进程身份已核对。

完整实验仍是三配置、12 轮、264 请求、33,696 输出 token，保留冷缓存、长解码、请求槽位复用和质量检查。目前完成 1/12 轮，其余 11 轮及最终独立核验仍待完成。单轮结果不能作为全模型验证通过，也不能据此新增提速倍数。

Nemotron 上一轮 r4 的失败源于实验工具的文件类型检查：编译器生成的三个临时 Unix socket 被误判为异常文件，导致编译中止。42 个阶段成功、编译失败、后续 9 个阶段未启动的原始结论保留。这一发现尚不能证明模型实现或 Neuron 编译器本身有问题。

新的 v11 实验程序已接入以下修复：

- 在明确指定的 `work_root/temporary/tmp` 目录中接受最多 64 个符合 UUID 命名、属于当前用户、单链接、零字节的 Unix socket。磁盘占用仍按实际分配空间统计；其他目录继续执行普通文件规则。
- 保留文件改名时的完整重新扫描、原有文件数量和大小限制，以及全部磁盘预留。没有跳过消失文件，也没有降低准入门槛。
- 最终结果归档同时修复：普通文件仍逐字节计算校验值；已关闭的 socket 保留其设备、inode、时间、权限及占用记录，不读取通信端点内容。若端点仍在使用，或身份在检查期间变化，归档会失败。独立结果验证与最终审查使用同一规则。
- 原有 52 个执行阶段、模型代码、数值判据、冷缓存、长解码、槽位复用和质量要求均保留。此前 v10 的源码未改动。

最终 62 项标准库检查全部通过，包括真实 Unix socket、文件改名竞态、最终结果清单、原有服务退出检查和磁盘不足场景。检查只覆盖实验程序的行为；新 Nemotron 完整模型实验尚未启动，不能将这些检查次数视为模型推理次数。

下一次 Nemotron 实验还需要当前 SmolLM3 完整结束、取得实际结果和退出记录，并恢复足够的 NVMe 预留。当前可用空间 49,651,453,952 字节，新实验要求 48 GiB，差 1,888,153,600 字节（约 1.76 GiB）。已从旧编译缓存中选出 253 个有完成标记的条目，共 1,039 个文件、4,607,754,240 字节（约 4.29 GiB）。另 490 个未完成、失败、含锁文件或内容类型不在本次清单中的条目不在此次归档范围内。选中条目无硬链接，当前源码和模型产物清单未引用这些路径。可恢复的归档程序已准备好，14 项检查通过，包括目录边界、硬链接、未完成条目和旧退出记录替代新实验记录等情况。执行时仍须等待本轮 SmolLM3 结束、确认无活跃引用，并逐一验证归档内容，实际净释放空间达到原有门槛后才移除缓存原件。尚未归档或删除，磁盘未扩容。
