# Qwen KV256：BF16／S16 拼接对照准备

此前 [KV256 保存数据复核](qwen-kv256-partial-byte-audit-20261113.md)确认：持久缓存的 NKI 路径在特殊 BF16 位模式下改变了尾部字节，有限数值输入通过；独立 NKI writer 的保存结果也通过。新对照固定同一 writer 和缓存别名关系，只改变前缀与尾部的拼接方式，用于进一步定位差异。

| 对照 | 拼接路径 | 公共输入／缓存／输出 |
|---|---|---|
| BF16 | 原 NKI 前缀与原缓存尾部直接拼接 | BF16 |
| S16 位重解释 | 两个 BF16 操作数各自 bitcast 为 S16，拼接后 bitcast 回 BF16 | BF16 |

S16 只用于内部搬运相同的 16 位数据，权重与外部数值精度保持。两图均使用原 `old, new` 输出顺序、输出 1 的缓存别名、相同 NKI writer、四个全 inactive 槽位，以及原始、有限数值和逐行标记三类输入。

固定范围为两张新图、六次调用。每次捕获完整旧输出、新输出、持久状态及差异位图，共 18 项完整比较；另外保留 12 份调用后的主机输入。退出后重读全部数据，重新计算每一行前缀与尾部的差异。

## 实际 HLO 检查与当前范围

检查器将读取实际编译输入 `model/graph.hlo`，从输出 1 沿操作数追踪到拼接、三次等宽 bitcast、原缓存前缀／尾部和原 NKI 输入，核对 MUST_ALIAS。它拒绝数值 Convert、错误拼接轴、错误切片来源及未参与输出的伪 S16 标记。输入 HLO 的检查不能证明最终设备指令的行为，仍需实际完整字节比较。

主任务复跑 **39 项源码／合成测试通过**，另有六项独立纯检查通过。两图对照的串行接线现已完成源码审查，主任务另复跑 **32 项串行测试和 40 项辅助工具测试，全部通过**；715 份本地源码与 2,822 份 SDK Python 源码摘要已核对。当前尚未编译或运行新对照。

接线会独立重算保存 HLO 的完整证明，并要求两张图都有准确的模型、HLO 与证明回执。如果编译后在 HLO 检查处停止，报告保留“图已保存、回执尚未产生、设备调用为零”的真实阶段；第二张图失败时也保留第一张图已完成的三次调用。源码审查通过后，仍须完成当前串行状态和磁盘预留检查才能实测。

原 1 GiB 输出上限、900 秒期限及磁盘预留规则保持。这个追加对照不能替代此前缺失的 alias0、尾部复制、完整复制控制，也不能替代原八布局矩阵或整模型验收。

Qwen 独立包 r7 的准备源码还补齐了 Mini 重放／清理完成记录的文件名兼容，主任务复跑 29 项测试通过。旧数字命名路径生成的内容保持相同，实际绑定仍要核验最新完整串行目录、874 个历史子任务、资源限制及原 25 项科学检查。
