# Dory1.0-4B 存储共享与缓冲寿命实测

2026-11-08，Dory 权重加载所依赖的真实 PyTorch 存储探针完成，原生进程实际退出 0；退出后的独立保存数据复核也退出 0。该结果验证小型样例上的存储和寿命行为，尚未加载 Dory 原始权重或执行完整模型，不产生提速倍数。

| 检查 | 实际结果 |
|---|---|
| 形状及缓冲 | `(4,)`、`(4,8)`、`(256,256)` × 普通/可追踪缓冲，6 组通过 |
| `frombuffer` 与 `detach` | 指向原缓冲，完整形状、BF16、stride、偏移及存储字节数相符 |
| 双向共享 | 从缓冲修改、从张量修改，均观察到同一存储变化 |
| 缓冲寿命 | 删除调用者引用和原张量、回收并分配对照缓冲后，分离张量仍保持原字节 |
| 显式复制对照 | 使用不同底层存储；可追踪原缓冲在最后共享张量删除后释放 |
| 完整输出 | 18 份张量，786,864 字节，全部原始字节一致 |
| 独立退出后复核 | 重新生成期望字节、读取全部保存输出，完整复核结果与运行内记录相同 |

最大样例覆盖全部 65,536 种 16 位编码，包括零、次正规数、无穷和 NaN。这里检查字节保真，未把这些测试编码用于模型数值计算。退出后的标准库复核不会重新执行 PyTorch 所有权和垃圾回收语义；寿命结论来自实际原生探针。

执行环境仍为原 CPU PyTorch 2.9.1，单线程、CPU 6，8 GiB 地址空间、600 秒 CPU / 900 秒墙钟限制。原生运行报告的总耗时约 65.82 秒、峰值内存约 292.80 MiB；包含前序检查、框架及运行开销。它不能用于估计约 7.95 GB 原权重完整模型的峰值内存或推理速度。输出总计 6,180,864 字节，其中包含完整运行依赖清单。

后继运行器只更新前序记录的核验：同时保留 Nemotron r7 的失败结束、MiniCPM5 前两轮失败，以及第三轮采集成功、重放失败、退出后独立复核成功的真实状态。26 项检查通过，其中 14 项继承的请求检查、12 项新增记录检查。原存储探针、采集算法和资源预算没有改变。

后续仍需核验完整官方 checkpoint、实际加载全部 507 个 BF16 物理张量、验证原权重参考模型和 Neuron 基线。两次循环、56 份独立历史、学习缩放参数、分词器模板及全部数值/质量/冷缓存/长解码/槽位复用/配对服务门槛继续保留。
