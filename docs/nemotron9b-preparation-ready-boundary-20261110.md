# Nemotron 9B：启动准备就绪边界的后继修正

[启动计时与分段期限报告](nemotron9b-startup-deadlines-20261110.md)所述 66.144 秒实测和准备／切换／确认 300／60／60 秒方案仍成立。接入前继续检查原写入实现时，发现第一版候选还需处理一个竞争窗口：原 `p.once` 会先创建执行意图文件，再写入、flush、fsync。**文件已存在不代表文件已经写完。前一报告把原执行意图文件称作“原子写入”不准确，以本修正为准。**

第一版候选在准备阶段按文件存在读取它，有可能碰到尚未写完的 JSON，随后拒绝并清理。这不会放过错误身份，但可能导致正常启动误失败。第一版源文件与测试记录保留，未用于启动模型。

后继 v2 改为：子进程在原执行意图完整写入及同步返回之后，原子创建一个专用的空目录 `<stage>-server-prepared`，然后执行原来的服务切换。父进程只在确认这是属于当前用户、权限 0700 的真实目录后，读取并验证原执行意图的完整内容及 ACK/进程绑定。普通文件、符号链接、错误权限、已有标记均被拒绝。目录只表示可以读取，不能代替原身份认证或实际服务切换观察。

原 bundle、父子与服务身份、健康检查、执行意图内容及后续 execve 保持不变；子进程仅在完整写入与 execve 之间增加标记发布。除了 HTTP 启动流程和这两条子进程语句，所有 worker 函数都与原 v24 的 AST 一致。0.25 秒空命令行容忍仍跨阶段连续计时，失败清理仍使用原 pidfd 路径。

v2 完成 **30 项测试**，包含直接调用子进程函数验证“健康检查 → 完整意图写入 → 就绪发布 → exec”的顺序、写入/健康检查失败时禁止发布，以及部分 JSON 存在时持续等待。此前 15 项执行切换回归所针对的辅助源文件哈希未变，因此当前适用验证共 **45 项**，不是额外 45 次模型实验。

后继仍是源代码候选，入口继续拒绝直接运行。完整协议／控制器／源文件清单、已完成任务历史、运行规格和独立串行准入尚待接入，之后才能开展真机服务复验。没有新增整模型通过或提速倍数。
