# MiniCPM5 注意力首轮：原生 K 边界检查失败，保留现场并修正观测契约

2026-11-08，注意力内部采集 r1 已实际运行，原生权重加载完成，随后在进入第一层 eager attention 时退出 **1**。原生服务退出 1；CPU 双分片和保存数据重放均没有启动。两次检查确认全部三个计划服务的进程组为空，完整保留了 **23 个部分文件，共 38,486,812 字节**。没有新增整模型合格结果或提速倍数。

## 实际失败与证据边界

报错为 `Exact observed tensor/layout through boundary k_post_rope`。观测器把 RoPE 返回的 K 与注意力实际消费的 K 的全部元数据直接比较，元数据包含形状、步长、偏移、精度和完整逻辑字节哈希。失败发生在调用原生 eager attention 之前。

官方参考源码在这两个边界之间调用 `past_key_values.update`；动态缓存更新使用 `torch.cat`。这个路径可以改变存储布局。但首轮断言前没有持久保存两端元数据，因此**尚不能从首轮证据断言只改变了布局、数值完全不变**，也不能把这次观测器失败归为模型错误。现有原始 K 数据保留，失败结论不被重写。

## 修正了什么

后继观测器将缓存边界单独记录：保存生产端和消费端完整元数据，再判断两者是否具有相同形状、BF16 精度及全部逻辑字节。只在原生的这个特定缓存边界允许布局不同；SDK CPU 路径仍要求布局也完全相同。完整数值或形状不一致时仍失败，并先保存边界记录。

原 RoPE 输出保持原有布局记录，RoPE 的自身输入对照继续使用它。注意力的自身输入对照改为从同一份、哈希完全一致的保存字节恢复**实际消费布局**，避免错误地把生产布局当成注意力输入。独立元数据复核会重新推导边界判断，核对独立保存的 JSON，并确认重放使用了这一记录。

13 项边界/失败保存检查和 41 项继承检查及调用连线检查通过，共 **54 项**。这些是标准库及合成对象检查，尚不能证明真实 K 边界或新一轮算术通过。原模型代码、权重、精度、输入、QKVO、缓存更新与 attention 算术没有修改。

原计划仍保留 96 份完整原始输出、353,284,922 字节，新增的是三份小型边界 JSON。原七处边界、六处预测标记、填充行、Gloo 归约、退出后完整字节复核及后续整模型验收均保留。后继配置必须绑定首轮真实失败及复核者退出记录，确认全部三个计划服务与已知进程退出，核对全部 23 个部分文件原样保留。
