# MiniCPM5：预填充改动怎样影响后续解码

对已有记录的进一步检查表明：仅在预填充阶段替换第 0 层输出投影，后续解码的第 0 层预测位置指纹仍与严格 CPU 基线一致，但差异首次出现在第 1 层注意力，并持续到最终 logits。进入解码时，后续 82 份缓存记录的指纹已经与基线不同。这与预填充变化经缓存影响后续解码的路径一致；目前尚未量化差异大小，也没有证明数值失败的根因。

本轮只读取和核验了 95 份原始 JSON 记录，共 27,711,882 字节，覆盖两个 rank、三个方案、每方案 14 次调用和 32 帧。没有读取模型权重或原始张量，没有重跑模型或已被拒绝的投影候选。

## 逐阶段指纹给出的证据

每次调用保留 213 个预测位置观测点的指纹。两个 rank 的这些指纹和最终指标全部一致，统计时只计一次。

| 对照 | 预填充：8 次调用 | 解码：6 次调用 |
|---|---|---|
| 仅预填充替换，相对严格基线 | 首次差异在第 0 层注意力；之后 211 个观测点均不同 | 直到第 1 层输入归一化仍一致；首次差异在第 1 层注意力，之后 206 个观测点均不同 |
| 预填充与解码都替换，相对严格基线 | 首次差异在第 0 层注意力 | 首次差异在第 0 层注意力 |
| 两个候选互相比较 | 全部 213 个指纹及最终 logits 指纹一致 | 第 0 层注意力起不同，最终 logits 也不同 |

因此，两个候选同为 28/32 通过，并不表示它们的解码输出相同。原 29/32 基线、两个候选 28/32，以及高优势首选 token 回退的结论保持不变；候选继续拒绝。完整原结果及 FP32 指标布局问题见[此前报告](minicpm5-full-bf16-trajectory-20261108.md)。

相对基线，首次调用前的 84 份缓存指纹都相同；首次预填充后，编号 2～83 的 82 份缓存指纹不同，编号 0、1 保持一致。只在预填充做改动，也会留下不同的后续状态，所以关闭解码阶段的替换不能消除已有缓存差异。本轮比较的是生产记录中的指纹，不是重新校验所有缓存原始字节。

## 现成数据能支持什么

四个位置保存了真实 BF16 数值：第 0 层注意力输出、第 0 层输出、第 41 层注意力输出、第 41 层输出。两个 rank 共 84 个数据包，声明总量为 3,145,728 字节。其余 209 个观测点只有元数据和指纹，无法从中恢复逐层误差幅度。

四行解码的数据按物理槽位保存，逻辑帧顺序并不相同。例如一组实际物理顺序为 6、5、7、4。直接排序帧号后切片会把不同请求的数据混在一起。已准备的解析与统计函数显式保留这一映射；16 项生成样例检查全部通过，覆盖错位、缺失观测点、篡改字节、非有限 BF16、边界和零向量等。

下一步可对全部三个方案、32 帧和四个位置计算候选相对基线的扰动大小，并与原有最终指标并列分析。严格 CPU 基线本身仍有 3 帧不通过，因此这些扰动不能直接称作相对官方参考的绝对误差。原 FP32 验收指标和阈值保持不变；双精度统计只帮助解释传播。
