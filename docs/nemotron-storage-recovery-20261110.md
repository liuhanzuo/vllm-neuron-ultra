# Nemotron：完成存储恢复，整模型重验仍待重试

Nemotron Nano-9B-v2 的 r11 在完成 52 个计划阶段中的 42 个后，于整模型编译阶段触发根盘 28 GiB 空闲下限而退出。此前阶段的成功不等于整模型通过，新分支封装仍欠完整运行复验。

2026-11-10 已完成一次串行存储维护：将六份已关闭、没有进程打开或映射的旧用户日志压缩到 NVMe。每一份压缩包均完整解压并匹配原始 SHA-256；全部六份验证完成后，才删除对应根盘原文件。模型、权重、参考数据和实验结果均未删除，EBS 未扩容。

| 项目 | 实测结果 |
| --- | ---: |
| 保留的原始日志内容 | 805,306,368 字节（768 MiB） |
| 压缩包总大小 | 95,403,896 字节（约 90.98 MiB） |
| 原文件占用的根盘块 | 805,330,944 字节 |
| 维护前 / 后根盘可用空间 | 30,150,422,528 / 30,955,704,320 字节 |
| 维护后 NVMe 可用空间 | 53,127,282,688 字节（约 49.48 GiB） |
| 维护实际退出 | 会话 32631，退出码 0 |
| 退出后独立解压复核 | 会话 25985，退出码 0，六份原始内容全部匹配 |

释放块数与可用空间净变化略有差别，因为系统仍会写少量元数据和活动日志。一份仍被日志服务占用的文件已排除，没有停止日志服务。压缩包位于私有目录，公开材料不包含日志内容。

新的完整 Nemotron 运行仍须预留 NVMe 49 GiB：30 GiB 空闲下限、18 GiB 工作区、1 GiB 元数据。维护后仅比这项预留多约 0.48 GiB；根盘比原 28 GiB 下限多约 0.83 GiB。因此本轮清理恢复了空间余量，但不能保证下一次编译成功，启动前还须检查新增文件写入位置和实时空间。Dory 计划中的 3 GiB 新存档也不能与该预留同时占用。

没有自动启动后继模型，没有新增提速或资格结论。原精度、完整数值、冷缓存、长解码、请求槽位复用、质量与真实 HTTP 配对性能门槛保留。原始失败见 [r11 收尾记录](nemotron-r11-mini-layer1-20261110.md)。
