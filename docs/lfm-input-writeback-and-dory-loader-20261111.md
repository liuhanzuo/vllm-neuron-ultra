# LFM3 输入写回差异与 Dory 加载路径分析

2026-11-11：LFM3 的新诊断已经实际进入 NKI 0.5 模拟器，首个恒等操作返回的 4,096 字节与预期完全一致，但主机输入在调用后发生变化，因此测试失败。Dory 已完成五份加载源码的认证读取及 15 项路径映射，实际动态库选择和 ABI 兼容性仍待验证。本轮没有新增合格模型或推理提速倍数。

## LFM3：返回值正确，输入却被修改

在补齐完整传递依赖后，真实会话 `16107` 成功启动 worker，并以退出码 **1**（终止记录 `fcf693`）结束。首例运行约 1.632 秒，最大常驻内存为 250,288 KiB；这是诊断运行时间，不是模型吞吐量。

| 观测项 | 真实结果 | 说明 |
| --- | --- | --- |
| 首例操作 | 恒等操作 | 尚未进入选择器搬运测试 |
| 返回数据 | 4,096 字节完全一致，差异字数 0 | 返回摘要为 `5781e3d8081dc2fb9a8d4c3593c858dab77b09ed734bed5662d3d7d2a5dcb98d` |
| 输入及返回前观测 | 所有已观测的视图、底层存储一致 | 观测覆盖检查通过 |
| 调用后主机输入 | `inputs_unchanged=false` | 单独这一项足以使首例失败 |
| 后续覆盖 | 未执行剩余 31 例 | 原程序遇到失败立即停止；不能声称完成 65,536 种 BF16 编码或算术、类型转换对照 |

现有源码给出一个明确的候选原因：固定版本 NKI 的 `_tensor_to_numpy(tensor, precise=False)` 默认把 BF16 提取成 FP32；模拟器在向主机输入写回时省略了 `precise` 参数，随后再复制回 BF16 数组。返回值则显式采用 `precise=True`。这解释了为什么“返回值一致”和“输入被修改”可以同时出现，也说明输入写回不在原观测边界内。

但这一轮没有保存各输入的调用后字节及逐项差异，因此还不能断言具体哪个 NaN 位模式改变，或把原因完全归于上述转换。下一轮将保留原失败，对比原路径、仅修正该写回调用的隔离候选、恢复原路径三组，并保存各输入的完整摘要、逐位差异计数和独立转换对照。不会修改安装中的 SDK，也不会把模拟器对照通过记为设备或整模型通过。

主任务已确认外层与 worker 均退出、服务失败状态稳定且进程组为空。原始 CPU 回归、设备、别名、B8/B16 和整模型验收仍待完成；既有 B4 资格及配对提速范围保持原口径。

## Dory：源码路径已经明确，实际加载仍需观测

真实采集会话 `5434` 退出 **0**（`430d41`），处理完整的 70,764 条已保存事件后，读取五份指定 Python 源码，共 **321,490 字节**。没有读取原生库载荷、加载模型或导入目标包。主任务独立重新计算五份源码摘要并解析语法，结果一致。

| 剩余关系 | 数量 | 当前结论 |
| --- | ---: | --- |
| 三种 vLLM CPU 扩展对 Torch 库的依赖 | 9 | 找到条件导入路径；实际 CPU 分支、库选择和符号兼容性未验证 |
| `fs_io_C`、`spinloop` 对 Torch 库的依赖 | 4 | 五份源码内无调用点；不能据此判断不会被使用 |
| 两条 `libgomp` 依赖 | 2 | 找到条件预加载策略；实际选中的库仍未知 |

需要注意四个具体行为：

1. `VLLM_TARGET_DEVICE=cpu` 仍可能选择 `ZenCpuPlatform`，不能仅凭这个变量认定运行的是 `CpuPlatform`。
2. `CpuPlatform` 根据 CPU 能力选择 `_C`、`_C_AVX512` 或 `_C_AVX2`。部分 AVX 扩展的特定 `ImportError` 被忽略，所以正常返回不能单独证明扩展模块导入或 ABI 成功。
3. `_custom_ops.py` 在调用平台内核加载前先导入 Torch。这是该源码路径的先后顺序，不能代替实际进程中动态链接器的选择证据。
4. CPU 配置方法会在特定条件下设置 `LD_PRELOAD`，优先搜索 `torch.libs`，再搜索 `torch/lib`。运行中修改环境只影响之后继承它的新进程，不会追溯更改当前进程已加载的 OpenMP 库。

15 项实际加载选择缺口全部保留，之前完成的 11 项系统库字节来源和 4 项 Python 缓存来源验证也保留。下一步先补齐少量入口、环境及调用点源码，再用保持原入口顺序的有限加载观测确认实际选中的分支；未触达的分支不能强行加载后算作原运行证据。Dory 保留原来的 2 次循环、循环间分离的 KV 历史（共 56 份独立注意力历史）及 TP1。

这里记录的是当前固定版本的源码行为和诊断边界，尚未据此确认上游 vLLM 或 NKI 的通用缺陷。实际加载、ABI、模型正确性与性能收益需要分别验证。
