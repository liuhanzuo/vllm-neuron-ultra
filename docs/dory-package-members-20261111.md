## 修正的是实验工具兼容性

第一轮在已通过整包摘要的 libc6 文件上拒绝了旧 GNU tar 头。保存流诊断确认其使用精确的旧 GNU 标识，扩展区域全零；后继仅兼容这一格式，继续拒绝 GNU 长路径、稀疏文件和其他未支持扩展。第二轮通过 tar 检查后，因宿主 libc 文件的硬链接数为 2 而停止。只读检查确认 libc 与 libstdc++ 两个指定路径均为普通文件且链接数为 2，后继仅对这两条路径接受该计数，其他宿主文件、安装包和工具文件继续要求 1。

文件身份检查补齐了跨解压阶段的前后核对，失败路径保留解压程序真实退出码及错误输出。13 项 tar 检查、6 项传输检查、2 项身份与失败检查、2 项固定宿主链接检查和 4 项接入检查通过；另有独立源码复核。两轮原失败退出 1 和保存证据完整保留。这些属于自有验证工具的问题，当前没有证据归为模型、vLLM-Neuron 或 Ubuntu 的缺陷。

## 结果边界与下一步

11 个原始系统库记录的字节来源现已获得安装包成员证据；libgomp 是本轮新增完整观测，没有补造旧摘要。字节相等仍不能证明进程实际选用了哪个库，或原生 ABI 正确。原清点中的 13 条 vLLM 加载关系、2 条 libgomp 选择歧义及 4 个 Python 时间戳缓存问题仍待验证；下一步先核对原始导入顺序和实际加载路径。

解压使用已固定文件摘要的本机 `/usr/bin/dpkg-deb`，它是本次验证的工具信任前提，没有声称独立重建过该工具。

MiniCPM5 仍需恢复稳定的存储余量，再验证新版完整计划并重新采集原生数据。原生 r1 因根盘跌破 28 GiB 保留线退出 1，未产生张量；不能将失败记录成功视为模型成功。原模型、权重、BF16、冷缓存 4096、长解码、请求槽位复用、质量 96 和配对 HTTP 门槛均保留。
