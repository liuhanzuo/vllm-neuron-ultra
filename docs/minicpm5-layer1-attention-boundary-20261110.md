# MiniCPM5 下一处定位：第二层注意力边界

把 11 月 9 日已保存的逐阶段哈希与 11 月 10 日完成的数值重放交叉核对后，可以把“只改预填充”方案的解码检查范围缩小到 **layers.1.self_attn（从零编号的第 1 层，即第二层注意力）**。

六次解码调用的首个记录哈希差异均出现在这里；此前记录的阶段哈希一致。四个保存观测点的数值重放则显示：全部 24 个解码帧在第 0 层注意力及层输出上与原 CPU 对照数值相同，到第 41 层两个点均不同。两类证据相容。

哈希覆盖一次调用的四个预测行，不能据此断言第二层的每一帧都不同，也没有测得该层差异的大小。这个边界更不能直接证明缓存错误、模型实现错误或芯片缺陷。原 CPU 对照与两个候选的失败结论均保留。

下一次独立诊断优先核对第二层注意力的当前输入、Q/K/V、位置与掩码，以及预填充留下的 K/V 和布局；在相同原权重、BF16 和相同请求轨迹下区分当前计算与历史状态的影响。新增观测还须检查是否改变原端点，避免重现观测器干扰。现有证据不足以指定某一个缓存张量就是原因，也不支持直接恢复被拒绝候选的性能测试。

这是对已发布 JSON 的交叉核对，没有重读原始张量或重跑模型，没有新增提速。
