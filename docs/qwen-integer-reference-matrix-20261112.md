# Qwen 缓存整数参考矩阵：全部 46,368 次调用通过

完整八布局、32 张编译图和 46,368 次 Neuron 调用已通过，包括 BF16 卷积缓存、FP32 循环状态，以及 128 到 4096 的六种 KV 长度。每种布局的 5,796 次调用均完成；实际外层退出和退出后独立报告／产物审核通过。没有新增整模型提速，已有结果仍见[全部模型提速表](model-speedups-20261112.md)。

## 本轮修复及验证范围

此前 BF16 选择路径会改变负零和 NaN 位模式，[12 次设备诊断](qwen-select-integer-20261112.md)确认整数选择可以保留字节。本轮只将编译参考写入器替换为“BF16 ↔ S16、FP32 ↔ S32 的位重解释 → 原 store_slots → 位重解释返回”。没有数值类型转换。原 NKI 条件拷贝候选、CPU 期望值、旧缓存读取、MUST_ALIAS 声明和测试顺序保持。

验证覆盖每种布局的全部 625 种槽位映射（包括空闲、重复目标及最后写入者覆盖）、原始位模式与有限值数据、独立输入与持久别名状态。每次核对完整输出及输入不变；持久模式还核对旧值读取和真实设备缓存。负零／NaN 负控保留，既有浮点参考失败没有被后继结果覆盖。

总计 40,000 次正确性调用、1,024 次预热、5,120 次测量和 224 次实际状态重置。设备执行前主任务独立复跑 10 项源码与 24 项串行模拟检查；退出后重新读取完整报告、校验全部有序调用与计时汇总，并重新核对 32 个编译产物的哈希。这证明的是本次完整缓存算子矩阵，整模型数值、冷缓存、长解码、槽位复用、quality96 和匹配 HTTP 仍需独立验收。

## 独立包的两项工具修复

固定 Neuron SDK 在编译时会原子重命名 cache 临时文件、删除锁、重建 bucket 工作目录；旧扫描可能将这些合法变化判为失败。运行器 v3 只对准确限定的临时路径执行最多八次完整重扫。普通文件和日志可继续增长，每次完整扫描仍检查文件、条目、分类和总量上限；终态仍要求精确稳定。作者的 40 项针对性检查和主任务复跑的 15 项扫描检查通过。原 History、锁、科学流程、wait/drain 和资源上限保持。预算是有限试跑上限，尚非实测编译峰值，也不是文件系统硬配额。

参数化准备工具的独立审阅又复现两处自有问题：JSON 的极大指数被解析为无穷大，未来输出路径可能与未读取的保留历史引用冲突。冻结 v1 保留失败证据，v2 增加嵌套有限数检查及全部保留引用的路径防碰撞；32 项作者检查、独立受影响控制和主任务复跑的 10 项检查通过。这些是实验工具修正，不是模型或上游仓库缺陷。
